# QMS 故障诊断

先记录发生时间、受影响用户/组织、操作、源码版本和脱敏 traceId，区分产品、环境与测试问题。按[维护手册](../../../docs/OPERATIONS-RUNBOOK.md)选择相关排查链，只读取该链需要的资料。

每次实验明确假设、最小动作和可推翻假设的观察结果。同一尝试没有新证据时换查下一层；不要通过改状态表、取消授权、跳过扫描或放宽断言“修复”现象。

| 现象 | 优先核对 |
| --- | --- |
| Node engine warning | 当前 node 路径、版本、项目启动脚本与 CI 约束 |
| 通知未出现 | 事务/Outbox → Worker 租约 → 投影 → 实时受众资格 |
| SMTP 配好仍无邮件 | 邮件 Worker 开关、实际进程及 keyring；申请 202 不等于投递成功 |
| 恢复失败 | 包格式、密钥、空目标库/桶、迁移及固定对象版本引用 |

修复后复验原失败场景、相关允许/拒绝路径和恢复后的数据一致性；将防复发措施写入任务计划。工具记录见[工程工具](../../../docs/ENGINEERING-TOOLS.md)，恢复约束依[数据保护](../../../docs/DATA-PROTECTION.md)，邮件细节依[邮件恢复](../../../docs/EMAIL-RECOVERY.md)。

原始日志、备份和秘密保存在 Git 外；输出结论与脱敏证据。需要生产变更时先完成可评估方案，并遵循当前用户授权；诊断请求本身不授权生产恢复或删除数据。
