# QMS 权限审查

先界定用户要求的变更范围，读取原始规格、实际代码和验证结果；不要以实现者的总结替代证据。审查流程依[开发治理](../../../docs/DEVELOPMENT-GOVERNANCE.md)，平台语义依[平台交接](../../../docs/PLATFORM-HANDOFF.md)；涉及供应商才读[供应商交接](../../../docs/SUPPLIER-PLATFORM-HANDOFF.md)，涉及文件才读[附件](../../../docs/ATTACHMENTS.md)。

沿入口到事务逐段回答：actor 来自何处，客户端参数能否扩大组织/资源范围，功能权限与节点资格在哪里检查，锁等待后是否重新检查撤权/禁用，幂等重放是否重新授权，拒绝或审计失败是否留下部分副作用。区分内部跨组织授权与供应商参与策略，不把所有跨组织行为一概判为合法或非法。

报告每个问题的文件与位置、可触发场景、预期/实际差异、影响和最小验证方式；没有复现时明确是待验证风险。缺少拒绝路径测试时不能写“隔离已证明”。只读审查不改角色、不重置账号、不调用真实变更接口。

| 场景 | 核心证据 |
| --- | --- |
| 供应商处理内部拥有的问题 | 真实供应商 actor、关联企业、释放状态、固定版本回复节点与领域参与策略 |
| 管理员跨组织重试 Outbox | 目标资源真实归属、目标组织权限、重试授权与审计、并发状态检查 |
| 撤权后下载附件 | 当前领域资源授权与扫描状态；区分阻止新签发和已签发短期 URL 的有效期 |

需要运行真实测试时使用任务授权的一次性资源，证据形式见[工程工具](../../../docs/ENGINEERING-TOOLS.md)。审查结论只覆盖实际读取和验证的范围；独立审查必须由未参与主要实现的上下文承担，不能自称独立复核。
