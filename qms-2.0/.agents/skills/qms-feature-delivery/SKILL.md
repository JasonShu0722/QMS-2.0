# QMS 功能交付

这是功能 / 缺陷的交付推进入口；[QMS Superpowers](../qms-superpowers-zh/SKILL.md)负责工程方法，飞书盘点与开工评审使用[接单 Skill](../qms-start-development/SKILL.md)。纯问答和文本维护不启动完整业务交付。

## 输入与接续定位

从活动工程 `qms-2.0/` 工作。先读适用 AGENTS 和已有计划顶部[当前摘要](../../../docs/DEVELOPMENT-GOVERNANCE.md)，取得目标 / 非目标、批准范围与动作授权、REQ / 实际 record_id（适用时）、Issue / 分支 / PR 映射、源码 / 部署版本、证据及下一动作。缺项只暂停依赖该缺项的动作，继续其他独立且已授权的工作。

再按[变更影响分析](../../../docs/CHANGE-IMPACT.md)确认事实拥有者、消费者和验收范围；术语或能力不清时读相关领域交接。机器人初稿需要对照活动源码评审，不把云端代码分析基线当作本地现状。

## 按检查点主动推进

必读[交付流程](../../../docs/DELIVERY-MAINTENANCE-PROCESS.md)，其授权、版本分配、发布、关闭回填和完成定义是本技能的权威细则。沿用有效单次 / 持续授权和具体限制：

| 当前事实 | 主动动作与交付结果 |
| --- | --- |
| 常规范围已批准且评审通过 | 查重 / 关联 / 建立 Issue，再实施；交付真实链接、范围和验收映射 |
| 本地实现中 | 调用工程方法与对应领域能力，按受影响门禁验证；交付改动、审查、实际证据与限制 |
| 实现、审查、适用验证通过 | 按规则分配 / 复用版本，核对 base / head，提交推送并创建 / 更新 PR；附真实 URL 和映射，不等提醒 |
| PR 最新检查通过且获准集成发布 | 执行授权动作并逐版本核验部署；交付真实 SHA / 镜像 / 健康 / HTTP / 目标行为事实 |
| 最终验收成立且获准关闭回填 | 逐需求及联合项核对，关闭 / 最小回填并回读；分别交付关闭、同步和归档状态 |
| 已结束或仅同步未完成 | 回查当前事实，只接续剩余获准动作，不因旧勾选或滞后台账重复实现 / 发布 |

仅本地限制走对应草案分支；纯文档免 Issue / PR，执行相关复核和治理。Skill 不授予合并、部署或台账写入；缺少后续授权不妨碍当前已获准检查点。

接续任务可运行 `corepack pnpm task:handoff --output <Git外新目录> --plan <阶段计划路径>`，参数和覆盖限制见[工程工具](../../../docs/ENGINEERING-TOOLS.md)。交接只描述当前源码和选定计划，不证明业务完成，也不改变用户授权。

根据任务选择公开平台服务；API DTO 变化遵守原生成契约流程。不要把目录名相似当作领域可以共享专业字段的理由。新领域接入分别证明功能权限、组织/企业范围及节点授权，而非仅复制已有页面。

依[开发治理](../../../docs/DEVELOPMENT-GOVERNANCE.md)选择门禁，依[工程工具](../../../docs/ENGINEERING-TOOLS.md)使用交接和证据工具；组合 PASS 只证明实际覆盖，数据库、Worker、附件与真实登录仍按计划要求。缺少前置时记录实际失败 / 未执行，不制造业务 PASS。

| 实际请求 | 应采取的范围 |
| --- | --- |
| 扩展供应商正式回复 | 查供应商交接，列出不可变修订、证据、节点权限与事务影响；运行对应真实服务验收 |
| 修改工程交接脚本 | 验证源码指纹、敏感信息排除、输出路径和失败行为；不无故执行数据库迁移 |
| 只改按钮文字 | 遵循前端目录规则和相关页面验证；不创建新的领域架构 |

## 输出与完成条件

每个检查点更新计划顶部摘要，输出范围与版本、真实对象链接、实际覆盖和代理 / CI / 人工证据、限制、下一动作及负责者。工程完成依治理，交付闭环依交付流程；发布、验收、关闭回填与 Git 同步分开报告，不把计划中的步骤或本地成果当作外部完成。
