# QMS 业务术语

本表解释跨模块交流用语，不新增字段或权限。原始定义以[总体设计](../../docs/superpowers/specs/2026-09-18-qms-2.0-redesign-design.md)和[平台规格](../../docs/superpowers/specs/2026-09-18-qms-2.0-batch-2-platform-design.md)为准；具体接入看[平台交接](PLATFORM-HANDOFF.md)与[供应商交接](SUPPLIER-PLATFORM-HANDOFF.md)。实现进度只查[能力状态](CAPABILITY-STATUS.md)和对应阶段最新证据。

| 术语 | 含义与边界 | 容易混淆的概念 |
| --- | --- | --- |
| 业务域 | 供应商、制程、客户、新品、审核等专业业务，拥有自己的事实模型与规则 | 不能把所有领域字段并入公共表 |
| 领域记录 | 业务域拥有的专业事实，通过稳定类型与 UUID 被平台引用 | 公共问题索引不拥有专业事实 |
| 问题索引 | 跨域检索、状态与流程关联所需的薄公共模型 | 问题中心是聚合入口，不是通用创建表单 |
| 报告编号 | 对外识别同一问题的稳定编号 | UUID 是内部身份，简报升级不换编号 |
| 简报 / 8D | 不同处理深度的业务形式；升级保持问题身份和追溯 | 切换页面或表单不等于完成受控升级 |
| 流程定义 / 发布版本 | 可编辑配置与已发布的固定版本 | 发布新版本不改变历史实例绑定 |
| 流程实例 / 节点轮次 | 一次受控执行与某节点的一次进入 | 重开、退回后的新轮次不能重用旧验证结论 |
| 功能权限 | 是否允许执行某类操作 | 有按钮权限不代表能访问某组织或处理某节点 |
| 数据范围 | 用户能访问哪些组织、企业或资源 | 客户端提交的 organizationId 不能扩大范围 |
| 供应商用户账号 | 供应商人员登录门户、参与整改及资料提交等协作的用户身份 | 不是 API 机器账号，不等同于供应商企业档案或完整组织架构 |
| 节点授权 | 当前流程位置的处理人、角色及动作约束 | 功能权限、数据范围和节点授权需联合成立 |
| 验证 / 关闭 | 记录验证事实与结束受控处理的不同动作 | 供应商流程的职责分离以固定版本配置及领域校验为准 |
| Outbox / 通知 | 事务内事件与异步产生的用户通知 | 业务已提交不等于用户已收到通知 |
| 附件 / 证据 | 公共文件生命周期与领域认可的证据关联 | 上传成功不等于扫描通过或领域接受证据 |
| 已验收 / 试点 / 生产 | 对应不同范围、环境和放行条件 | 开发环境 PASS 不能用作生产就绪证明 |

新增术语时先说明所属领域、权威来源和与已有术语的区别；变更含义时在任务中列出受影响 API、数据、页面和历史记录。英文标识保持源码写法，不创造平行 DTO。

“供应商用户账号”依据负责人于 2026-10-17 在开发策划会话中的确认；讨论中的“接口”仅用于解释供应商人员，不作为对外命名。术语确认不声明供应商档案、组织与账号关系已经改造。
