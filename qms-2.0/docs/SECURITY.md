# 底座安全边界

## REQ-0030 平台管理员范围变更（2026-10-26，代码已部署，生产授权须单独核准）

平台管理员通过显式`platform:admin`权限及既有有效直接授权/岗位任职识别，不凭用户名或岗位名称，也不把普通组织管理员的目录全选推断为平台身份。投影覆盖已注册、实际存在且适用的活跃内部组织功能；供应商门户专属、规划和预留能力不自动放行。停用内部组织仅保留必要组织管理和审计读取/导出；用户主组织、来源组织和任职有效性仍复验。

功能权限的ORM/SQL投影与实际角色成员资格分开；平台权限不充当经理/部长或任意流程roleCode、assignee和本单身份。公开预览的platformScope说明来源与目标范围。新迁移只登记权限，不自动给已有admin账号赋权；基础设施初始化/撤销须准确用户/角色/真实来源ID、只读差异预览和版本摘要复验，实际变更同事务失效会话并保留审计。生产预览/执行另行核准，具体证据和边界见[修复计划](../../docs/superpowers/plans/2026-10-26-req0030-admin-process-fix.md)。

账号及供应商账号治理、角色替换等目标权限上限检查读取`roleGrantSources`真实授权来源；功能可用性读取`effectiveRoleGrants`运行时投影。不能因目标停用而隐藏其真实marker，也不能把所有虚拟内部组织投影当成账号真实治理依赖。候选任职预览按拟调整后的投影计算差异，保留跨组织直接来源及platformScope。CLI实际改变绑定角色权限时同事务推进关联岗位roleVersion；no-op不推进，上限与审计失败均不得部分写入，防止grant再revoke回相同集合后旧编辑稿覆盖最后撤销。

## 本人会话历史与审计摘要增量（2026-10-18，开发中）

REQ-0018 的会话历史沿用完整认证保护，仅查询当前会话所属用户，分页参数有界，不接受目标用户或组织参数，不返回会话令牌、哈希或额外客户端标识。状态依次判定撤销、过期、有效；数据源和保留策略均不扩展。

REQ-0020 的审计动作说明与当前账号摘要只扩展读取模型，不改原动作、事件 UUID 或权限。操作人已缺失或主组织不匹配时不公开摘要；前端不得把缺失操作人解释为确定的系统事件。账号详情跳转逐目标组织复验账号读取权限，无效、重复或不完整定位参数明确拒绝。原导出范围、数量上限、公式防护和仅创建者下载规则保持适用。实现与实际验证见[本轮计划](../../docs/superpowers/plans/2026-10-18-qms-compact-account-master-audit.md)，尚不构成上线或验收完成。

本文记录底座、ABC 与 D–H 治理的实际能力和限制，不是生产就绪证明。验证入口与证据层级见 [FOUNDATION](FOUNDATION.md)。

## 身份、Cookie 与请求保护

2026-10-18 负责人后续决定：所有账号的 MFA 开关，包括管理员本人，统一由管理员在账号管理维护；个人安全入口只提供状态、绑定/验证、恢复码及邮箱功能。新增账号级可空覆盖字段：未配置保持迁移前默认，管理员显式要求或关闭决定有效策略，治理身份和记住登录七天上限独立不变。账号治理写入沿凭据权限、近期完整认证、目标受控组织和权限包含复验、CSRF、版本并发、幂等和事务审计；成功撤销目标会话与未完成挑战，保留绑定及恢复码。原个人偏好和解绑写入口拒绝，不能仅隐藏前端按钮。该后续决定优先于下文早期个人开关说明，当前实施见[集中治理计划](../../docs/superpowers/plans/2026-10-18-account-security-dialog.md)。

密码使用 Argon2id；服务端生成 32 字节随机 Session，数据库仅保存 SHA-256 摘要。未勾选记住登录时会话有效期 8 小时；勾选后，服务端依据当前跨组织治理权限判定管理员 7 天、普通账号 30 天，均固定到期、不滑动续期。MFA 与首次改密 challenge 只保留记住意图，仍为五分钟；全部认证关卡完成后才签发完整会话，Cookie 期限来自该会话的实际到期时间。旧会话迁移不延长到期时间。撤销、过期或账号禁用后不能继续解析。登录及有效会话返回服务端门户入口，不接受客户端声明身份，也不从浏览器存储推断门户。

个人账号中心已提供受认证保护的资料读取/邮箱编辑、修改密码、有效会话列表和单会话撤销。资料和审计同事务；修改密码使用旧哈希条件更新，避免已通过的旧口令验证覆盖并发改密结果，并在同一事务撤销其他会话、使重置凭证失效和写入审计。当前会话必须通过退出登录结束。管理员一次性密码重置签发与匿名兑换 API/页面已实现；D–H 已增加 TOTP 注册/验证、一次性恢复码、MFA 五次失败后15分钟锁定，以及高风险写操作最近五分钟完整认证。管理员默认要求 MFA，角色可额外要求 MFA；本轮 P0/P1 D 新增管理员本人偏好 `DEFAULT/ENABLED/DISABLED`，显式关闭覆盖其本人角色要求但不删除验证器和恢复码，不改变治理身份或七天上限。普通账号不能使用偏好入口，失去治理身份后其旧管理员偏好不覆盖普通策略。挑战状态不能进入普通业务接口。

`POST /api/v1/me/mfa/preference` 只操作当前治理管理员本人；近期完整认证、当前因子、CSRF、HMAC 幂等回执和事务审计不可省略。重新开启已有绑定时即使当前策略关闭也须验证新的因子；未绑定先完成注册。成功更新偏好、安全版本并撤销本人全部会话及未完成 challenge，失败保持原状态。一次性因子操作在重新认证后不自动重放已提交因子，而提示输入新验证码或未用恢复码。原可选普通账号解绑仍是独立破坏性操作，不能当作管理员开关使用。本轮源码、机器证据及上线后人工浏览器清单见 [C/D 实施计划](../../docs/superpowers/plans/2026-10-17-qms-p0-p1-identity.md)；代码存在不等于已完成最终浏览器验收。

`qms_session` 使用 HttpOnly、SameSite=Lax、Path=/；生产模式始终 Secure。CSRF Cookie 可由脚本读取；写请求必须同时提供匹配的 `x-csrf-token`，缺失或不匹配返回 403。浏览器不得把 Session、JWT 或刷新令牌放到 localStorage/sessionStorage。开发模式非 Secure Cookie 只用于本机 HTTP；生产必须配置 HTTPS，不能为了登录方便关闭 Secure。

登录和退出使用账号/会话与客户端 IP 的 HMAC 组合限流键；重置兑换按用途前缀、resetId 和 IP 限流，伪造 Session Cookie 不改变预算。生产缺 `QMS_RATE_LIMIT_SECRET` 时启动失败。每键 60 秒内最多 30 次请求，连续五次登录失败后从 1 秒开始指数等待、上限 30 秒，成功后清理该键。状态目前只在单 API 进程内存中保存，重启后重置，不提供多副本统一限流。MFA 与自助邮件找回已实现；MFA失败次数/锁定与邮件发送间隔另有持久化保护。多副本共享请求限流、外部身份平台及生产运维配置仍需独立治理。

## 代理与供应商隔离

直接启动 API 默认忽略客户端 forwarded 头。只有 `QMS_TRUST_PROXY_HOPS=1` 启用一跳信任，其他值（包括 `true`）不启用。Compose API 无公开宿主端口，只允许 Nginx 网关访问；Nginx 将 `X-Forwarded-For` 覆写为其连接的 `$remote_addr`，不能追加客户端自报链路。新加上游入口需要单独评审真实 IP 信任范围，不能无限信任代理头。

功能权限按请求选定的目标组织校验，未指定时使用会话归属组织。先检查组织参数 UUID、数据范围，再检查目标组织的功能权限；其他组织的权限不能补充该组织中缺失的权限。供应商组织来自服务端会话，只允许本企业；其他企业 ID 返回 `ORGANIZATION_SCOPE_DENIED`，重复参数返回 `ORGANIZATION_SCOPE_AMBIGUOUS`。内部用户只能选择已分配角色的组织。管理员写操作在 Serializable 事务中重新检查当前账号状态及授权，拒绝后在回滚事务外记录审计；全局角色不能通过组织管理接口移除。流程权限保留拒绝边界。新增接口必须同时补供应商允许与拒绝测试。

管理员 B/C 写请求使用 `Idempotency-Key`；请求摘要使用当前安全keyring的用途隔离HMAC，回放同时验证保留旧key与legacy秘密，不保存密码或临时凭证明文。相同 key 和内容重放安全响应，相同 key 不同内容返回 409，序列化冲突返回 409 可重试。一次性密码重置凭证有效期 30 分钟，签发不改变现有密码；兑换才在同一事务更新密码、消费凭证、撤销会话和记录审计。自助邮件找回须预先确认邮箱，凭证15分钟单次消费，重置撤销会话但保留MFA；SMTP后台投递及并发边界见 [EMAIL-RECOVERY](EMAIL-RECOVERY.md)。

## 审计、附件与异步恢复

`AuditLogService.record()` 支持在调用方事务中写入 actor、组织、动作、资源、结果、trace 和数据库时间。元数据仅允许白名单基本值，避免 Cookie、口令、签名 URL、密钥、任意嵌套对象进入审计。附件初始化将元数据与审计写入同一事务。

登录凭据错误会产生 `LOGIN_FAILED`，未知账号的 actor/组织为空，不保存提交的账号或密码。已认证请求因功能权限、组织范围或流程边界拒绝时产生 `ACTION_REJECTED`。这两类错误的响应 traceId 与审计一致，由服务端在 request 内生成，不采信客户端 trace 头。会话撤销与 `SESSION_REVOKED` 审计同事务，审计失败时撤销回滚；重复撤销不重复记成功事件。管理员用户、角色、权限分配和一次性密码重置 API 已接入事务审计，幂等重放不重复写成功记录。角色授权变化、身份迁移和本人改密会使相关未消费重置凭证失效。审计写入失败对外只返回受控 500，不泄露数据库诊断。MFA验证/注册/恢复码/停用、近期认证与邮件确认/找回已有成功和拒绝审计；不将其扩写为所有CSRF、限流和未认证请求均产生审计。

文件策略默认允许 PDF、JPEG、PNG、TXT、XLSX、DOCX，单文件最多 25 MiB、批量最多 10 个。对象键使用随机 UUID，记录 SHA-256、版本、组织和上传人。供应商附件从 QUARANTINED 开始，只有受控干净扫描结果才能 AVAILABLE，逻辑删除后拒绝下载。G适配器已提供60秒签名防覆盖上传、私有版本化对象和COMPLIANCE保护。真实病毒扫描、公开附件HTTP上传完成/下载及资源授权闭环仍属P3；服务级隔离不等于完整生产附件防护。

Outbox 使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取和五分钟租约；失败最多五次，前四次间隔 1/2/4/8 秒，再失败进入 FAILED。服务级人工重试只接受 FAILED，重置计数后重新排队。租约恢复可能重新执行 handler，因此未来业务 handler 必须幂等；不能把并发领取保护描述为端到端 exactly-once。Worker已绑定真实流程/时限handler并持续轮询，支持 --once；缺handler或非法参数明确失败。任务/站内通知投影和事件确认同事务。失败队列公共查询/重试需独立权限、真实聚合归属与锁后复验；邮件投递另有独立60秒租约和持久尝试上限。

## 部署与秘密

本机演示 seed 只允许 development 和 loopback PostgreSQL，要求两类账号使用不同且至少 16 字符的环境口令，已有密码保持不变。Compose 不自动建立演示账号。验收数据库和容器必须可销毁，不连接生产资源。

秘密、`.env`、上传、原始日志、数据库备份不入 Git。需要提交的仅环境变量名称、模板和脱敏验证摘要。Docker 上下文排除上述资源，归档不进入活跃构建、测试、安装、容器或部署。测试结束使用对应临时 Compose 项目的 `down --volumes --remove-orphans` 清理。

D–H已完成开发环境TLS、MFA、治理审计、对象保护与备份恢复演练，证据见FOUNDATION。生产证书/密钥/IAM/邮件环境、业务级授权、完整附件和供应商业务主链仍需独立验收；开发演练不等于生产部署放行。详见 [DATA-PROTECTION](DATA-PROTECTION.md)。
