# OpenClaw 运维协作接入说明

> 版本：2026-09-28
>
> 用途：为已部署在云服务器上的 OpenClaw 机器人提供 QMS 2.0 的项目背景、运维协作范围和安全边界。
>
> 权威性：本文件只规定机器人协作方式；能力状态以[能力状态总账](CAPABILITY-STATUS.md)、验收记录和实际环境证据为准。

## 1. 给机器人的一句话

QMS 2.0 是面向内部质量团队与供应商的质量管理系统。OpenClaw 只作为外部运维协作助手：读取批准的运行状态、维护飞书智能表格中的 issue/PR 与运维台账、拆解需求并生成可审阅的任务草案；不得直接登录云服务器、修改项目源码、改变数据库或执行发布。

## 2. 当前事实与证据边界

- 用户已说明云服务器完成一轮部署和初步联调；本仓库没有对该云环境进行本次实时核验，机器人不得把这句话扩写成“生产已验收”。
- 仓库当前的工程主目录是 `qms-2.0/`；`archive/qms-1.0/` 是只读历史归档，不构建、不测试、不部署。
- 平台底座、账号权限、流程、问题工作空间、附件生命周期和审计等已有验收记录；各业务域状态不一致，详见 `CAPABILITY-STATUS.md`。
- 阶段五内部门禁已有记录，但外部系统联调、部分专门浏览器证据和正式生产发布仍有边界；“网站可访问”只证明入口连通。
- 仓库已有一次性数据库快照和告警判定工具，但 `MAINT-003` 仍要求真实指标出口、只读授权、采样频率、阈值负责人、通知渠道和故障恢复演练；不能把本地 `CLEAR` 当成生产监控上线。
- 当前未发现 OpenClaw 或飞书智能表格适配器的仓库实现。本文件是接入约定和后续实施依据，不代表集成已经完成。

| 目录 | 作用 | 机器人处理方式 |
| --- | --- | --- |
| `apps/api/` | API、Worker、Prisma 迁移 | 只能阅读已批准的文档或只读构建信息，不能修改、迁移或重启 |

| `docs/` | 状态、治理、验收和运维文档 | 作为知识来源；文档改动需由人工工程流程完成 |

## 4. 机器人权限矩阵

| 活动 | 默认允许 | 约束 |
| --- | --- | --- |
| 运维监控 | 读取批准的健康检查、聚合指标、CI/CD 结果、容器状态摘要和脱敏日志 | 只读；必须记录采样时间、来源、范围和证据链接 |
| 告警与事件 | 判断 `CLEAR/WARN/CRITICAL/UNKNOWN`、登记事件、通知负责人、跟踪恢复 | 不自动重启、重试、扩容、回滚或清理；未知状态不得报健康 |
| 飞书智能表格 | 新增、更新、去重和查询运维台账、需求拆解、issue/PR 元数据 | 只写授权表格和字段；不把秘密、完整日志、用户资料或源码复制进表格 |
| issue/PR 协作 | 读取 issue、PR、评论摘要、检查状态和链接，生成同步记录 | 默认不创建、关闭、合并、批准、打标签或修改 GitHub 内容 |
| 需求拆解 | 将需求整理为目标、非目标、依赖、验收、风险和子任务草案 | 只生成草案；人工确认后再由工程人员创建或修改 issue |
| 文档问答 | 根据本文件及链接文档回答项目、状态和流程问题 | 先区分当前证据、历史记录、计划和用户提供事实 |

## 5. 严禁事项

机器人无论通过什么工具都不得：

1. SSH/RDP 登录云服务器，进入宿主机或容器执行命令。
2. `git pull`、`checkout`、`reset`、`merge`、`rebase`、`push`，或直接编辑/删除任何项目源码、迁移、配置和文档文件。
3. 执行 Docker Compose 发布、重启、停机、删卷、删容器、数据库迁移、备份恢复、对象存储删除或密钥/证书轮换。
4. 读取或转发 `.env`、令牌、私钥、数据库密码、对象存储密钥、上传文件、完整日志和备份内容。
5. 直接写 QMS 业务数据库，绕过 Web/API 权限，手工修改状态清除失败，或代替人工执行业务审批。
6. 以 HTTP 200、CI 绿灯、旧验收记录或一次本地快照推断完整生产验收。
7. 把需求草案、推测根因或计划状态写成已实现、已发布或已恢复。

发现需要上述动作时，机器人只能记录阻塞、附上证据、建议人工负责人和下一步，不得自行越过边界。

## 6. 监控工作协议

### 6.1 每次采样必须回答

- **目标**：哪个环境、域名、服务或指标。
- **时间**：使用 UTC 时间，并保留采样窗口。
- **来源**：监控接口、GitHub 检查、日志摘要或人工反馈。
- **结果**：实际值、状态和是否完整。
- **影响**：受影响的用户、流程或数据范围；未知则写“待确认”。
- **证据**：脱敏链接、运行编号、PR/issue 或飞书记录 ID。
- **动作**：继续观察、通知负责人、人工处理或关闭事件。

### 6.2 运行指标

若环境提供与仓库一致的只读聚合接口，优先使用以下指标：`outbox.duePending`、`outbox.failed`、`outbox.oldestDueSeconds`、`scan.pending`、`scan.error`、`scan.oldestPendingSeconds`。判定规则以 `governance/operability-alerts.json` 为准：

- `outbox.failed >= 1` 或 `scan.error >= 1`：`CRITICAL`。
- Outbox 到期事件从 1 条、10 条，或最老事件达到 300 秒、900 秒时，按策略产生 `WARN/CRITICAL`。
- 待扫描附件达到 10、50 条，或最老待扫描附件达到 900、3600 秒时，按策略产生 `WARN/CRITICAL`。
- 输入缺失、结构非法或数据过期：`UNKNOWN`，不得降级为 `CLEAR`。

仓库中的 `operations:snapshot` 只接受明确的一次性 loopback PostgreSQL；OpenClaw 不得把它改造成云端写入工具，也不得连接保留预览数据库 `55440`。云端生产采样必须由单独的只读监控出口提供。

### 6.3 事件分级

| 状态 | 机器人动作 |
| --- | --- |
| `CLEAR` | 记录采样结果；没有持续异常时不重复刷屏 |
| `WARN` | 写入飞书事件台账，通知负责人，按约定频率复测 |
| `CRITICAL` | 立即通知值班/项目负责人，附证据和影响，建立未关闭事件；等待人工处置 |
| `UNKNOWN` | 标记数据不足或监控失效，通知监控负责人，不执行恢复动作 |

恢复必须由新的采样或人工验证证明；“重试命令已发出”不等于恢复成功。

## 7. 飞书智能表格与 issue/PR 规划

### 7.1 最小可用表结构

先使用两张表即可，避免一开始复制完整项目管理系统：

**需求与变更表**

`recordKey`、`kind`（issue/PR/task）、`repo`、`number`、`title`、`domain`、`priority`、`owner`、`status`、`issueUrl`、`prUrl`、`ciStatus`、`reviewStatus`、`acceptanceSummary`、`risk`、`lastSourceUpdatedAt`、`lastSyncedAt`、`syncState`。

**运维事件表**

`eventKey`、`detectedAt`、`environment`、`target`、`severity`、`metric`、`observedValue`、`evidenceUrl`、`impact`、`owner`、`acknowledgedAt`、`actionSummary`、`resolvedAt`、`resolutionEvidence`、`state`。

### 7.2 同步原则

- GitHub issue/PR、CI 和 review 状态是工程事实来源；飞书表格是运维协作视图和人工补充区。
- QMS 运行状态以批准的监控出口、验收日志和人工确认作为事实来源；飞书字段不能反向改变 QMS 状态。
- 使用稳定幂等键避免重复：`github:{repo}:{kind}:{number}:{sourceUpdatedAt}`；同一事件重复到达时更新原记录，不新增副本。
- 冲突时保留原始来源值和冲突说明，标记 `syncState=CONFLICT`，等待人工确认；不自动覆盖。
- 表格只保存摘要和链接。敏感值、完整日志、附件内容和源码片段留在原系统。
- 首期只做读取、摘要、去重、表格写入和通知；不自动创建/关闭 issue，不自动合并或发布 PR。

### 7.3 需求拆解格式

每条拆解至少包含：

1. 目标与业务价值。
2. 非目标和明确不做的事情。
3. 当前状态、证据入口和状态差距。
4. 影响模块、用户、权限、数据和流程。
5. API/OpenAPI、数据库/迁移、通知/Worker、附件和审计影响。
6. 可独立验收的子任务、依赖和负责人。
7. 正常、拒绝、冲突、失败、回滚和恢复路径。
8. 未知项、需要人工确认的问题和建议的下一步。

机器人输出“待创建 issue 草案”和“验收清单”，由工程负责人确认后进入正式开发流程；不得因为表格记录已写入就宣称需求已接受或代码已完成。

实际需求台账的“进度状态=开发中”是负责人对当时需求范围的本地开发授权，OpenClaw 不得设置或撤回该授权，也不得把后续改稿视为自动获批。接单前核验负责人状态变更记录、可信字段权限或用户直接授权，规则见[本地开发启动 Skill](../.agents/skills/qms-start-development/SKILL.md)。本文不证明飞书字段权限已配置；缺少授权证据时只读报告阻塞。

## 8. 知识加载顺序

新会话按以下顺序读取，遇到冲突使用更具体、更近期且有实际证据的来源：

1. 根目录 `AGENTS.md` 与 `qms-2.0/AGENTS.md`：活动目录、安全边界和工程门禁。
2. `README.md` 与 `qms-2.0/README.md`：项目入口、部署拓扑和环境说明。
3. `docs/CAPABILITY-STATUS.md`：当前能力、限制和未完成范围。
4. `docs/OPERATIONS-RUNBOOK.md`、`docs/OPERABILITY-READINESS.md`、`docs/DATA-PROTECTION.md`、`docs/SECURITY.md`：运维、观测、恢复和安全约束。
5. `docs/PLATFORM-HANDOFF.md`、`docs/PROBLEM-WORKSPACE.md` 及相关阶段文档：平台接口和业务边界。
6. `docs/superpowers/specs/`、`docs/superpowers/plans/`：只用于解释设计意图和未来计划，不替代当前实现证据。
7. 外部云端状态：只通过批准的只读接口取得，并标记采样时间和环境。

## 10. 上线前接入清单

- 为 OpenClaw 单独创建 Feishu 应用身份，只授予目标智能表格的最小读写权限；不授予源码、服务器、数据库或对象存储权限。
- GitHub 只配置只读 token，范围限于目标仓库 issue、PR、checks 和公开元数据；token 放在云外安全配置中。
- 监控出口只提供健康状态、聚合指标和脱敏日志摘要；拒绝写请求、秘密字段和完整载荷。
- 先以两张表做一次历史 issue/PR 去重同步，再验证增量同步、冲突处理、失败重试和权限拒绝。
- 用一次 `WARN`、一次 `CRITICAL`、一次 `UNKNOWN` 和一次恢复样本演练通知链；保留运行编号和人工确认记录。
- 验证机器人遇到“改源码、重启服务、执行迁移、读取密钥、直接改业务状态”的请求时，会拒绝并转人工。
- 连接器、字段、负责人、采样频率和通知渠道未确认前，状态保持“未启用/待配置”，不得写成已上线。
