# API 接入管理

2026-11-11通用规则更新：所有外部接收接口的新正文统一为JSON对象数组，如`[{"example":true},{"example":false}]`，空数组`[]`允许。数组每项须为非null对象，不接受根对象、标量或数组中的null/标量/数组；对象内字段仍不做业务映射。一次HTTP请求的整段原始数组保存为一份收件，成功统一返回200（有无回执正文由开关决定），及无Idempotency-Key保持；历史对象正文继续可查。设计和实际发布状态见[对象数组计划](../../docs/superpowers/plans/2026-11-11-qms-inbound-array.md)。本节覆盖下文历史对象限制，发布前不据文档认定生产已生效。

## 配置与授权

正式入口 `/console/api-integrations` 包含接收接口、接收记录和发出接口。新接口为草稿，创建有效凭据后才能启用。组织、接口编码、来源系统编码及名称创建后固定；可修改接口名称、用途、回执开关、正文限制、保留天数、容量及来源 IP。编辑使用版本号防止覆盖并发修改。

操作栏“删除”供具备接口管理权的管理员使用，一次确认后停止接收、撤销全部关联凭据并从接口列表移除，已有接收记录、正文和审计按原保留策略继续可查。删除后可重新使用同一接口编码，新接口生成新标识，旧凭据不能调用新接口。删除使用版本号和管理幂等保护，结果未知时按页面提示重试原删除请求；不需要先手动停用或逐个撤销凭据。

删除API为`DELETE /api/v1/admin/integrations/endpoints/:id`，提交organizationId及expectedVersion，成功204。需要integration:manage、CSRF及近期认证；同请求重放及重复删除不重复成功审计。已删除接口不能编辑、发放/查看凭据或复制配置，历史记录检索不受影响。

| 权限 | 用途 |
| --- | --- |
| `integration:read` | 读取接口及调用说明 |
| `integration:manage` | 新建、编辑及启停接口 |
| `integration:credentials:manage` | 配合管理权发放、撤销凭据 |
| `integration:receipts:read` | 查询已收数据、请求结果和运行事实 |
| `integration:payload:read` | 配合收件读权读取正文，必须写入访问审计 |

按负责人对 Admin 默认可用性的明确要求，有效 `platform:admin` 身份沿现有内部组织权限投影获得上述五项权限，管理菜单据受控 context 显示“API接口管理”。普通账号仍须通过岗位明确授予，不按用户名或岗位名称推断平台身份，也不批量修改存量岗位。仅正常启用的内部组织可使用。管理写操作保留 CSRF、幂等键和近期认证；机器凭据绑定唯一组织及接口，最多同时两个有效凭据。页面默认永久有效，也可设 1～365 天；API 显式 `validityDays: null` 表示永久，省略该字段仍为 90 天。创建人由服务端保存，永久凭据仍可随时撤销。

调用说明和有效凭据行的“复制对接配置”提供实际 URL、POST、Content-Type、完整 Authorization、重试可能新增记录的说明及当前回执模式。再次打开页面也可复制。读取 `/admin/integrations/endpoints/:id/connection` 同时要求接口管理与凭据管理权限，使用无缓存响应，并在事务内解密、校验及记录审计；失败不披露秘密。新凭据原文通过既有 keyring 加密保存，普通列表、审计和创建幂等回放不含秘密或密文。历史凭据只有校验值，无法恢复原文；创建一份新凭据即可使用复制功能，旧凭据仍按原规则有效，不会自动撤销。含鉴权信息的复制文字须通过受控渠道交付接口方，不贴入台账或 Issue。

## 调用协议

`POST /api/v1/integrations/inbound/{接口编码}/messages`，例如编码 `test` 对应 `/api/v1/integrations/inbound/test/messages`。编码区分大小写，特殊字符由页面 URL 编码。既有 UUID 地址继续有效；组织之间相同编码由凭据绑定的接口区分，不靠 URL 猜测组织。正文为未压缩、有效UTF-8的JSON对象数组。页面提供完整复制操作和请求示例：

支持可选 UTF-8 charset（包括双引号形式），`Content-Encoding: identity`不区分大小写；其他编码和压缩仍拒绝。合法UUID的百分号编码路径与原路径使用相同原始字节处理和正文上限。

```powershell
curl --request POST "https://<qms-host>/api/v1/integrations/inbound/test/messages" --header "Authorization: Bearer <credentialId>.<secret>" --header "Content-Type: application/json" --data-binary "@payload.json"
```

`payload.json`示例：

```json
[{"example":true},{"example":false}]
```

无需发送 `Idempotency-Key`，即使仍携带旧请求头也忽略其值，不执行去重或内容冲突校验。每次请求独立保存，服务端自动生成UUID检索编号，成功回执的messageId与receiptId相同。收件、必要审计和容量计账在同一个事务提交后才响应成功。

| 情况 | 开启回执 | 关闭回执 |
| --- | --- | --- |
| 每次成功（含重复发送） | 200，新接收编号 | 200，零正文 |
| 鉴权、格式、配额或存储失败 | 对应 4xx/5xx | 对应 4xx/5xx |

每次按当次回执开关响应，历史配置快照不改写。应用 `X-Request-Id` 是本次请求排查号，与错误正文 `traceId` 相同；关闭回执时也不含收件字段。网关提前拒绝可能无 JSON，应按 HTTP 状态处理。网络中断或5xx后结果可能未知，先检索接收记录；每次重试都会作为新请求处理，可能新增记录。技术收件不表示业务字段校验或业务入库。

## 保留与排查

- 正文默认及硬上限 1 MiB，可缩小；接口频率默认每分钟 60 次，可设 1～300。通过机器鉴权及组织/接口/IP检查后的格式失败和重复请求也计频；无效身份不创建接口计数。数据库原子计数跨 API 重启/多进程保持；网关另按真实代理来源限流并覆写转发头，大小写路径使用同一保护规则。
- 正文默认保留 7 天，可设 1～30 天；到期即不可读，Worker 每轮最多清理 1000 份。按实际密文字节计账，接口默认 256 MiB、范围 16～1024 MiB；组织合计 1 GiB、100000 份元数据。应用上限不表示已有备份工具能支撑同等生产容量。
- 接收元数据保留90天用于检索；正文到期不恢复，之后再次发送为一份新记录。90天是元数据保留期，不是防重复窗口；旧版本形成的消息编号与重复结果按原保留期限可查。
- 已收数据及请求结果支持来源编码精确匹配、接口、消息编号、接收编号、追踪号和时间筛选。列表不含正文；正文分权、审计后解密并纯文本显示；受控 GET 均 `Cache-Control: no-store`。
- 分页固定同一查询时间区间，单次跨度最多90天；查询快照变旧不导致格式拒绝，到期收件及七天外请求结果仍按数据库当前时间排除。失败记录在已实际读取接口配置时保存其评估版本和回执开关，避免被失败后才生效的修改覆盖。
- 请求结果仅保存已验证身份的受控元数据，保留 7 天、每组织最多 10000 条，超限有界淘汰。未认证请求不归入 URL 或正文声称的组织。采集故障不反转已提交成功响应；数据库不可用、进程终止等可能造成明细缺失，不能据无记录认定没有发生请求。
- 停用接口/组织、撤销或过期凭据后，不能继续接收。组织强制删除使用 tombstone，同事务停接口撤凭据，保留历史归属和收件。

## 生产启用与恢复

上线前设置真实 `QMS_PUBLIC_BASE_URL`，核对TLS、可信代理层数、来源出口IP、协议、重试可能新增记录、200和非JSON错误识别、敏感样本、吞吐及秘密交付渠道。生产配权、发放凭据和启用接口分别需要相应授权。

正文及新凭据原文复用 keyring 加密，轮换须保留新旧密钥并完成重加密和实际读取核验。完整备份包含配置、凭据校验值及原文密文、永久空有效期、收件密文、检索编号和容量计账；恢复后先停用接收接口，再核对密钥、到期/凭据状态和计账后授权启用。144 迁移允许空有效期，旧镜像不识别永久凭据，不能直接回退旧镜像；优先向前修复，确需快照恢复时先停止接收并核对迁移后新增数据。参见[数据保护](DATA-PROTECTION.md)；小样本恢复成功不能替代批准容量的完整恢复门禁。

145迁移追加接口删除时间与活动编码唯一索引；恢复须同时保留删除标记、凭据撤销和历史归属，不能把已删接口重新暴露。旧镜像没有删除过滤，不直接回退旧镜像；优先向前修复，不清空接口或收件表回退。

146迁移允许历史body_digest列为空，新收件不再生成摘要。历史摘要值保留，旧镜像会恢复原消息头卡控及去重行为，不能当作等价回退；优先向前修复。
