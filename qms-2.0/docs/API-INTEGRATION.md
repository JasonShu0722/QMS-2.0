## 配置与授权

正式入口 `/console/api-integrations` 包含接收接口、接收记录和发出接口。新接口为草稿，创建有效凭据后才能启用。组织、接口编码、来源系统编码及名称创建后固定；可修改接口名称、用途、回执开关、正文限制、保留天数、容量及来源 IP。编辑使用版本号防止覆盖并发修改。

操作栏“删除”供具备接口管理权的管理员使用，一次确认后停止接收、撤销全部关联凭据并从接口列表移除，已有接收记录、正文和审计按原保留策略继续可查。删除后可重新使用同一接口编码，新接口生成新标识，旧凭据不能调用新接口。删除使用版本号和管理幂等保护，结果未知时按页面提示重试原删除请求；不需要先手动停用或逐个撤销凭据。

删除API为`DELETE /api/v1/admin/integrations/endpoints/:id`，提交organizationId及expectedVersion，成功204。需要`integration:manage`、CSRF 和有效会话。同请求重放及重复删除不重复成功审计。已删除接口不能编辑、发放/查看凭据或复制配置，历史记录检索不受影响。

| 权限 | 用途 |
| --- | --- |
| `integration:read` | 读取接口及调用说明 |
| `integration:manage` | 新建、编辑及启停接口 |
| `integration:credentials:manage` | 配合管理权发放、撤销凭据 |
| `integration:receipts:read` | 查询已收数据、请求结果和运行事实 |
| `integration:payload:read` | 配合收件读权读取正文，必须写入访问审计 |

按负责人对 Admin 默认可用性的明确要求，有效 `platform:admin` 身份沿现有内部组织权限投影获得上述五项权限，管理菜单据受控 context 显示“API接口管理”。普通账号仍须通过岗位明确授予，不按用户名或岗位名称推断平台身份，也不批量修改存量岗位。仅正常启用的内部组织可使用。管理写操作要求 CSRF、幂等键和有效会话。机器凭据绑定唯一组织及接口，最多同时两个有效凭据。页面默认永久有效，也可设 1～365 天；API 显式 `validityDays: null` 表示永久，省略该字段仍为 90 天。创建人由服务端保存，永久凭据仍可随时撤销。

调用说明和有效凭据行的“复制对接配置”提供实际 URL、POST、Content-Type、完整 Authorization、重试可能新增记录的说明及当前回执模式。再次打开页面也可复制。读取 `/admin/integrations/endpoints/:id/connection` 同时要求接口管理与凭据管理权限，使用无缓存响应，并在事务内解密、校验及记录审计；失败不披露秘密。新凭据原文通过既有 keyring 加密保存，普通列表、审计和创建幂等回放不含秘密或密文。历史凭据只有校验值，无法恢复原文；创建一份新凭据即可使用复制功能，旧凭据仍按原规则有效，不会自动撤销。含鉴权信息的复制文字须通过受控渠道交付接口方，不贴入台账或 Issue。

## 调用协议

`POST /api/v1/integrations/inbound/{接口编码}/messages`，例如编码 `test` 对应 `/api/v1/integrations/inbound/test/messages`。编码区分大小写，特殊字符由页面 URL 编码。既有 UUID 地址继续有效；组织之间相同编码由凭据绑定的接口区分，不靠 URL 猜测组织。正文为未压缩、有效UTF-8的JSON对象数组。页面提供完整复制操作和请求示例：

支持可选 UTF-8 charset（包括双引号形式），`Content-Encoding: identity`不区分大小写；其他编码和压缩仍拒绝。合法UUID的百分号编码路径与原路径使用相同原始字节处理和正文上限。

```powershell
curl --request POST "https://<qms-host>/api/v1/integrations/inbound/test/messages" --header "Authorization: Bearer <credentialId>.<secret>" --header "Content-Type: application/json" --data-binary "@payload.json"
```

`payload.json`示例：

```json
[{"example":true},{"example":false}]
```

无需发送 `Idempotency-Key`，即使仍携带旧请求头也忽略其值，不执行去重或内容冲突校验。每次请求独立保存，服务端自动生成UUID检索编号；管理端的messageId与receiptId相同，成功响应不返回这些字段。收件、必要审计和容量计账在同一个事务提交后才响应成功。

| 情况 | 开启回执 | 关闭回执 |
| --- | --- | --- |
| 每次成功（含重复发送） | 200，正文严格为 `true` | 200，零正文 |
| 鉴权、格式、配额或存储失败 | 对应 4xx/5xx | 对应 4xx/5xx |

每次按当次回执开关响应，历史配置快照不改写。应用 `X-Request-Id` 是本次请求排查号，与错误正文 `traceId` 相同；关闭回执时也不含收件字段。网关提前拒绝可能无 JSON，应按 HTTP 状态处理。网络中断或5xx后结果可能未知，先检索接收记录；每次重试都会作为新请求处理，可能新增记录。技术收件不表示业务字段校验或业务入库。

## 保留与排查

- 正文默认及硬上限 1 MiB，可缩小；接口频率默认每分钟 60 次，可设 1～300。通过机器鉴权及组织/接口/IP检查后的格式失败和重复请求也计频；无效身份不创建接口计数。数据库原子计数跨 API 重启/多进程保持；网关另按真实代理来源限流并覆写转发头，大小写路径使用同一保护规则。
- 正文默认保留 7 天，可设 1～30 天；到期即不可读，Worker 每轮最多清理 1000 份。按实际密文字节计账，接口默认 256 MiB、范围 16 MiB～5 GiB；组织合计默认 1 GiB、可由管理员配置至10 GiB，最多100000份元数据。应用上限不表示已有备份工具能支撑同等生产容量，生产启用更大容量前须完成对应完整备份恢复证明。
- 接收元数据保留90天用于检索；正文到期不恢复，之后再次发送为一份新记录。90天是元数据保留期，不是防重复窗口；旧版本形成的消息编号与重复结果按原保留期限可查。
- 已收数据及请求结果支持来源编码精确匹配、接口、消息编号、接收编号、追踪号和时间筛选。列表不含正文；正文分权、审计后解密并纯文本显示；受控 GET 均 `Cache-Control: no-store`。
- 分页固定同一查询时间区间，单次跨度最多90天；已收数据与请求结果默认每页20条，支持10、20、50、100、500、1000，查询最大1000条；接口候选分页仍最大100。当前页勾选最多1000条批量删除，切页、筛选或范围变化清空选择，不跨页累计。查询快照变旧不导致格式拒绝，到期收件及七天外请求结果仍按数据库当前时间排除。失败记录在已实际读取接口配置时保存其评估版本和回执开关，避免被失败后才生效的修改覆盖。
- 请求结果仅保存已验证身份的受控元数据，保留 7 天、每组织最多 10000 条，超限有界淘汰。未认证请求不归入 URL 或正文声称的组织。采集故障不反转已提交成功响应；数据库不可用、进程终止等可能造成明细缺失，不能据无记录认定没有发生请求。
- 停用接口/组织、撤销或过期凭据后，不能继续接收。组织强制删除使用 tombstone，同事务停接口撤凭据，保留历史归属和收件。

## 生产启用与恢复

上线前设置真实 `QMS_PUBLIC_BASE_URL`，核对TLS、可信代理层数、来源出口IP、协议、重试可能新增记录、200和非JSON错误识别、敏感样本、吞吐及秘密交付渠道。生产配权、发放凭据和启用接口分别需要相应授权。

正文及新凭据原文复用 keyring 加密，轮换须保留新旧密钥并完成重加密和实际读取核验。完整备份包含配置、凭据校验值及原文密文、永久空有效期、收件密文、检索编号和容量计账；恢复后先停用接收接口，再核对密钥、到期/凭据状态和计账后授权启用。144 迁移允许空有效期，旧镜像不识别永久凭据，不能直接回退旧镜像；优先向前修复，确需快照恢复时先停止接收并核对迁移后新增数据。参见[数据保护](DATA-PROTECTION.md)；小样本恢复成功不能替代批准容量的完整恢复门禁。

145迁移追加接口删除时间与活动编码唯一索引；恢复须同时保留删除标记、凭据撤销和历史归属，不能把已删接口重新暴露。旧镜像没有删除过滤，不直接回退旧镜像；优先向前修复，不清空接口或收件表回退。

146迁移允许历史body_digest列为空，新收件不再生成摘要。历史摘要值保留，旧镜像会恢复原消息头卡控及去重行为，不能当作等价回退；优先向前修复。

## API入库衔接（二期第一阶段）

管理端独立入口“API入库衔接”按目标组织配置规则，使用`ingestion:read`、`ingestion:manage`、`ingestion:run`分别控制查看、配置、执行。有效`platform:admin`沿既有内部组织投影默认获得新权限与菜单；普通账号仍需岗位授权。执行还要求对应目标档案的写权限；预览、历史提交和差异读取另需接收记录及正文读权限。

每条规则选择一个接收接口与供应商、客户、物料或组件项目映射目标，配置编码/名称来源路径、类型化条件及“全部/任一满足”，可选仅新增、更新指定字段、变化人工确认。供应商可另映射联系人/邮箱。编码按现有目标档案规则处理；客户档案保留既有大写规则。组件仅同步编码名称，项目、人员、阶段和分类继续由管理员在现有组件项目映射页面单条或批量补配。待配置筛选与既有100条批量预览/共享项目影响检查接续使用。

同一组织、接口和目标仅允许一条启用规则；需要组合条件时使用规则内的全部/任一条件。不同目标可同时启用，因而同一个供应商/客户接口及物料/成品接口都能分流。多个接口写同一档案时，已有差异转人工确认并重新校验版本，避免无明确字段所有权时覆盖。

先保存停用规则，从已接收记录选择数组行号进行试处理；预览不写档案，明确“确认导入”才入队。历史导入选固定接收时间范围，预览固定全部接收记录及原始顺序，确认后立即建立一个可见历史任务，由Worker分段规划、展开数组及处理，不按整个批次的份数或行数拒绝。条数尚未知时显示“后台统计”，任务显示接收准备和处理进度。预览有有效期，配置改变或过期须重新预览；已提交集合不随预览到期丢失。重复提交复用已登记条目；明确另建处理记录时填写重新处理原因。首次初始化先提交固定历史批次，再启用自动入库；后续接收任务排在本批预留序列之后，不自动重排已登记队列。

新数据接收与任务登记在同一数据库事务提交，HTTP200/true仍只代表接收保存与任务登记成功；正式档案结果在处理任务中查看。沿用现有Worker，每轮先处理入库条目。同组织、同接口按顺序处理，数组按原行号；档案写入和条目结果同事务提交。规则修改不改写已排队快照；关闭规则仅停止新增自动任务。暂停阻止后续事务开始，取消不回滚已入库资料。系统故障阻塞对应队列，恢复条件后可重试；已撤权配置者的任务可由当前有目标写权限的管理员显式重试接管，保留原配置者和实际授权者。

历史批次控制同时覆盖本批次表示的既有单条、自动任务和共享失败项，恢复或取消后同步关联批次状态。重试不复活已取消条目或其他处理代次；原任务已被手动暂停时继续保留暂停，须明确恢复原任务。行展开先独立提交，随后处理业务，首行写入失败仍能保留可重试或跳过的失败记录。

已有较新来源版本、较新接收事实或档案版本变化时，旧历史和旧人工确认不得回退资料；缺少来源更新时间时，补导历史遇到差异转人工确认。来源空值不自动清空人工资料，不根据未出现的对象删除档案。数据校验失败按行记录，系统故障、正常筛选跳过和待确认分别显示；人工确认/跳过、重试和队列控制均须记录原因。

未过期预览、未规划、未完成、处理失败和待确认所需正文继续保留并计入原容量，清理或手动删除不得破坏输入。历史任务按内部小段控制活动工作集，队首保持推进能力；活动登记保护不作为历史批次总量上限。终态结果保留90天，父任务清理须同时检查子任务和待确认条目。实际正文存储容量仍适用；缺失或已经清理的正文明确报错。备份恢复必须同时保留入库表、预览接收集合、父子游标、来源正文和密钥；旧镜像没有本轮规划与保护语义，生产回退优先向前修复。

## 制程不良品入库与AI整理（二期第二阶段）

REQ-0038 / V0.0.55沿用本页接收与有序入库，新增目标`PROCESS_DEFECT`。字段、手工必填、数量1、缺项入账、关联快照及自动只补待补项遵循[第二阶段需求](../../docs/superpowers/specs/2026-11-16-qms-api-ingestion-phase-2-stage-2-requirements.md)。收件200/true只表示原始保存与入队，不表示制程或AI已经处理完成。

制程入库规则在「工厂来源字段」填写 IMS 报文里的实际字段路径（支持点路径，不预设 IMS 字段名）。数字 `1` 或文本 `"1"` 对应一工厂，数字 `2` 或文本 `"2"` 对应二工厂。已配置字段但值缺失、为空或非法时，其他校验通过的记录仍入账；工厂存 `NULL`、台账显示 `/`，并标注工厂待完善。既有未配置规则和历史任务快照按原口径处理，不推断或回填历史工厂。正式启用前需用 IMS 实际报文核对路径和两厂来源明细编号是否会冲突；目前未完成该联调。实现与回退边界见[设计](../../docs/superpowers/specs/2026-11-22-qms-process-defect-factory-design.md)和[实施计划](../../docs/superpowers/plans/2026-11-23-qms-process-defect-factory.md)。

AI为规则可选项，在独立“AI管理”的“模型渠道”维护具名渠道、允许模型列表及默认模型；支持OpenAI Chat Completions、OpenAI Responses、Anthropic Messages和Gemini GenerateContent四种协议，旧渠道默认Chat Completions。“提示词应用”按业务板块和场景维护变量、渠道/模型、提示词及文本或JSON字段输出，本批实际接入制程质量的不良描述整理。应用先保存草稿、再发布不可变版本；制程 API 入库规则选择应用版本，并在“不良描述来源=多字段组合”的行中把 API 来源字段绑定到应用变量，提示词只消费这些变量，不重复配置 IMS 来源路径。发布新版本不自动切换既有绑定。旧内嵌配置归入同组织中心，原配置快照及历史任务保持，后续业务继续受中心停用控制。只向模型发送选定字段；本阶段输出目标为现有“不良描述”，编码、数量、项目及人员继续由原领域规则管理。详细边界见[AI配置中心专项设计](../../docs/superpowers/specs/2026-11-17-qms-configuration-groups-design.md)和[AI补充方案](../../docs/superpowers/specs/2026-11-16-qms-process-defect-ai-description-supplement.md)。

台账详情发起 AI 重试或重新生成时，系统从原提示词应用的最新已发布版本创建任务，按变量名复用已保存的值，新增变量无历史值时留空。任务等待或失败期间保留现有描述。人工修订过的描述由用户确认采用建议后更新。

先保存直接组合描述，再异步整理；AI成功采用生成文本，失败、超时或无效输出继续保底。人工修订优先，迟到结果只作建议，由用户明确采用。规则和输入版本隔离旧结果，项目/板块补配不应造成重复生成。预览试运行仅在明确点击时调用，不自动外发每次预览。

渠道密钥只写不可回读，界面和API只返回是否已配置；本人、他人及管理员均无回读原文、密文或尾号入口。留空保留，清除需独立确认；服务地址或协议改变必须重新输入密钥。四协议共用HTTPS、固定已验证公网IP及TLS主机名、禁止重定向、响应大小和超时控制；按各协议使用原生路径、鉴权头和响应解析，Gemini密钥不拼入URL。密文纳入原keyring轮换和全库加密备份，恢复后默认停用渠道，核对授权后再启用。运行密钥由有权人员上线配置，本次开发不借用环境密钥、不创建供应商账号、不进行生产业务外发。

REQ-0039拆分配置职责：渠道查看、维护、测试及凭据管理使用`ai:connections:read/manage/test`和`ai:credentials:manage`；应用查看、维护、发布和测试使用`ai:applications:read/manage/publish/test`；工序板块映射使用`process-quality:configuration:read/manage`，保留原平台配置入口。165迁移只把旧配置权限对应的既有能力等价迁入普通岗位；管理员沿动态投影默认可用。业务执行仍检查入库执行及目标写权限，规则绑定另需应用查看权。

制程不良台账支持单条及沿现有跨页选择的批量软删除，独立`process-quality:defects:delete`不从普通写权限自动授予。正式引用阻断整批删除，预览后提交重验版本和引用；已删除来源身份及历史保留，原接收行或来源编号重投跳过，不复活或新建替身，AI和自动补配不再更新。详见[本轮删除及权限规格](../../docs/superpowers/specs/2026-11-17-qms-ledger-permissions-user-management.md)。

### 台账查询标准（2026-11-18，制程不良本地化方案）

多维表格参考项目只提供交互启发，不改变 API 入库的事实边界。制程不良台账的搜索、状态/分类/待办筛选、表头快捷筛选和分页必须使用同一服务端查询口径；`items`、`total`、页码和空态不能由前端当前页数组推导。顶部筛选按钮与表头筛选入口共享一套受限筛选模型，字段和运算符由领域白名单验证，服务端不能接受任意数据库字段、SQL、JSON 路径或脚本。

首版筛选模型只支持有限条件组：文本、日期时间、枚举和数值各自使用匹配的运算符，逻辑为“全部条件/任一条件”，条件数量有界。项目状态必须从已保存项目快照查询，不能在 `view()` 后按当前页派生值过滤；日期按明确来源时区转换后比较，空值、零值和“未确认”保持不同含义。未传筛选参数时继续兼容现有 `page/pageSize/search` 和既有状态参数。

筛选或分页变化时，前端清理不再适用的当前页选择；跨页选择上限、删除预览/引用阻断、版本校验、未知结果重试、AI/补配排除和归档排除继续由原 API/领域服务负责。该标准不新增台账表、视图引擎或全文检索依赖；只有真实查询计划证明需要时才增加索引或高性能表格依赖。具体制程不良台账改造见[筛选聚合设计](../../docs/superpowers/specs/2026-11-18-qms-process-defect-ledger-filter-compact-design.md)和[实施计划](../../docs/superpowers/plans/2026-11-18-qms-process-defect-ledger-filter-compact.md)。

多维表格参考仓库长期索引统一维护在[前端设计参考仓库索引](FRONTEND-DESIGN.md#参考仓库索引)，API 入库相关页面只复用其中的筛选交互原则，不复制外部项目实现。
