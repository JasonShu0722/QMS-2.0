从 `qms-2.0/` 执行：

```powershell
corepack pnpm check:maintenance
corepack pnpm check:governance
```

每项必须有稳定 ID、分类、状态、负责人、已观察事实、影响、触发条件、下一步、复核日期及来源 SHA-256。开放事项的来源变化或复核到期会失败；维护者先比较差异、核对限制是否仍然存在，再更新事实、行动与摘要。复核截止日按 UTC 零点判断，不能仅刷新日期来消除失败。

`MAINT-003` 的判定策略和一次性数据库触发/恢复演练已经纳入 `OPERABILITY-READINESS.md`，但这只补齐可复用的本地判定与验证基础。它仍需在目标运行架构中补齐真实指标出口、只读授权、采样频率、阈值负责人和通知渠道，并用故障注入证明告警触发、处置和恢复；在这些条件完成前不得把台账状态改为 `closed`。

关闭时补 `closedOn` 和 `closure`：指向仓库内实际证据文件、验证命令和 PASS 结果。检查器验证这些字段和文件存在，无法单靠字段证明验证确实执行；关闭前仍须按[开发治理](DEVELOPMENT-GOVERNANCE.md)检查原问题、失败路径及适用的真实环境。原始日志、凭据和备份留在 Git 外，台账只记录可定位的脱敏证据。已关闭事项保留历史；来源后续变化不反向改写当时结论。

新发现的安全更新、弃用、性能瓶颈、容量或重复故障先确认可复现事实，再登记。涉及依赖升级时按[变更影响分析](CHANGE-IMPACT.md)核对官方维护状态与许可证；涉及上线处置时按[维护手册](OPERATIONS-RUNBOOK.md)和发布门禁执行。台账中的 `reviewDue` 是下次本地或 CI 检查的失败条件，不等于持续监控或生产告警。
