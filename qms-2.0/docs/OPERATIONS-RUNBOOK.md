## 故障诊断

发布迁移前必须出现 `Pre-migration encrypted database snapshot verified: <完整SHA>`，随后才执行 Prisma migrate。备份失败、root 权限/目录安全检查失败或解密核验失败会阻断部署；不得删掉检查点来放行。实际路径、独立密钥、恢复到隔离空库和本机快照限制见[数据保护](DATA-PROTECTION.md)。同 SHA 重跑保留旧快照并生成新随机快照，不需要覆盖或删除既有文件。

| 现象 | 只读排查顺序 | 恢复成功的证据 |
| --- | --- | --- |
| 登录或权限拒绝 | 复现时间与 traceId → 会话 → 用户/组织状态 → 功能权限 → 数据范围 → 节点规则 | 原允许场景恢复，原拒绝场景仍拒绝 |
| 待办或通知缺失 | 业务事务与审计 → Outbox → Worker 存活/租约 → 投影 → 实时受众授权 | 事件被处理、待办唯一、无重复通知；不能以 HTTP 成功代替 |
| 邮件未到达 | 申请结果 → 加密投递任务 → Worker 租约/尝试 → SMTP 结果 → 收件验证 | 测试邮箱真实收到且凭证按预期单次有效 |
| 附件不能下载 | 领域授权 → 上传完成核验 → 固定对象版本 → 扫描事实 → 当前状态 | 合法资源可读取，隔离和撤权场景仍拒绝 |
| 冲突或重复操作 | 幂等键与请求摘要 → expectedVersion → 锁顺序 → 事务与回执 | 无重复副作用，409 可解释，失败无部分写入 |
| 恢复失败 | 备份格式/密钥 → 目标库/桶隔离 → 完整性 → 迁移 → 对象引用 | 新隔离环境中逐项一致性和实际读取验证通过 |

先保留脱敏证据，再提出最小修复。禁止直接改状态表“清掉失败”；Outbox 重试通过已有授权接口 `/api/v1/outbox/failures/:id/retry`，依据当前生成契约提供请求，记录重试审计并验证幂等。未知事件归属不放行。相同尝试没有新证据时改查下一层，不无限重试。

## 发布与恢复

1. 固定源码提交和未提交差异、镜像标识、迁移集合、目标环境和操作负责人；任何验收结果都关联这一范围。
2. 按[开发治理](DEVELOPMENT-GOVERNANCE.md)执行阶段及发布门禁；失败或缺配置时停止发布。保留预览库 55440 不用于验收。
3. 核对配置与密钥来源、实际 TLS/代理、SMTP、对象存储、Worker、容量和回退路径。备份前停写与恢复目标要求见数据保护，不能以“备份文件存在”证明可恢复。
4. 在一次性资源验证迁移、历史数据、真实主链及恢复后的一致性；记录实测恢复耗时和恢复点。RPO/RTO 由目标环境明确，不在此假定已达标。
5. 按授权执行目标环境发布，验证登录、权限拒绝、Worker 与附件关键链；失败根据预定条件回退镜像或进入隔离恢复。不可逆迁移不能只靠旧镜像恢复。
6. 记录最终环境、结果与未覆盖项，清理本任务一次性资源；失败恢复目标不切入业务流量。

### 成功部署后的构建缓存回收（CP-1 候选，未发布）

`deployment/deploy.sh` 在 Worker READY、公网检查及 deployed SHA 记录成功后，持有原部署锁执行一次 `docker builder prune --force`，再输出最终部署成功。仅回收默认 builder 的 dangling cache；它不是按 Compose 项目隔离的缓存，后续构建可能需要重建缓存。不加 `--all`，不执行 system/image/container/volume prune，不删除运行镜像、回退镜像、数据卷、上传或加密快照。失败或被更新提交取代的部署不会到达该成功后回收步骤。

清理输出保留 Docker 回收量；清理失败时 stderr 明确“Deployment healthy / builder cache cleanup failed / deployed SHA retained”，脚本非零退出，服务健康及 deployed-sha 不回滚。此时应先核实实际服务 SHA 与磁盘分类，不把 CD 失败自动解释成生产服务回滚。默认 dangling cache 回收不能保证所有磁盘占用下降；本次只交付脚本、控制流测试和文档，未执行生产清理或测量云端回收量。

## 维护触发条件

已观察到、需要跟踪到关闭的事项登记在[维护事项台账](MAINTENANCE-REGISTER.md)；复核期限和来源变化由 `check:maintenance` 检查。下表继续定义日常触发类别，不能把未记录的告警或演练描述为已上线。

| 触发 | 处理要求 |
| --- | --- |
| 文档到期或依赖来源变化 | 比较差异、同步正文，记录复核者和理由，再更新摘要 |
| 安全公告或依赖停止支持 | 查官方公告并关联当前锁文件，按影响分析安排补丁与回归 |
| 通知积压、失败或扫描长时间隔离 | 记录队列最老年龄、数量、租约与错误分类；基于环境基线确定阈值和告警责任人 |
| 备份接近工具容量边界 | 提前评估容量方案并演练；不得放宽完整性检查或默默截断 |
| 密钥、证书或对象保留政策变化 | 按原手册演练轮换和恢复，保留历史解密能力与审计 |
| 同类故障再次出现 | 回顾根因、检测缺口与措施，补原场景回归并验证防复发 |

本表是维护触发清单，不创建后台定时任务。生产指标采集、阈值和通知渠道需要后续环境配置与验收。
