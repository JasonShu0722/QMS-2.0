# QMS 2.0 账号与系统管理

状态：补齐规划，第一切片已完成；管理员治理切片待续。

QMS 2.0 当前已经具备登录、会话、组织范围和权限判定底座，但这些能力不等于可供管理员使用的账号与系统管理功能。本文件把总体设计中的“系统管理”拆成可执行工作包，并记录与 QMS 1.0 横向盘点后确认的遗漏。

## 已有底座

- 独立账号登录、服务端身份分流、HttpOnly Session、CSRF、限流和退出。
- `User`、`Organization`、`Role`、`Permission`、`UserRole`、`Session` 和 `AuditEvent` 数据模型。
- 功能权限、组织数据范围和拒绝审计。
- 当前用户权限上下文查询：`GET /api/v1/system/permissions`。

这些接口服务于平台运行，不提供账号生命周期、资料编辑或权限配置界面。

| 能力 | 现状 | 规划归属 |

| 用户生命周期 | 缺少用户创建、禁用、启用、组织归属、账号类型和管理员重置 | 切片 B |

| 组织与基础资料 | 只有组织读取和范围校验，缺少组织维护、部门/岗位和系统字典 | 切片 D |

QMS 1.0 的供应商主数据、客户主数据、制程和审核专业字段不并入本工作包；它们仍由各自业务域负责。

## 执行顺序

### 切片 A：个人账号中心

- 个人资料：当前账号查看和编辑允许字段，敏感字段不回显。
- 修改密码：验证旧密码、校验新密码、记录审计并撤销其他会话。
- 会话管理：列出当前账号的有效会话元数据，支持撤销其他会话。
- 两类门户共用入口，入口由服务端会话决定，不能通过客户端切换身份。

### 切片 B：管理员用户与组织归属

- 管理员查询、创建、启用、禁用和编辑用户基本信息。
- 维护账号类型、主组织和组织角色分配。
- 管理员重置密码必须一次性、可审计，不能读取原密码。
- 所有写操作使用独立管理权限、组织范围校验、CSRF、审计和幂等保护。

### 切片 C：角色与权限管理

- 只读权限目录与稳定权限代码。
- 角色模板、角色与权限绑定、用户角色分配和权限矩阵。
- 全局角色与组织角色边界明确，不能通过组织参数越权。
- 流程节点权限继续由流程运行时校验，不能被普通功能权限替代。

### 切片 D：组织与基础资料

- 组织层级、部门、岗位和启停状态。
- 受控系统字典和参数，变更审计，禁止把业务域专业字段做成通用大表。
- 通知模板和规则只提供平台事件能力，业务文案由业务域扩展。

### 切片 E/F：安全增强与管理审计

- 管理员强制 MFA，普通账号按角色和策略启用。
- 密码找回、MFA 变更、会话撤销和权限变更均记录安全审计。
- 操作日志按组织、操作者、资源、动作、结果和时间查询，敏感字段脱敏。

### 切片 G/H：横向治理

- G：TLS 终止与密钥轮换、对象存储访问保护、数据库/附件备份、恢复演练和结果留痕。
- H：数据导出与报表权限、导出审计和保留策略；核心页面国际化与可访问性验收。

## 验收门槛

## 依赖与并行策略

G/H 不要求在 F 完成后串行启动。G 的 TLS/密钥、对象存储保护可与 B/C 并行，备份恢复演练在试点验收前必须完成；H 应先冻结导出授权、保留策略、国际化和可访问性基线，再与 D–F 及业务页面并行实现。

A、B、C 验收通过后，允许启动批次 3 的领域建模、接口草案、自动化夹具和非生产实现。供应商质量真实试点和发布仍需 D/E/G/H 的最小门禁全部通过。

- 用户、组织、角色和权限写操作都有明确功能权限与数据范围拒绝用例。
- 修改密码后旧密码失效，其他会话按策略撤销，审计与事务一致。
- 禁用用户无法建立新会话，已有会话按策略失效。
- 管理员不能读取密码、Session 令牌原文或哈希、MFA 秘密或重置令牌；前端仅使用服务端返回的会话撤销句柄。
- OpenAPI、前端生成类型、管理页面和真实浏览器主链路同步验收。
- 不从 `archive/qms-1.0/` 复制兼容层；只提取经过重新设计的业务能力边界。

本轮已完成切片 A 的 API、生成契约和两类门户个人账号页，并为切片 B/C/G/H 建立规划边界；完整管理员后台和横向治理不会在一个切片中伪装完成。
