## 本人头像增量（E / V0.0.11）

供应商用户账号由内部管理员在供应商档案按需创建，人员账号不是外部 API 凭据。首次显式开通独立企业隔离边界，一家可多账号，不开放供应商自行注册/邀请。账号创建、有效临时密码、重置、停用分别沿已有账号治理权限与档案组织范围，专用入口不放宽通用账号目标权限约束。详情及候选交付状态见 [供应商交接](SUPPLIER-PLATFORM-HANDOFF.md)。

内部与供应商个人账号中心提供本人头像上传、更换和移除，右上角个人菜单使用同源头像。仅允许 JPEG/PNG、最大 2 MiB；`ACCOUNT_AVATAR` 的资源标识必须为当前本人用户 ID，不能由管理员权限代替本人访问，亦不开放他人头像目录。

`PATCH /api/v1/me/avatar` 使用 CSRF、`Idempotency-Key`、`expectedVersion`，在同事务内重新验证会话、私有文件归属、CLEAN 扫描证据、头像版本与审计。`/me` 仅返回头像文件 ID 和版本，不返回签名地址。移除清业务引用，保留扫描文件及对象历史。头像版本独立于安全版本，修改头像不撤销登录会话。

照片仍经过真实文件生命周期和扫描 Worker，未上传完成、扫描中、失败或病毒隔离时不能设置。浏览器每次经授权下载取短期签名，再获取固定版本内容形成内存 Blob；换图、卸载、退出及会话切换清理旧地址和迟到结果，不把地址放入持久存储。源码、机器证据和上线后的人工确认分开记录，见 [A/B/E 实施计划](../../docs/superpowers/plans/2026-10-17-qms-p0-p1-web.md)。

## ABC 契约与安全边界

- `GET /api/v1/admin/organizations` 仅列当前用户持有账号或 D–H 治理目录权限中至少一项的组织，返回组织摘要、`type` 和该组织 `permissions`；供应商最多本企业。写权限不隐含 read。
- B/C 所有管理写请求须携带 `Idempotency-Key`（8–128 个字母、数字、点、下划线、冒号或连字符）。相同内容重试复用同一 key；新操作使用新 key；不同内容复用 key 返回 409。
- `PATCH /api/v1/admin/users/:id?organizationId=源组织`，body 的 `organizationId` 表示目标组织；迁移要求两端 `account:users:transfer`，并覆盖目标用户各已分配组织的既有权限，成功清理旧组织角色并撤销会话。含全局角色的身份迁移被拒绝，自停用、自迁移和自类型变更被拒绝。
- 用户被问题负责人、流程任务办理人或通知接收人引用时，主组织变更返回 `ADMIN_USER_ORGANIZATION_IN_USE`（409），保留全部业务历史、角色、会话和重置凭证。数据库外键同时禁止级联变更业务组织；邮箱编辑和停用仍可执行。业务归属调整须由相应领域定义迁移策略，不能借账号管理隐式搬移。
- `POST /api/v1/admin/users/:id/password-reset` 接收 `{ temporaryCode }`，返回 201 `{ resetId, expiresAt }`。前端用 `crypto.getRandomValues` 生成至少 32 字符的安全随机 base64url 临时代码并一次展示；服务端不返回、不存储代码原文，签发不改变当前密码。
- 独立 `/reset-password` 页面调用 `POST /api/v1/auth/password-reset/complete`，提交 `{ resetId, temporaryCode, newPassword }`；先取得 CSRF，成功返回 204。凭证 30 分钟过期且只能使用一次，兑换成功才更新密码、撤销会话。此流程不自动发送邮件。
- 用户名限 ASCII 字母、数字、点、下划线、连字符。用户名和邮箱全局大小写无关唯一；迁移遇旧数据冲突明确失败，需管理员清理后重新部署，不能静默删除或覆盖数据。
- 组织角色权限只能从管理员在所选组织已有权限中授予；修改现有角色、分配或移除成员角色也校验既有权限，不能绕过升权限制。禁止删除仍有成员的角色、操作其他组织角色、通过组织分配移除全局角色或使自己失去既有管理权限。
- 权限目录定义只读，矩阵可配置当前组织角色，保存使用带原权限基线的角色 PATCH，没有独立矩阵写入接口。角色复制创建当前组织的新角色，不复制为全局角色。纯角色改名仅 PATCH `name`，不重写权限；真正的权限/角色分配变化使受影响用户未消费的重置凭证失效。
- A 仅编辑邮箱；资料与审计同事务。会话列表只返回有效会话的撤销句柄与元数据，不能回显令牌或哈希。本人改密保留当前会话、撤销其他会话并使旧重置凭证失效；旧哈希条件更新防止并发覆盖。
- 登录在密码校验后持有用户行锁，重新核对账号状态、密码哈希、主组织和类型，并在同一事务创建会话；并发停用、迁移或改密不能通过已经验证过的旧身份重新登录。
- API DTO/Swagger 生成的 `@qms/contracts` 是 Web 唯一类型来源，完整路径、参数和返回值见 [OPENAPI](OPENAPI.md)。初始密码、临时代码和新密码仅存在前端内存，不进入 URL、浏览器持久存储或日志。MFA 与自助邮件找回已在 D–H 实现；供应商业务试点仍需独立验收。

## 分板块矩阵与可操作范围

角色清单的权限列按权限码去重，显示数量及最多两个模块摘要；详情按钮打开只读抽屉，按板块／模块展示该角色实际权限并支持名称／代码搜索。未匹配目录时保留受控名称／代码，关闭恢复触发按钮焦点；组织切换加载或失败期间清除旧角色及目录，失权或删除角色后关闭旧详情。REQ-0023 的本地验证和未上线／待业务浏览器验收状态见[联合实施计划](../../docs/superpowers/plans/2026-10-19-qms-profile-position-role.md)。

选择组织和角色后，可按板块筛选，并搜索模块、权限名称或代码。模块复选框、全选和清空仅影响当前显示模块中可授予的操作，不改变隐藏板块或不可授予项；页面显示修改数量，支持保存和重置。角色创建/编辑共用同一分组选择器。标签切换保留草稿，无须确认；存在草稿时切换角色或组织须确认放弃；无变化不发 PATCH。权限目录按平台功能、供应商质量、制程质量、客户质量、新品质量、审核管理、系统管理排序。

| 模块 | 现行独立权限 | 操作范围 |
| --- | --- | --- |
| 用户管理 | `account:users:read` | 列表与详情读取 |
| 用户管理 | `account:users:create` | 新建用户；创建组织候选按此权限筛选 |
| 用户管理 | `account:users:update` | 编辑邮箱；空 PATCH 也要求此权限 |
| 用户管理 | `account:users:status` | 启用或停用 |
| 用户管理 | `account:users:transfer` | 主组织或账号类型变更；迁移组织候选按此权限筛选，跨组织须两端持有 |
| 用户管理 | `account:users:reset` | 签发一次性重置凭证 |
| 角色管理 | `account:roles:read` | 角色、分配、权限摘要、只读详情及分组目录读取 |
| 角色管理 | `account:roles:create` | 创建或复制角色 |
| 角色管理 | `account:roles:update` | 修改名称或权限 |
| 角色管理 | `account:roles:delete` | 删除未使用角色 |
| 角色管理 | `account:roles:assign` | 替换用户在所选组织的角色分配 |

用户页按对应权限显示按钮和字段，不能把 update 当成停用、迁移或重置权限。混合 PATCH 必须拥有所有提交字段的权限，否则整体拒绝；服务事务在幂等回放前再次检查完整权限集合和迁移两端。自锁保护包含全部账号与新增治理管理权限。只有写权限并不自动获得列表、详情或目录读取能力。

保存角色权限时发送 `permissionCodes` 和读取时的 `expectedPermissionCodes`。缺少必需基线返回 400，当前集合已变化返回受控 409，名称与权限均不部分提交。Web 保留冲突草稿，重新加载须确认放弃；只改角色名不带两个权限字段。没有角色 update 的账号只能查看矩阵；全局角色禁止组织接口编辑，前端同样只读。管理员没有持有的操作禁用，即使批量选择也不会授予。

平台现有模块为工作台、问题查询、受控流程；系统模块为组织目录、当前权限上下文、用户管理和角色管理。工作台查看明确标作预留权限，不宣称独立工作台 API 拦截已交付；受控流程定义使用 `workflow:manage`；P1 运行时另有 `workflow:start`/`workflow:act`，仍需节点规则与数据范围授权。供应商质量列出供应商管理、供应商绩效、供应商审核、PPAP、供应商整改；制程、客户、新品和审核各板块也仅列待接入模块。planned 模块没有操作代码、可选复选框或本轮业务入口，不能伪造代码授予。

PostgreSQL 迁移原子把旧 `account:users:manage` 展开为五个写权限、`account:roles:manage` 展开为四个，包含全局角色，去重后移除旧关联与记录。UserRole、既有 read 和历史审计不变，不自动补 read；种子和运行时都不恢复旧 manage。升级应用与迁移需协调完成。

后续业务域注册权限时，必须同步 API 静态 catalog、真实接口 Guard/事务授权、数据库 Permission 迁移、DTO/生成 contracts 和允许/拒绝测试；有真实业务入口与验证证据后才能从 planned 转为 active。数据库单独插入未知代码不足以成为可授予权限。不得为了目录展示虚构删除、导出或审批能力，也不得用普通角色矩阵替代流程节点权限。

## 执行顺序

### 切片 A：个人账号中心

- 个人资料：当前账号查看和编辑允许字段，敏感字段不回显。
- 修改密码：验证旧密码、校验新密码、记录审计并撤销其他会话。
- 会话管理：列出当前账号的有效会话元数据，支持撤销其他会话。
- 两类门户共用入口，入口由服务端会话决定，不能通过客户端切换身份。

### 切片 B：管理员用户与组织归属

- 管理员查询、创建、启用、禁用和编辑用户基本信息。
- 维护账号类型、主组织和组织角色分配。
- 管理员重置密码必须一次性、可审计，不能读取原密码。
- 所有写操作使用独立管理权限、组织范围校验、CSRF、审计和幂等保护。

### 切片 C：角色与权限管理

- 只读权限目录与稳定权限代码。
- 角色模板、角色与权限绑定、用户角色分配和权限矩阵。
- 全局角色与组织角色边界明确，不能通过组织参数越权。
- 流程节点权限继续由流程运行时校验，不能被普通功能权限替代。

### 切片 D：组织与基础资料

- 组织层级、部门、岗位和启停状态。
- 受控系统字典和参数，变更审计，禁止把业务域专业字段做成通用大表。
- 通知模板和规则只提供平台事件能力，业务文案由业务域扩展。

### 切片 E/F：安全增强与管理审计

- 管理员强制 MFA，普通账号按角色和策略启用。
- 密码找回、MFA 变更、会话撤销和权限变更均记录安全审计。
- 操作日志按组织、操作者、资源、动作、结果和时间查询，敏感字段脱敏。

### 切片 G/H：横向治理

- G：TLS 终止与密钥轮换、对象存储访问保护、数据库/附件备份、恢复演练和结果留痕。
- H：数据导出与报表权限、导出审计和保留策略；核心页面国际化与可访问性验收。

## 依赖与并行策略

G/H 不要求在 F 完成后串行启动。G 的 TLS/密钥、对象存储保护可与 B/C 并行，备份恢复演练在试点验收前必须完成；H 应先冻结导出授权、保留策略、国际化和可访问性基线，再与 D–F 及业务页面并行实现。

用户已授权本轮 D–H，且已另行启动阶段三非生产建模、规则、表单和门户。供应商真实试点/发布仍须集成已验收平台变更、跨企业资源授权、P3 附件证据闭环、真实业务浏览器主链路及生产部署门禁；本轮治理验收不自动放行这些业务和部署条件。

## 验收门槛

- 用户、组织、角色和权限写操作都有明确功能权限与数据范围拒绝用例。
- 修改密码后旧密码失效，其他会话按策略撤销，审计与事务一致。
- 禁用用户无法建立新会话，已有会话按策略失效。
- 管理员不能读取密码、Session 令牌原文或哈希、MFA 秘密或重置令牌；前端仅使用服务端返回的会话撤销句柄。
- OpenAPI、前端生成类型、管理页面和真实浏览器主链路同步验收。
- 不从 `archive/qms-1.0/` 复制兼容层；只提取经过重新设计的业务能力边界。

本轮浏览器场景覆盖内部 A 资料/改密/会话、供应商 A 资料及入口隔离、B 创建/编辑/启停、C 角色/复制/分配/矩阵、只读账号 UI 与 API 拒绝、凭证签发后纯角色改名和匿名单次兑换。迁移、审计回滚、授权边界、幂等和登录竞态另有真实 PostgreSQL 与 HTTP 证据。每层实际 PASS/FAIL 及完整聚合结果均以 FOUNDATION 最新记录为准，不能用单层通过替代整体门禁。
