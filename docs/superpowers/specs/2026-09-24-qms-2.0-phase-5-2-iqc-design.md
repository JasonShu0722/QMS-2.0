# QMS 2.0 阶段五 5.2 IQC 来料检验设计规格

- 日期：2026-09-24
- 状态：后端开发切片已完成，待真实资源、业务浏览器和 MES 联调验收；本文不构成生产验收完成证据
- 上位规划：[阶段五覆盖补齐与分析增强设计](2026-09-24-qms-2.0-phase-5-coverage-and-enhancement-design.md)
- 用户决策：C1 接入 IQC；预留 MES 来料批次和检验结果接口；重点物料检验记录支持拍照存档

## 1. 范围与业务边界

本子波次建立内部 IQC 来料检验台账：记录供应商、物料、来料批次、到货与抽检数量、检验项目及结果、检验人员与时间，支持重点物料检验照片。内部人员可按供应商、物料、批次、期间和结论检索，并从记录进入受授权的照片和关联供应商问题。

IQC 记录是检验事实，不等于供应商整改问题。检验 NG 后由有权限的内部人员显式发起现有 `supplier-quality` 问题草稿；正式发单继续经过现有编号、问题索引和 Workflow。来源记录与问题保持稳定引用和创建时快照，禁止仅靠物料编码或文本推断关联。重复触发须返回已关联问题，不得产生两张同源草稿。

C2 特采审批、放行互锁，C3 准入，以及供应商资质、绩效、PPAP 和结算不属于本子波次。检验结论不直接控制 MES 收货、库存或生产放行；这些业务动作需另立接口与权限决策。

## 2. 领域事实与约束

新增 `supplier-incoming` 领域拥有来料检验事实，不向 `SupplierQualityProblem` 表塞检验项目，也不复制供应商问题的状态机。现有 `SupplierBusinessProfile` 用作拥有组织与供应商企业关系的服务端校验依据；检验记录保存创建时供应商名称、业务编码、物料编码、批次及来源值快照，避免资料后改破坏历史解释。

| 事实 | 字段与规则 |
| --- | --- |
| Inspection | UUID、拥有组织、供应商资料 ID、物料编码、来料批次、到货数量、抽检数量、结论、检验人/时间、版本、创建来源；数量为正整数，抽检数量不得大于到货数量 |
| InspectionItem | 检验项目名称、实测或定性结果、判定、记录顺序；保留输入文本，不推断未配置的公差或抽样标准 |
| SourceSnapshot | `MANUAL` 或 `MES`、外部来源键、来源批次键、观察时间、接收批次、原始字段快照、映射版本和内容摘要；外部键在拥有组织及来源系统内唯一 |
| InspectionPhoto | 检验记录与平台文件 UUID 的引用、用途、拍摄/上传说明；只存文件引用，不存对象地址或扫描状态副本 |
| ProblemLink | 检验记录与供应商问题 UUID、触发时结论和来源摘要；一个检验记录默认至多触发一个主问题，正式问题仍由供应商模块与平台持有 |

人工记录必须标记 `MANUAL`，不得伪装成 MES 同步。重点物料分类需要来自经确认的物料主数据或可审计的内部标记；在规则未确认前，照片为可选证据，不以“重点物料”推导照片必填、自动 NG 或放行限制。提交后的检验事实不可原地改写为另一批次；更正保存修订与原因、操作者和时间，保留原始快照。阶段初始可先实现草稿、完成、只读查询与更正审计；不建立可自定义检验流程引擎。

## 3. 权限、组织隔离与问题关联

- 内部用户使用独立 `supplier-incoming:inspections:read/write` 功能权限，按服务端已授权的拥有组织访问。供应商账号默认无 IQC 台账及照片权限，不因关联 `SupplierBusinessProfile` 自动获授权。
- 检验记录创建时核对资料的 `ownerOrganizationId`、`supplierOrganizationId` 和资料版本；请求中的组织或供应商 ID 不得扩大范围。详情及列表在过滤后读取；不可见与不存在统一处理。
- 建立问题草稿时同时校验 IQC 写权限、现有供应商问题写权限、当前资料关系和结论 NG；问题创建继续使用现有事务、幂等、审计和问题索引边界。已撤权用户不得借旧幂等键重放。
- 对记录完成、更正、关联问题使用服务端版本 CAS、`Idempotency-Key`、CSRF、审计和明确的 409 冲突。检验事实、问题关联与回执在同一数据库事务提交；外部 MES 请求不参与该事务。

权限目录只有在控制器、数据库约束、允许/拒绝测试和前端入口同时交付后才由 `planned` 改为 `active`。Web 仅从 Nest Swagger 生成的 `@qms/contracts` 引用 DTO。

## 4. 照片与附件扫描

IQC 照片复用平台 `FileLifecycleService` 的初始化上传、对象存储、扫描 Worker、资源鉴权及下载短链接。新增独立 `supplier-incoming` 资源适配器，以检验记录 UUID 为 `resourceId`；不借用现有 `supplier-quality` 适配器，因为现有适配器仅授权已建公共问题索引的供应商问题。

上传照片时按检验记录拥有组织、当前版本、内部账号和 `supplier-incoming:inspections:write` 校验；读取按 `read` 权限、组织和文件归属重新校验。只有平台判定 `AVAILABLE` 且扫描 `CLEAN`、对象校验一致的文件可附着到已完成记录或下载。`WAITING_UPLOAD`、`PENDING`、`REJECTED`、`ERROR`、`EXPIRED`、`DELETED` 均不能作为已通过扫描的检验证据。扫描失败需呈现原因、允许新文件重试并保留检验草稿；不得把客户端状态写成通过。

检验记录与照片引用的提交使用同一事务及资源版本检查；完成后禁止静默替换历史照片，修订通过新增引用及审计处理。对象内容、上传日志和凭据不进 Git。

## 5. MES 适配器契约与来源快照

MES 端口只接收来料批次和检验结果，不把 MES 值直接写成已完成的人工检验记录。适配器输入至少包含来源系统、外部记录键、外部批次键、供应商外部键、物料编码、来料数量、检验项目/结果、事件时间与时区、修订号和原始负载摘要。映射时服务端解析拥有组织与 `SupplierBusinessProfile`；无法解析时进入隔离失败记录，不创建错误归属的检验事实。

适配器输出保留接收批次、映射版本、原始值快照、映射后值、处理状态、失败原因和审计。以 `(拥有组织, 来源系统, 外部记录键, 修订号)` 去重；相同内容重放返回原回执，不同内容使用同键报冲突。晚到或更正事件不得覆盖较新修订；失败可按同一来源键重试且留痕。MES 未提供字段、认证、签名/传输方式及样本前只定义端口和持久化边界，保持同步未启用，不生成模拟成功数据。

质量数据 5.1 指标事实从 IQC 已完成记录的稳定引用与来源快照派生；指标不反向修改 IQC 检验事实。批次下钻先到 IQC，再依授权进入供应商问题，跨组织引用不得泄漏详情。

## 6. API 与页面交付形态

Nest Swagger 计划提供内部分页台账、创建草稿、读取详情、完成、带原因更正、问题草稿触发和来源快照读取入口；URL 统一置于 `/api/v1/supplier-incoming/inspections` 下。列表默认最近期间、稳定排序和页上限，按组织强制过滤；详情返回项目、照片可用状态、问题引用及来源类型。前端入口挂在内部供应商质量导航，不向供应商门户开放。

页面需支持草稿与照片上传进度、扫描等待/拒绝/重试、NG 显式发起问题、同源问题跳转、来源快照以及 409 后保留输入。按钮可见性取自服务端权限与记录能力，不能仅以浏览器角色名称判断。MES 未启用时仅展示未启用状态，不显示同步成功或虚构数据。

## 7. 验收门槛

1. 真实 PostgreSQL 迁移验证数量、来源唯一键、关联外键、版本冲突和事务回滚；至少两个内部组织、两个供应商企业，覆盖允许、跨组织拒绝、撤权和同键不同内容冲突。
2. 真实对象存储、扫描服务与 Worker 验证照片上传、待扫描、通过、拒绝、失败重试、跨记录/跨组织访问拒绝和下载授权；未扫描文件不能成为完成证据。
3. API、Swagger 生成契约、Web 和真实 Chromium 浏览器完成一条人工 IQC 草稿→照片→扫描→完成→NG 关联供应商问题→下钻链，以及重复点击、409 保留草稿和扫描失败路径。
4. MES 真实联调需先取得字段字典、认证方式、时区、样本和测试环境；未取得前记录契约与未启用原因，不能将单元夹具视为真实联调 PASS。
5. 运行受影响 API/Web 测试、lint/build、`contracts:generate`、`contracts:check`、`check:governance` 和 `git diff --check`，在 `qms-2.0/docs/PHASE-5.md` 逐项记录实际命令、环境、PASS/FAIL 及未覆盖范围；一次性资源与保留预览数据库 `55440` 隔离。
