# A2 Worker、提醒与升级可观测性设计规格

- 日期：2026-09-26
- 状态：阶段五 A2 开发切片
- 范围：到期提醒、逾期升级、通知重试、定时任务已经由 Workflow 与 Outbox 实现；本切片补齐 Worker 周期结果的受控运行观测。

## 1. 现状与缺口

`WorkflowEventHandler` 和 `workflow-timing.ts` 已在事务内创建到期提醒、逾期升级和定时 Outbox 事件。`OutboxWorkerService` 已提供 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取、租约回收、有限重试、失败队列和人工重试。现有进程测试验证了真实 Worker 启动、持续轮询和 `--once`，但运维无法从标准输出区分一次消费周期的成功、重试和失败数量。

## 2. 本切片交付

- `runWorkerLoop` 接受可选周期观察器，在每个完成的 Outbox 周期后报告 `processed`、`retried`、`failed`。
- Worker 通过环境开关 `QMS_WORKER_LOG_CYCLES=true` 输出一行结构化 `QMS_WORKER_CYCLE` 日志；默认不输出，避免改变现有日志契约。
- 非法开关值与其他 Worker 配置一样以 `WORKER_CONFIGURATION_INVALID` 非零退出。
- 真实编译 Worker `--once` 测试验证日志字段可被解析，真实 PostgreSQL 仍由既有 timing、projection、outbox 和 worker-process 集成测试覆盖。

## 3. 边界

- 不新增邮件、IM 或其他通知通道，不把日志视为投递成功证据。
- 不改变通知受众、提醒时间、升级权限、Outbox 重试次数和数据库状态机。
- 指标采集、阈值告警、日志持久化和生产通知渠道仍属于 MAINT-003 运维交付，不在本切片宣称完成。

## 4. 配置与回滚

生产默认不设置 `QMS_WORKER_LOG_CYCLES`。出现日志解析或容量问题时移除该环境变量即可回到原有 Worker 行为；代码回滚只涉及 Worker 入口和 runner，不涉及迁移。

## 5. 验证要求

- API TypeScript 编译通过。
- Worker runner 单测验证周期观察器。
- 真实 PostgreSQL timing/projection/outbox 集成测试通过。
- 真实编译 `dist/worker.js --once` 验证 `QMS_WORKER_CYCLE` JSON 行。
