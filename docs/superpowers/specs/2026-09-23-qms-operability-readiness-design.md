# QMS 运行观测与隔离演练设计

**目标：** 在试点前提供可复核的 Outbox 与扫描滞留快照，并复跑现有真实 PostgreSQL/对象存储备份恢复演练。生产采集、告警阈值与通知渠道仍由目标环境单独配置和验收。

## 方案选择与边界

新增公开 HTTP 指标接口会引入授权、契约、数据范围及部署暴露面；直接部署监控栈需要目标环境、阈值基线和责任人。本轮先做只读运维快照命令：只接收显式声明的一次性 loopback 数据库，拒绝保留预览端口 55440，以只读事务查询聚合数量和最老年龄，不读取事件载荷、错误正文或文件名。将观察字段与现有 Worker/扫描状态对应，并在 Git 外保存实测报告。

快照包含已到期待处理 Outbox 数、失败数、最老到期年龄，以及待扫描/扫描错误文件数、最老待扫描年龄。它只表明采样时的数据库状态；不能据此证明 Worker 正常、通知已送达、告警已上线或生产恢复能力。扫描拒绝属于业务安全结果，不混同扫描错误。

## 演练与失败条件

在本任务一次性 PostgreSQL 和 MinIO 上复跑已有 `data-protection.acceptance.mjs`，使用新建库、桶、Git 外密钥与产物，保留真实 PASS/FAIL 和资源清理状态。缺少 Docker、凭据或对象服务时明确 `NOT_RUN`，不换成 SQLite/Mock。测试工具必须验证 55440、非 loopback、非一次性目标在连接前失败；数据库查询失败返回非零且不输出连接串。
