# QMS 维护事项台账设计

**目标：** 让已知的弃用、容量限制、性能和重复故障有负责人、触发条件、复核期限和关闭证据，并在来源变化时提醒复核。

## 方案选择

外部工单系统适合团队协作，但当前仓库没有稳定的工单连接与字段约定；纯 Markdown 清单易读，却难以检查过期和虚假关闭。本轮使用 Git 内小型 JSON 台账和中文导航，检查器只验证可判定的结构、来源摘要、期限及关闭证据。它不自动声称外部安全公告已检查，也不创建后台定时任务。

## 记录边界

每项包含稳定 ID、分类、状态、负责人、已观察事实、影响、触发条件、下一步、复核日期及来源文件摘要。当前登记本轮实测的 Ant Design 弃用提示、数据保护文档明确的备份容量限制，以及尚未部署生产告警的试点准备缺口。开放事项不能出现关闭时间；关闭事项必须有真实证据文件、验证命令、结果和日期。来源变化或复核到期使治理检查失败，促使维护者核实后更新，不自动判定业务语义。

## 验证

先写重复 ID、来源变化、过期、无证据关闭及合法开放项的反例测试；再接入 `check:governance`、默认测试、索引与中文运维入口。台账不读取秘密、原始日志或备份，不代替发布检查。
