# QMS 2.0 阶段五 5.1 质量数据与指标基础设计规格

- 日期：2026-09-24
- 状态：首个后端纵向切片已实现，外部系统联调和正式看板仍未验收
- 上位规划：[阶段五覆盖补齐与分析增强设计](2026-09-24-qms-2.0-phase-5-coverage-and-enhancement-design.md)

## 1. 本切片范围

5.1 先建立组织隔离的指标定义、来源快照引用、指标事实和趋势查询基础。指标事实保存分子、分母、计算值、统计期间、来源系统、来源记录键和维度快照，允许后续从指标下钻到来源记录或正式问题。

当前支持人工记录以及 `IMS`、`MES`、`ERP`、`SAP` 来源标识；外部系统尚未核实字段、认证和测试样本前，不启动真实同步。

## 2. API 入口

- `GET /api/v1/quality-data/metrics`：读取当前组织指标定义。
- `POST /api/v1/quality-data/metrics`：创建指标定义，使用幂等键和审计。
- `POST /api/v1/quality-data/facts`：记录指标事实，服务端计算分子/分母结果。
- `POST /api/v1/quality-data/snapshots`：登记外部来源的待核实快照，不自动转成指标事实。
- `GET /api/v1/quality-data/trend`：按指标和期间读取趋势事实。
- `GET /api/v1/quality-data/dashboard`：读取当前组织的指标定义与各指标最近事实。

所有入口使用 `quality-data:metrics:read` 或 `quality-data:metrics:write`，并通过服务端组织范围校验。写入复用平台幂等、最近认证、审计和并发冲突处理。

## 3. 数据边界

- 指标定义和事实属于质量数据模块，不修改供应商、制程、客户或新品领域事实。
- 来源快照只保留来源系统、外部键、观察时间、原始 JSON 和待核实状态；真实适配器在后续波次接入。当前指标事实仅允许人工来源，禁止将未联调的外部标识当作同步成功。
- 趋势查询只读指标事实，不把聚合结果回写领域表。
- AI 分析、自动决策、自然语言生成 SQL 和自动业务写入不属于本切片。

## 4. 验收门槛

- 真实 PostgreSQL 可部署迁移并验证组织隔离、唯一来源键、期间约束和分母大于零。
- API 契约由 Nest Swagger 生成并通过 `contracts:check`。
- API lint/build 通过；后续补充真实集成测试覆盖重复事实、跨组织读取、撤权、409 和趋势边界。
- 外部系统连接必须在字段、认证、样本和失败重试策略确认后另立适配器子计划。
