# 阶段五 C6：供应商 PCN 变更管理设计

## 目标与授权

依据阶段五总设计中已纳入本期的 C6，支持供应商材料、工艺、设备和场地变更申报，由内部质量人员审批。用户已授权先完成开发再进行整体验收。本切片使用活动 checkout，不创建遗漏现有未提交成果的独立 checkout。

## 方案选择

采用独立 `supplier-pcn` 领域模块保存申报事实，审批由平台 `ProblemIndex` 与 `WorkflowRuntimeService` 处理。复用供应商资料提交模块会混淆质量资料接受与变更批准；领域自行推进审批状态则违反阶段五总设计。因此内部人员从已发布的、组织内的 PCN 专用流程版本启动审批，动作严格由受控节点决定。

## 数据与状态

申报包含供应商业务档案、变更类别 `MATERIAL/PROCESS/EQUIPMENT/SITE`、标题、物料编码、变更前后情况、原因、风险控制和计划日期。领域状态仅表达 `DRAFT/SUBMITTED/NEEDS_CHANGES/APPROVED/CLOSED` 事实；`APPROVED/CLOSED/NEEDS_CHANGES` 必须由平台 Workflow 的 `APPROVE/CLOSE/RETURN` 成功事务回写，不设可绕开平台的审批入口。平台流程以供应商 `ACTION` 节点起始，流转至内部 `APPROVAL` 节点，批准后进入 `CLOSE` 节点；退回通过 `RETURN` 回已访问的供应商节点。供应商修订后以 `SUBMIT` 回审批节点。审批表示质量批准，不能替代实际变更实施或外部客户批准。

每次创建、修改、提交、审批递增版本并新增不可覆盖的事件；事件保留当时申报内容、附件和审批意见，避免补充后丢失审核依据。计划日期采用有效的 `YYYY-MM-DD`，不得接受日期归一化产生的不存在日期。数据库约束限制类别、状态、版本、非空文本和档案组织关系。

## 权限与隔离

内部使用 `supplier-pcn:requests:read/approve`，供应商使用 `supplier-pcn:submissions:read/write`。服务再次检查身份与权限；供应商仅能访问本企业所属的业务档案和 PCN，内部仅能访问其已授权组织拥有的 PCN。越界详情返回 404，查询组织越界返回 403。跨模块档案查询调用 `SupplierQualityService` 公开读模型。

## 写入与文件边界

所有写入必须有近期认证、CSRF、`Idempotency-Key` 和资源版本（创建除外），并在 `ReadCommitted` 事务中锁定资源，使用条件更新防止过期状态写入。平台 `WorkflowRuntimeService` 对启动和节点动作再执行工作流版本、节点、任务与问题索引 CAS。幂等重放先检查当前资源访问，权限撤回后不能取回历史响应。同键同载荷只产生一个事件，同键异载荷拒绝。成功和拒绝都有审计。

首次提交和退回后重提必须绑定本 PCN 的真实 `AVAILABLE/CLEAN` 文件；不接受隔离、感染、其他资源或其他供应商的文件。文件适配器仅允许供应商在草稿/需补充状态上传，双方按 PCN 读取权限下载，禁止删除审核证据。审批前再次确认已提交证据仍可用。工作流节点的供应商处理还需 `workflow:act`、该节点 `assignment` 授权与 `supplier-pcn:submissions:write`；内部审批需 `workflow:act`、节点授权与 `supplier-pcn:requests:approve`。

## API 与页面

内部入口 `/api/v1/supplier-pcn/requests`，供应商入口 `/api/v1/supplier-portal/pcns`；提供分页状态筛选、详情、供应商档案引用选择、创建、修订、提交、启动工作流及节点动作。启动必须校验已发布流程的节点结构与 PCN 权限 assignment，避免任意流程冒用 PCN 记录。Swagger 是 Web 类型来源。

页面复用 Ant Design 台账、详情 Drawer、Form、AttachmentPanel 和未保存保护；内部可查看详情和填写审批意见，供应商可选择档案新建/修订并上传扫描附件。失败保留输入，冲突提示刷新，403 清除敏感内容；支持加载、空数据、筛选无结果、错误、无权限、分页和窄屏局部表格滚动。
