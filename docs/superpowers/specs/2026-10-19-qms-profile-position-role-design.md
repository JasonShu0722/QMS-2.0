## 3. 岗位角色自动生效

```text
有效角色 = 直接分配角色 ∪ 当前有效任职所关联的岗位角色
有效权限 = 同一授权组织范围内所有有效角色权限的去重并集
```

- 同一角色可以同时来自直接分配和多个岗位。角色只展示一次，另列全部来源；撤销一个来源不影响其他有效来源。
- 保存岗位角色关联后，当前在岗人员自动获得／失去该来源。新增任职、任职结束、岗位停用自动进入下一次请求鉴权，无需重登或再审批。
- 既有 UserRole 在迁移后仍是直接分配；岗位角色映射初始为空，不凭角色名／部门名／岗位名自动推断映射，不改变既有权限。
- 岗位、任职和角色绑定必须属于同一组织，不引入组织树授权继承。内部账号既有跨组织直接管理授权保留，供应商不能跨组织。
- 部门／组织停用遵循既有受控启停规则，停用范围的岗位来源失效。祖先节点传播须对照既有组织治理行为固定测试，不自行新增隐式跨层授权。
- 修改角色权限或 MFA 要求必须影响所有直接及有效岗位任职来源；不能只更新直接 UserRole 的人员。
- 自动生效以配置／任职事务提交成功为界，后续请求使用新结果；不反向改写已完成业务及历史审计。受控的高风险在途写入在事务中复验授权／安全版本，不能用旧 Guard 判定继续完成撤权后的写入。

### 3.1 写入、安全与删除边界

- 岗位角色配置同时检查岗位维护、角色读取与角色分配能力，优先复用 `organization:structure:manage`、`account:roles:read`、`account:roles:assign`。
- 任职新增如会增权，除 `organization:positions:assign` 外还检查角色分配能力及可授予权限上限。映射修改、任职增加、重新启用岗位／部门等所有可增权入口不能成为旁路。
- 只绑定本组织可分配角色；全局只读模板先复制为组织角色，不绑定外组织或全局模板。
- 供应商岗位授权继续服从既有门户权限白名单；本人摘要不向供应商开放组织目录、角色管理或他人资料。
- 角色“仍被使用”的删除检查包含岗位映射；管理员自锁保护、重置凭证、MFA 与记住登录策略均使用完整有效角色。
- 权限减少及安全要求变化使用既有安全版本／会话失效机制，旧会话不能继续使用已撤销能力；未完成 MFA 的会话不能使用新敏感授权。操作者自身受影响时，确认已提交结果后结束旧会话，不能引发重复写入。
- 配置、任职、安全版本和审计事务一致，失败回滚。变更预览可以提供，但不成为第二次审批或授权生效闸门。

### 3.2 最小数据方案（技术草案）

| 对象 | 方案 | 约束 |
| --- | --- | --- |
| User | `fullName`、`phone`、`profileVersion` | 可空资料，版本独立于头像／安全版本，不推测回填姓名 |
| PositionRole | organizationId／positionId／roleId | 唯一关联、同组织引用约束、必要查询索引 |
| 映射并发控制 | 独立映射版本或既有版本 CAS | 选最小完整方案，不覆盖并发岗位编辑 |
| UserPosition／UserRole | 复用 | 继承结果不复制为直接 UserRole，不为每人再建权限矩阵 |

优先动态解析有效来源，避免每人派生授权需要异步追赶；不新增重算 Worker 或定时任务。公共读取接缝须同时接受普通 Prisma 读取和已有事务客户端，防止跨模块循环依赖。

## 4. REQ-0022 资料与账号中心

### 4.1 字段维护

| 信息 | 本人 | 管理员与来源 |
| --- | --- | --- |
| 姓名、电话、邮箱 | 可维护 | 管理员依现有用户更新权限维护；CAS／幂等／事务审计 |
| 用户名、组织、类型／状态 | 只读 | 依现有独立治理权限，不由个人 PATCH 修改 |
| 部门、职务／岗位、任职时间 | 只读 | 规范化结构和任职关系，管理员维护，不新增自由文本 |
| 头像 | 原功能维护 | 原对象授权／扫描／版本／移除保持，不新增代传规则 |
| 角色／有效权限及来源 | 仅本人当前组织查看 | 管理员按组织范围查看；本人不获得编辑授权 |
| 签名状态、标签、创建／撤销时间 | 按现有签名权限 | 不返回原文／图像编码／秘密或伪造有效期 |

建议字段细则：姓名去首尾空白，填写时1～100字符；电话可空，最多40字符的国际号码／分机文本，不限定国内手机、不作为登录或唯一身份。邮箱沿用原规范及确认流程。姓名不是实名核验字段，签章主体绑定稳定 userId。旧资料空值显示“未填写”，不阻断原登录；批量建号模板不自动新增列。上述长度是实现前 DTO 建议值，不把它们当用户原始表格中的硬性业务规则。

供应商展示自身供应商组织及其中的有效岗位，未分配显示受控空态，不借用内部质量部门或允许本人自填组织职务。

### 4.2 界面

- 顶部一张概览：左侧身份摘要（头像、姓名／用户名、组织、任职），右侧账号／授权状态（邮箱确认、MFA、角色数量／来源及动作）。桌面拉伸对齐，统一内部节奏，不裁切固定高度。
- 姓名空值可显示用户名回退，但不写入姓名字段。长组织／多岗位／多角色摘要可展开，窄屏叠放，无整页横向溢出。
- “个人信息设置”集中基本资料、头像、任职只读信息和签名操作；主概览不常驻文件选择器或邮箱表单。
- 改密、安全弹窗和统一登录会话表复用。MFA秘密清理、忙时关闭保护、焦点恢复、原账号治理规则不变。
- 签名无权限明确不可用，不把403当无签名；单个摘要失败不阻断基本资料编辑。
- 409保留草稿，读取重试不重复写；关闭安全弹窗不使表单永久禁用，账号／组织切换和卸载后的迟到响应不能串号。

签名图片预览、图像存储和文档盖章不由现有指纹模块推断为已具备。若需要复现 QMS 1.0 图片签名，须在该部分实现前固定私有文件／扫描／下载／版本引用范围；不能用指纹冒充图片签名，也不据此承诺电子证书签章能力。

### 4.3 契约与历史

扩展 `/api/v1/me` 及管理员资料 DTO；本人任职／授权／签名摘要以完整会话 userId 为边界，不让普通用户调用管理员任意人员接口。直接角色集和有效角色集语义分开，避免把继承结果送进“替换直接角色”接口后存为永久授权。

既有签名接口含 fingerprint；本人摘要若要求网络响应不含指纹，应提供专用投影，不能仅在前端隐藏或随意删既有 DTO。没有 expiresAt，按 status／revokedAt 显示有效性。

Swagger 是契约来源，生成 contracts 后前端只用生成类型。资料审计记字段名及版本，不记电话、签名素材、凭据或资料原文；资料变化不回写历史审批、审计及签章。

## 5. REQ-0023 角色清单

- 表头单行，正文沿用上下4px单元格内边距，动作目标36／44px。不固定死所有数据行，避免裁切长名称和控件。
- 权限列“共 N 项权限”加最多两个模块名称，按权限码去重计数；目录未匹配回退受控名称／代码，不漏权限。
- 可访问按钮打开只读抽屉，支持名称／代码搜索及板块／模块分组。只列该角色实际权限，不以禁用全目录复选框充当详情；关闭恢复焦点。
- 保留全局只读、组织范围、读取权限、加载／错误／空态、中英、主题及窄屏表内滚动。组织切换、失权或角色删除清除旧详情，丢弃迟到响应。
- 复用已加载角色／目录，不新增 API、权限或数据库；创建／复制／修改／删除及矩阵 CAS 行为不变。
- 本人权限摘要可复用名称／分组逻辑，但数据范围独立：本人查看不能要求管理员读取权限，也不能据此开放他人角色接口。
