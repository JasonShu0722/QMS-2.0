当前处于需求评估阶段。已确认 8D 的适配方向及账号批量操作的业务口径，待开工。参考版本为已上线的 `V0.0.77`。

| 优化点 | 目标与验收 |
| --- | --- |

### 已确认的账号业务规则

- **批量建号与预览。** 主组织按组织代码精确识别，预览显示有权管理的组织名称。五列逐行校验。空缺、无法识别、组织与账号类型不匹配、越权或其他校验失败的行显示具体问题，确认时跳过。提交时服务端重验，条件变化导致不再符合要求的行也跳过并反馈。存在可创建行即可确认，全部不可创建时禁用确认。结果区分成功、跳过及创建失败，方便按行修正。
- **内部账号状态。** 建号成功后进入「待配置」，由有权人员批量追加任职，经现有配置规则取得对应业务权限。供应商账号沿用所属供应商企业的账号治理、权限和数据边界。
- **批量任职。** 保留所有已有任职，只追加尚未具备的选定岗位。已有岗位静默跳过，重复提交同一岗位仍按已有岗位处理。新增任职继续校验实际授予权限、组织范围和岗位有效性。
- **批量删除。** 沿用单账号的影响确认、近期身份校验、账号保护及审计。强制删除需由具备相应权限的操作者显式选择并确认，复用现有永久删除的处理规则。撤销目标账号凭证和有效任职，解除其当前配置引用。允许留空的当前关联留空，需补配的在途职责按现有待配置规则处理。保留历史业务单据、审批、签章、原操作者及审计记录。

## 8D 工作区整页重做（各板块共用，制程先落地）

当前通用问题工作区外壳套着 8D 办理页，两层分别显示标题、刷新、报告和追溯，挤占了正文空间。整体前端按 [Blendex 8D Workspace](https://8d.blendexlab.com/?lang=zh) 的页面布局和逐章办理交互适配：**一条页头、左侧章节导航、右侧只展示当前章节**。页头、操作区、章节表单与清单、证据、流程日志及网页报告预览共享组件和样式，不为各板块复制页面。问题输入区按板块提供对应的字段、来源摘要和明细；正文沿用共同的 8D 展示结构。本次第 7 张图是布局参考，第 8～10 张图是现状反例。沿用 QMS 主题、权限和办理规则；章节是填报导航，不是审批关卡，不照搬参考站的评分或流程。

### 章节与数据分工

- **问题输入与风险评估：** 放在 D1 之前，独立导航、同页两区。问题输入记录来源、初始现象、影响范围和数量；风险评估展示风险等级及判定依据，沿用 QMS 的风险等级和调整权限。D2 引用已有问题事实，补充调查确认的边界、描述和证据，不要求重复录入。
- **D1 团队建立：** 独立保留。带入单据负责人及责任科室，由有权人员维护成员、部门、职责分工和协作范围；更换负责人沿用现有转派。D3、D5 可复用团队成员作为责任人候选，不取代既有资格校验；团队分工随报告历史版本可回看。
- **D5 制定永久纠正措施／D6 实施与验证：** 独立导航、分别设计，共用同一措施记录。D5 记录对应根因、措施、选择依据、责任人、计划完成时间和验证标准；D6 引用 D5 已选措施，补实际实施人、验证人、完成时间、证据、改善前后数据和验证结论。验证未通过保留结论，回 D5 改方案，不另建重复措施；不新增审批节点。

| 反馈 | 调整方案 |
| --- | --- |
| 1. 操作散乱和重复 | 页头左侧集中返回、问题标题和唯一报告编号；右侧只留一处刷新和一个「流程日志」按钮。操作区突出当前节点能执行的主操作；「保存草稿」紧邻主操作，转派、调整风险、期限、来源等集中到「更多」，仅显示允许执行的动作。办理和受控报告预览各留一个入口，不再叠两层页签。 |
| 2. 编号重复、技术字段和 UUID | 报告编号在业务页头只显示一次，工作标签用可辨识的问题标题，不用短 UUID。页头摘要标出状态、风险、当前环节，人员及责任科室显示业务名称，未设置显示「未配置」，历史名称缺失明确提示，不用 UUID 兜底。流程编码、实例 ID、流程版本、内容与记录版本不在办理页展示。隐藏技术字段不等于解除版本锁定；已有的授权历史入口仍能按日期辨识和只读回看。 |
| 3. 附件和升级记录 | 去掉全局证据侧栏；证据就近归到来源事实、围堵行、原因分析、措施计划／验证或横展行。已有附件沿原业务归属呈现，不复制文件、不静默重挂；保留受控查看、下载和历史证据。升级不单独占卡片，已发生的业务升级并入流程日志。 |
| 4. 基础信息不逐条铺开 | 首屏用紧凑摘要呈现问题、责任科室、负责人和当前办理期限；问题输入区汇总来源条数、不良数量，以及工序、产线、发生时间等关键字段。来源相同时合并展示，存在差异时明确提示并可展开明细，不把首条值当成全单结论。追溯码、工单等留在授权明细，来源标识、来源版本、来源角色等技术字段不进入默认视图，空字段不占整行。 |
| 5. 节点事实、流程记录和轨迹 | 「流程节点事实」是节点状态和动作计数，不是日志；以页头「当前环节」替代常驻节点面板。「流程记录」就是已有的单据日志；「轨迹」另外混有延期历史和技术审计。共用工作区只保留一个「流程日志」浮窗，显示时间、人员、内容；制程先用现有记录核对发单、提交、审核、退回、派审／改派／跳过、延期和升级等实际业务动作，同一动作不重复展示。接入时移除独立「流程记录」「轨迹」「追溯」重复入口，不把原始审计事件整表搬入浮窗，不删除后台审计或历史数据。 |
| 6. 围堵、措施及横向展开 | **D3 围堵**按分组和位置一行一项，清单可直接比较数量、措施、责任人和完成情况，长说明与证据在对应行编辑。**D5 与 D6** 独立展示计划和实绩清单，通过同一措施关联；D6 的改善前后并排对照，证据归到对应条目。**D7 横向展开**用紧凑的文件更新／横展清单，先看是否更新、部门／主导者、计划和实际完成情况，详情与证据按行展开。表头说清字段，表格里不再重复「第 N 条＋字段名」；关键状态和操作不能被裁切。 |

**条目增删规则：** 围堵、措施、横向展开等可增减清单在可编辑状态下均支持逐条删除，预置建议行也能删。只有默认值、未录入业务信息且无附件的空行可直接移除；已填内容或已有附件的条目删除前提示「此条目已有内容，确定删除？」有附件时一并提示将从当前报告移除该条目的附件关联。取消保留全部内容，确认只从当前草稿移除该条，随报告保存生效；不删除已提交历史版本或其证据。待审锁定、关闭及历史只读视图不提供删除操作。

### 范围与验收

- 制程先作为共用工作区的首个落地和验收场景，客户、新品、供应商后续接入同一套组件；不把共用样式做成制程专用，也不因确定复用方向而默认所有板块同时切换。各板块按既有授权和节点提供当前状态、可用操作和已发生的日志，不强行统一后端审批。网页办理和网页报告预览使用相同内容布局；预览读受控版本，不把未保存草稿冒充已提交内容。授权 PDF 下载和既有版式保留。不改编号规则、审批分配、跳过逻辑、字段必填规则或存量数据。
- 页头和操作验收：从制程问题跟进、问题中心和我的待办进入同一单据，核对唯一编号、返回路径、操作权限；办理、待审、退回及关闭／历史只读都只保留适用操作。切章节不丢草稿，离开仍有未保存保护。
- 工作标签验收：返回综合工作台后，多页标签从顶栏左侧紧接工作台名称排布，当前页保持未激活。标签与「全部已打开」显示授权读取到的问题标题，空标题使用报告编号，加载和失去读取权限时使用通用「问题处理」。恢复旧会话时去掉占位标题中的短 UUID，重新打开问题后更新为业务名称。核对窄屏收纳和单页管理入口。
- 章节边栏验收：对照 Blendex 核对独立的问题输入与风险评估、D1、D5、D6 以及其余章节的顺序、整行高亮和右侧仅显示所选章节；桌面滚动正文后仍可切章，窄屏目录可展开且不挤压正文，网页预览采用同一章节导航而不显示编辑操作。
- 日志和名称验收：以实际单据核对分管失效改派、无人跳过、退回、延期与已有升级事件；浮窗只有时间、人员、内容，同一事件不重复，不能访问其他组织或无权单据。人员离职、部门改名或历史名称缺失时不露内部编码，不伪造操作者。
- 表单和证据验收：真实浏览器对照参考页，覆盖 H5／窄屏和桌面、多来源同值及不同值、多措施、多附件、长文本和空数据；实际操作新增、编辑、返回及保存重开，核对表头不重复、关键操作可达、证据归属正确、报告预览读取正确版本。视觉和业务验证分别记录，不以组件测试通过替代页面验收。
- 章节关联验收：问题输入的事实在 D2 不重填；D1 的团队分工可供下游引用，但不扩大权限；D6 关联 D5 的原措施，覆盖多措施、验证未通过、返回调整和历史版本回看，不生成重复措施或重复计数。
- 删除验收：空行及仅有默认值的预置行直接删；有内容或只有附件的行均先提示。取消后内容和附件不变，确认并保存后重开不恢复该行，其他条目和已提交历史版本不受影响；只读状态无删除入口。
- 复用验收：制程首版检查共用布局不依赖制程来源字段，凡修改已有共用组件，回归其他实际调用入口。每个板块接入时替换与领域相关的问题输入内容，不复制工作区或重新实现章节样式，并对照该板块现有授权、操作和历史读取行为。

## 账号与发单验收

- 分别复验组织职责与单据审核。发单覆盖已关联与不可见关联。单用户任职覆盖未预览、预览失效和受限账号。
- 建号覆盖五列模板、旧模板提示、内部与供应商账号混合、同批多个主组织、空缺或无效行、跨组织越权、组织与类型不匹配、重复用户名、预览后授权变化及部分成功。核对内部账号进入待配置、实际创建数与结果逐行一致、原始密码不回显。
- 用户批量操作覆盖新旧岗位混合、同一岗位重复提交、受限账号、逐账号结果及组织切换。删除覆盖确认取消、普通删除受限、显式强制删除、受保护账号拒绝、当前可空引用清除、在途待配置和历史业务记录保留。
