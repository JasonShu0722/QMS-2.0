# 制程不良品台账工厂区分设计

## 目标

在制程不良品台账的班次列前增加“工厂”列，并为制程不良入库接口增加工厂来源字段。系统支持一工厂、二工厂两种值；历史缺失数据、接口缺失数据和接口非法数据均不写入错误工厂，工厂字段按空值保存，页面统一显示 `/`。

本设计只覆盖制程不良品台账、制程不良手工登记和制程不良 API 入库，不扩展到其他质量台账、工厂主数据维护或组织权限模型。

## 已确认规则

### 工厂值

QMS 内部保存 `factoryCode`，取值为：

- `FACTORY_1`：一工厂
- `FACTORY_2`：二工厂
- `NULL`：未提供或未形成有效工厂值

外部接口值转换为：

- 数值 `1` 或字符串 `"1"` → `FACTORY_1`
- 数值 `2` 或字符串 `"2"` → `FACTORY_2`
- 缺失、空值、其他数值、其他字符串或不支持类型 → `NULL`

非法原始值不写入 `factoryCode`，也不保留在工厂字段中。

### 展示值

- `FACTORY_1` 显示“一工厂”。
- `FACTORY_2` 显示“二工厂”。
- `NULL` 显示 `/`。

台账列、详情抽屉、筛选结果和其他制程不良展示位置统一采用该口径，不再显示“未维护”。

### 手工登记

- 新建手工制程不良时，“工厂”为必填下拉框。
- 下拉框仅提供“一工厂”和“二工厂”。
- 历史手工记录的空工厂值保留为 `NULL`，显示 `/`。
- 编辑历史空工厂记录时，提交前必须补选工厂。
- 已有接口来源记录的工厂不通过普通手工表单覆盖，仍由接口来源和入库规则控制。

### 接口异常落库

工厂字段的异常属于字段级校验问题，不阻断其他字段合法的制程不良记录落库：

1. 工厂值转换失败时将 `factoryCode` 置为 `NULL`。
2. 记录保存 `factory:EMPTY` 或 `factory:INVALID` 入库问题，按现有待完善机制标记待完善。
3. 原始非法工厂值不写入业务字段。
4. 入库预览、单条试处理、历史批量导入和 Worker 正式入库使用同一转换逻辑。

这样可以避免因工厂字段问题丢失整条不良记录，同时避免错误工厂进入台账。

## 数据与 API 设计

### 数据模型

在 `process_defects` 增加可空字段 `factory_code`，类型和约束遵循现有制程不良字段风格。新增迁移只增加字段及必要索引，不修改历史迁移文件。

历史记录统一保持 `NULL`，不根据生产线、工序、组织或其他现有字段推断工厂。

### 入库规则配置

制程不良入库规则的来源字段白名单增加 `factoryCode`，管理端规则编辑器增加“工厂来源字段”输入项。

- 新建制程不良入库规则必须配置工厂来源字段。
- 已有已启用规则不自动改写，不因历史规则缺少该配置而批量失败。
- 编辑已有制程不良规则时，保存前必须补充工厂来源字段。
- 规则配置保存仍使用现有版本、权限、CSRF、幂等和审计机制。

规则只配置来源路径，不在规则中写死一工厂或二工厂。来源值的 `1/2` 转换由制程不良入库领域统一处理。

### 入库处理链路

来源报文 → 规则路径读取 → 工厂值归一化 → 制程不良字段组装 → 字段级问题收集 → 预览或写入 → 台账展示。

工厂归一化必须在预览和正式写入共用的规则评估层完成，不能只在 Worker 或前端补转换。工厂字段应纳入来源字段展示、差异比较、更新字段控制和审计变更字段。

外部记录唯一身份仍沿用现有 `receiptId + rowIndex` 或 `externalRecordKey`，工厂不加入去重键。来源工厂后续变化时，按现有规则的 `mode`、`updateFields`、人工确认和版本冲突处理。

### OpenAPI 契约

下列 DTO / 响应模型需要从 Nest Swagger 重新生成：

- `ProcessDefectDto` 增加可空 `factoryCode`。
- 手工创建和更新制程不良 DTO 增加工厂字段及必填规则。
- 制程不良查询筛选字段白名单增加 `factoryCode`。
- 入库规则映射和预览字段契约增加工厂来源字段及问题状态。

生成文件只能通过 `contracts:generate` 更新，不手工编辑生成的 `api.ts`。

## 前端设计

### 台账

默认列顺序调整为“发生时间、工厂、班次、项目号……”。工厂列支持列设置、表头快捷筛选和筛选面板枚举筛选，筛选仍走现有服务端查询模型和分页总数。

默认显示列包含工厂；用户隐藏列后仍可从筛选面板选择工厂筛选。窄屏继续沿用现有横向滚动和列设置机制。

### 手工登记和详情

手工登记表单增加必填下拉框，未选择时阻止提交并显示字段级提示。详情抽屉增加工厂项，空值显示 `/`。表单和详情不显示内部枚举值。

### 入库规则编辑器

制程不良目标显示“工厂来源字段”配置项。保存时校验来源字段非空；预览结果明确区分一工厂、二工厂、工厂为空以及工厂字段异常。异常结果不展示原始非法值为工厂名称。

## 权限、审计与兼容

- 复用现有制程不良读、写权限和 API 入库管理权限，不新增权限码。
- 有效 `platform:admin` 继续通过既有管理员投影访问台账和配置入口；普通未授权账号保持拒绝。
- 工厂来源变更纳入现有制程不良入库审计和记录版本。
- 历史接口规则不自动批量改写，避免无审计地改变生产报文映射。
- 旧数据和旧接口结果不因新增字段而丢失；空值统一以 `/` 展示。

## 验收范围

### API 与领域

- 手工新建缺少工厂时返回字段校验错误。
- 手工新建传入一工厂、二工厂后正确保存和返回。
- 接口值 `1`、`"1"`、`2`、`"2"` 正确转换。
- 接口缺失、空值和非法值时，记录仍可落库，`factoryCode` 为 `NULL`，记录带字段问题并进入待完善。
- 非法原始值不会进入 `factoryCode`、台账显示或筛选值。
- 工厂更新遵循现有模式、允许更新字段、人工确认、幂等和版本冲突规则。
- 组织范围、删除、归档、重复来源和审计行为保持不变。

### Web

- 台账工厂列位于班次列前，值显示正确，空值显示 `/`。
- 工厂表头筛选和筛选面板筛选使用同一服务端条件。
- 手工登记工厂为必填，详情和历史记录空值显示 `/`。
- 入库规则编辑器能配置工厂来源字段，预览能展示空值和字段异常状态。
- 中文、英文、加载、错误、权限、键盘焦点和窄屏状态正常。

### 工程门禁

- 新迁移通过真实 PostgreSQL。
- API 定向单元测试和真实 PostgreSQL 入库测试通过。
- Worker 入库、预览、历史批量处理测试通过。
- Web 台账、登记表单、筛选和入库规则编辑器测试通过。
- `contracts:generate`、`contracts:check`、`check:governance`、API/Web 构建通过。
- 按 QMS 基础设施规则补充真实浏览器证据；缺少真实资源时记录 `NOT_RUN`，不以 Mock 或 Skip 代替。

## 回滚与限制

数据库字段可回滚前必须先停用使用新工厂映射的入库规则，并处理已创建的相关任务；旧版本不支持 `factory_code` 时不得直接回滚到继续写入新字段的配置状态。

本设计不提供工厂主数据增删改、按工厂拆分组织权限、历史数据自动回填和其他台账同步。后续若工厂数量需要动态扩展，再单独设计工厂主数据及引用关系。
