## 4. 接收、配置与描述组合

### 4.1 接收与处理入口

- 沿用现有接口、机器鉴权和对象数组协议，整个数组逐条处理，不只识别第一条。
- HTTP200及开启回执时true仍表示技术收件成功，不表示全部业务落库成功；关闭回执保200空正文。
- 单条试处理只预览，确认后入队。历史范围一次提交、后台分段有序执行，不新增100份/10000行批次总量门槛；实际容量和正文可用性仍生效。
- 自动入库沿收件事务登记任务，同组织同接口按序、数组按原行序，复用暂停/恢复/取消/重试、未知结果恢复、输入保护及配置版本快照。

### 4.2 字段及板块配置

在目标选择中增加“制程不良品台账”，保原四主数据目标行为。映射发生时间、成品编码、工单号、生产线编码/名称、工序编码/名称、追溯码、来源明细编号及可选来源更新时间；不写死IMS字段名，不要求填QMS内部UUID。

组织内“工序名称→板块”按名称去首尾空白后精确匹配，同一有效工序名称只能对应一个板块，多个工序可以对应同一板块；不增加模糊匹配优先级或任意脚本。规则在现有管理配置内维护，管理员默认可达；自动补配只作用于本组织待补记录。

### 4.3 描述组合

配置有序来源字段、可选标签和分隔符（换行、空格或常用标点）。提取标量文本，跳过空值及空标签，保数字0和布尔false；试处理展示最终描述。对象/数组值、超长值不转成“[object Object]”或静默截断，记录字段问题、保原文并允许人工修正。只按纯文本展示，不执行HTML或表达式。2026-11-17追加批准[AI整理补充](2026-11-16-qms-process-defect-ai-description-supplement.md)，纳入REQ-0038 / V0.0.55同一PR；直接组合继续作为默认和失败保底。

## 5. 缺项入账与人工完善

- “待完善”表示事实字段缺失/无效，“待补配”表示关联缺失，两者可同时存在；不取代原“跟进中/已关闭”状态，不新增审批。
- 已通过接收协议、可定位到数组对象的数据，合法字段正常保存，缺失/无效事实保持空值，记录具体问题及来源定位，仍进入台账。不能填虚构时间/编码，不能只记系统失败而丢出台账。
- 不合规原值保留在受控接收正文，台账保存必要定位及问题，不复制整份敏感正文。未完成任务和必要输入沿原保护规则处理；列表不泄露正文。
- 班长/PQC等原现场维护角色逐条补全，保原权限；补充不改变“自动”来源，另记维护人、时间、版本及变化。
- 补时间自动重算班次，补成品编码尝试关联项目，补工序名称尝试关联板块；保存后重算缺项及待补提示。
- 未知发生时间仍可查，日期筛选/按发生时间统计不按接收日代算。记录条数与数量合计区分，保现有统计未知值语义，不开发质量目标指标引擎。
- 非对象正文、鉴权失败、超正文容量继续原样拒绝；缺项容错不等于取消信任边界校验。

## 6. 历史快照与自动补配

项目号/新品量产阶段保存同一次有效关联快照，记录成品编码、映射/项目ID与版本及关联时间；细分类型、板块各自记录结果及配置来源。一次只补仍缺项目组或字段，不因补细分类型重算已有阶段。

登记时有有效项目即保存当时结果；缺映射则待补，配置补齐自动尝试。延迟补配保存首次有效关联结果和补配时间，不能声称当前映射可还原缺失历史阶段。成品编码缺失不猜关联，先补码再尝试。

单条配置、导入、既有组件批量补配及项目变更都能影响待补对象；复用Worker有界扫描和持久化重试，不新增消息中间件，不在读列表时写快照。仅处理有效组织待补对象；补配与审计同事务，CAS避免与人工抢写，重复无变化不升版本/不重复审计。

已关联记录不因项目转量产、配置重命名/停用/删除、板块规则变化而回刷。单条维护显式纠正成品编码/工序名称时，可重算对应输入依赖，保旧值及审计；不开放人工批量改历史。归档保持原不可写边界，已关闭未归档保持原可补资料语义。

列表、详情、筛选、导出及既有新品遴选/8D来源投影使用已保存结果，不能一处显示历史新品、另一处实时映射为量产。既有发单快照、在途问题及人工纳入关系保留，不自动发单或关闭。

## 7. 身份、重复与更新策略

- 有来源编号：组织+受控来源系统+明细编号定位业务记录；编号保持字符串，不信任正文组织和身份声明。
- 无编号仍入账并提示身份未完善：来源接收记录+数组行号保证同一已收行重试不重复新增，但不保证跨重复推送去重。不同消息不按追溯码、工单或相同内容自动合并。
- 后补编号与另一台账冲突时保原记录并提示，不自动合并/删除。人工与IMS疑似重合沿原现场核对边界，不新增自动推断。
- 三策略（仅新增/更新指定字段/变化人工确认）沿用，只能更新本目标允许的来源事实。自动派生、关联快照、责任判定、分析进展、物料复核、关闭状态及发单关系不能通过通用映射写入。
- 缺失值不清空完整资料；人工补全/修正不被后台来源静默覆盖，有差异沿既有确认路径处理，明确采用才更新；旧来源和旧确认继续有水位及版本保护。
- 系统错误、权限失效、正常待完善/待补配分开显示，已入账待补不能显示为无结果失败。
