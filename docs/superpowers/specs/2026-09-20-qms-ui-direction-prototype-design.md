# QMS UI 方向样板

2026-09-21：用户认可第二版整体方向。后续前端工作统一遵循[前端设计规范 v1.0](2026-09-21-qms-frontend-design-standard.md)，代码与样式参考见[实施指南](../../../qms-2.0/docs/FRONTEND-DESIGN.md)。下文初版紫色方案仅保留为历史记录，当前默认浅蓝；样板不等同正式业务交付。

用户已同意先试做综合工作台、质量分析中心、8D 处理空间，以判断 Sneat 风格是否适合未来多应用 QMS，再决定是否采购完整版。

## 范围

本轮交付同一套视觉体系的三个可交互页面，不再比较三套模板。采用浅灰背景、白色面板、低饱和紫色强调、清晰中文层级和按任务调整的信息密度。仅借鉴视觉方向，代码自行实现，不复制商业素材。

- 综合工作台：个人任务优先级、质量指标与趋势、业务入口、动态和任务跳转。
- 质量分析中心：时间及来源筛选、趋势、缺陷帕累托、分布、风险明细与下钻。
- 8D 工作空间：问题概览、左侧节点进度、当前节点表单、证据、报告和追溯、专注模式。
- 顶栏持续标示演示数据。交互只修改内存；页面内明确反馈演示提交，不暗示真实业务完成。

## 技术与隔离

使用现有 React、Ant Design、lucide-react 和独立 CSS，SVG 呈现演示图表。独立 Vite HTML 入口 `apps/web/ui-prototype.html`，样板位于 `apps/web/src/prototypes/ui-direction/`，不接入正式 App 路由、不调用 API、不连接数据库、不修改现有主题或契约。Vite 默认生产构建仍使用原 `index.html`。

三个页面体现不同结构：工作台以任务和态势并置，分析页以图表和下钻为主，处理空间以节点、表单和证据并置。三个页面不是三套互相竞争的视觉方案。

## 验证与决策

执行 Web 类型检查、正式 Web 构建，并在浏览器检查三页切换、筛选、下钻、节点切换、草稿、演示提交、报告/追溯及窄屏布局。不把这些验证称为真实业务或平台验收。本轮不更改 FOUNDATION 历史结果。

用户体验后确认颜色、密度、导航和工作空间是否合适，再决定购买与正式实现。原型不直接晋升生产代码。

## 已确认的第二版调整

用户确认按原主设计 6.2、6.3 完善样板。默认浅蓝替代初版紫色，支持浅色、深色、跟随系统；品牌色独立提供蓝、青、紫。状态色保持稳定语义，图表分类色不随品牌主色随意变化。

导航采用工作台完整导航、业务域图标轨和上下文菜单；加入问题台账作为多记录入口。内部工作标签与问题内的工作区/报告/记录视图区分，标签条固定 36 px，根据可用宽度收纳，支持去重、关闭、查询已打开页面、轻量恢复及另开浏览器页签。专注模式收起两侧辅助区域，保留流程节点。

标签仅保存记录标识、标题、页面标识等元数据到会话存储；非活动页面卸载，只保留少量内存表单和视图状态。关闭未保存内容时确认，主题偏好单独保存在本地存储；存储不可用不阻断使用。正式业务与接口保持原状，离线单文件同步更新。
