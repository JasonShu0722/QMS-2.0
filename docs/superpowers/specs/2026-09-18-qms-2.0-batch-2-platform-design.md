# QMS 2.0 批次 2：问题与流程平台设计

- 日期：2026-09-18
- 状态：已获用户确认，待编制实施计划
- 适用范围：QMS 2.0 批次 2 的问题与流程平台
- 前置条件：批次 1 工程与安全底座已验收并合并到 `main`

## 1. 目标

批次 2 在批次 1 的认证、授权、审计、附件、Outbox 和应用外壳之上，建立所有业务域共同使用的问题与流程平台。完成后，平台可以在不引入任何具体业务域专业字段的情况下，完成问题编号、问题索引、受控流程、待办通知、台账查询、处理工作空间和报告追溯的真实闭环。

批次 2 是一个统一验收批次。实现内部按依赖顺序推进，但不把中间子阶段标记为正式产品批次。

## 2. 产品边界

### 2.1 本批次包含

- 编号规则版本和问题报告编号服务。
- 薄公共问题索引及其稳定的领域记录引用。
- 白名单流程节点、流程定义、不可变发布版本和流程运行实例。
- 功能权限、数据范围和流程节点权限的联合校验。
- 幂等键、乐观锁、事务回滚和并发冲突提示。
- 待办、通知、时限、升级和失败队列的通用平台能力。
- 问题中心、业务台账、个人视图和问题处理工作空间。
- 简报与 8D 的受控流程切换，切换时保持同一个问题报告编号。
- 报告预览、审计时间线、来源引用和流程追溯。
- OpenAPI 契约、真实 PostgreSQL 集成验证和 Playwright 主链路验证。

### 2.2 本批次不包含

- 供应商质量专业字段、供应商问题闭环或供应商门户。
- 制程质量、客户质量、新品质量和审核管理的专业字段。
- 通用问题创建表单；业务域必须通过领域服务接口创建问题事实。
- 完整 BPMN 语义、任意脚本、任意表达式执行或开放式流程引擎。
- 旧系统导入、QMS 1.0 兼容层、外部身份平台和长期预览环境。
- AI 自动决策、移动端和生产级外部集成。

在供应商质量批次开始前，使用只存在于测试代码中的中性领域适配器验证“领域创建—问题索引—流程处理”接口。该适配器不得添加供应商、制程、客户、新品或审核字段，也不得出现在生产导航中。

## 3. 核心设计

### 3.1 问题编号

编号服务在创建问题的同一数据库事务中分配唯一对外报告编号。编号规则按版本保存，规则版本包含稳定分类码、周期和流水号策略。编号创建后永久不可变，业务代码使用内部 UUID 关联记录，不解析编号字符串判断权限、状态或业务域。

简报升级为 8D 时保留原问题 UUID、报告编号、来源引用、附件和审计轨迹，只创建新的流程实例版本，并记录升级人、时间、原因和字段映射结果。升级失败时业务记录、索引、流程、审计和 Outbox 一起回滚。

### 3.2 薄公共问题索引

公共索引只保存跨模块聚合所需字段：内部 UUID、报告编号、业务域、问题类型、来源引用、严重度、当前状态、责任方、负责人、截止时间、流程实例引用、升级信息、关闭归档信息以及创建更新时间。

领域记录由领域模块拥有，索引保存稳定的领域类型和记录 UUID。问题中心通过公开领域服务或读取模型加载领域摘要，不直接读取领域内部表，不反向拥有专业字段。

### 3.3 受控流程

流程设计器使用 React Flow 作为编辑器，但只允许以下节点：处理、审批、验证、抄送、驳回、退回、重开和关闭。节点可以绑定角色、明确处理人规则、时限、提醒、升级和有限条件分支。条件表达式采用白名单字段与比较运算，不允许运行任意脚本。

流程定义按业务域、问题类型和回复形式绑定。发布时生成不可变版本，保存发布人、发布时间、变更说明和结构快照。运行实例固定引用创建时版本；新版本只影响新建问题。已发布版本不能修改，只能复制为新草稿。

### 3.4 权限和并发

每个流程动作同时校验功能权限、数据范围和当前节点流程权限。流程节点权限由服务端从会话、角色、组织范围和节点规则解析，客户端提交的组织 ID、处理人 ID 或角色不能扩大授权范围。

创建、节点提交、审批、驳回、重开、关闭和简报升级支持幂等键。可变领域记录、索引和流程实例使用版本号；版本不匹配返回 HTTP 409、稳定错误码和刷新提示，后提交者不能静默覆盖先提交者。

### 3.5 待办、通知和后台任务

领域事务提交时写入 Outbox 事件。Worker 消费事件生成待办、通知、超时和升级任务。事件处理最多重试 5 次，指数退避后进入可查询的失败队列，并支持授权用户人工重试。通知模板和业务文案属于平台事件类型，不在本批次绑定供应商或其他业务域字段。

### 3.6 工作空间和查询

问题中心只承担跨域检索、聚合、跟踪、升级预警和统计，不提供通用创建入口。业务台账提供精简表格、筛选、排序、字段显隐、保存视图和个人快捷视图。处理页默认进入问题概览，左侧显示流程节点和完成度，中间显示当前节点工作区，顶部提供工作区、报告预览和追溯记录视图。

报告预览读取问题索引、领域摘要、流程节点结果、审计事件和附件引用，生成可追溯的只读视图。报告不得把隔离状态附件作为可下载证据，也不得通过前端状态绕过权限。

## 4. 模块和接口边界

后端继续使用模块化单体，新增或扩展以下模块：

- `problem-index`：索引、编号、领域引用和聚合查询。
- `workflow`：定义、草稿、发布版本、实例、节点动作和版本校验。
- `task-notification`：待办、通知、时限、升级、失败任务和人工重试。
- `reporting`：报告预览、摘要读取和追溯查询。
- 现有 `audit-log`、`file-management`、`authorization` 和 `outbox`：通过公开服务接口参与事务，不被新模块直接读取内部表。

OpenAPI 是 API 唯一契约源。接口分为三类：

1. 管理接口：流程草稿、校验、发布、复制和失败任务重试。
2. 业务接口：由领域适配器创建或更新问题事实，并同步索引和流程实例。
3. 查询接口：问题中心、台账、个人视图、处理空间、报告和追溯。

所有写接口返回稳定错误码、字段错误和 trace ID；并发冲突、流程版本不匹配、无节点权限和重复幂等请求分别有可测试的响应语义。

## 5. 前端范围

内部应用壳保留批次 1 的身份分流和导航结构，新增可操作入口：

- 问题中心：跨域检索、筛选、状态和升级信息。
- 业务台账：基于授权范围的记录列表和保存视图。
- 流程管理：受控节点编辑、校验、草稿和版本发布。
- 我的待办：待处理、待审批、待验证、即将逾期和失败状态。
- 问题处理工作空间：概览、节点操作、报告预览和追溯。

前端只保存查询缓存和工作标签引用，不保存 Session ID、完整问题快照或大体积 DOM。表单提交显示幂等请求状态、字段校验、权限拒绝和 409 冲突恢复路径。

## 6. 数据一致性和安全要求

- 创建问题、分配编号、创建索引、创建流程实例、写审计和写 Outbox 在一个事务中提交。
- 节点动作、领域更新、索引状态、审计和 Outbox 在一个事务中提交。
- 失败任务人工重试不能重复生成待办或通知，必须使用事件幂等键。
- 报告和追溯查询沿用批次 1 的认证、CSRF、限流、功能权限和组织范围校验。
- 供应商隔离规则继续由服务端会话组织范围执行；本批次的中性测试适配器也必须提供允许和拒绝成对证据。
- 附件沿用隔离、扫描、逻辑删除和下载权限，不新增绕过路径。

## 7. 验证策略

### 7.1 后端与数据库

- 编号并发分配、规则版本、重复请求和事务回滚使用真实 PostgreSQL 集成测试。
- 索引与领域引用、流程版本冻结、节点权限、乐观锁和 409 使用 API 集成测试。
- Outbox 事件、待办通知、超时升级、失败队列和人工重试使用真实 Worker 测试。
- 审计事件必须包含操作者、组织、动作、资源、结果和 trace ID，敏感信息不得进入 metadata。

### 7.2 前端与主链路

- OpenAPI 生成类型和契约检查必须通过。
- Vitest 覆盖表格视图、工作标签、表单错误、冲突恢复和报告只读状态。
- Playwright 使用真实 API、真实 PostgreSQL 和会话 Cookie，完成中性领域创建、问题中心检索、流程处理、审批/验证、升级、报告追溯和失败重试。
- 每个组织范围场景同时验证允许访问和拒绝访问。

### 7.3 工程门禁

批次验收必须运行冻结依赖安装、迁移和种子、全量测试、构建、OpenAPI 检查、归档隔离、Compose 配置和必要的服务运行验证。验收脚本不得因缺失数据库、浏览器或配置而静默跳过；缺依赖必须明确失败并停止。

## 8. 完成门槛

批次 2 只有在以下条件全部满足后才算完成：

1. 领域适配器可以创建真实问题，公共索引可以聚合查询，业务代码不依赖编号字符串推断权限。
2. 流程设计、发布、实例运行、节点权限、版本冻结和简报升级 8D 可以完成真实操作。
3. 幂等、并发冲突、事务回滚、Outbox 重试和人工重试都有自动化证据。
4. 问题中心、台账、个人视图、处理工作空间、报告和追溯在浏览器中可操作。
5. OpenAPI、前端类型、数据库迁移、审计、附件权限和组织范围保持一致。
6. 完整验证命令通过，失败项、未运行项、环境依赖和限制写入批次交接文档。
7. 范围审查确认没有提前引入供应商质量专业字段、其他业务域模型、旧系统兼容层或完整 BPMN 实现。

## 9. 后续衔接

批次 2 验收后，批次 3 以供应商质量作为第一个真实业务域，使用本批次提供的领域接口、公共索引、流程运行时、待办通知、附件和审计能力。批次 3 不得修改公共索引去承载供应商专业字段；供应商字段和业务闭环仍由供应商质量模块拥有。其他业务域在供应商主链路验证通过后进入批次 4。
