## 1. 目标、依据与方案选择

目标是让相同业务意图使用稳定的控件、动作层级和反馈，减少负责人反复指出按钮、切换、留白与操作细节。覆盖对象是当前 Web、内部／供应商门户、受支持的移动场景，以及可识别的规划场景；未来新增模块通过同一矩阵补充，不能宣称穷尽尚未定义的业务。

权威层级沿用[统一前端规范](2026-09-21-qms-frontend-design-standard.md)、[前端实施指南](../../../qms-2.0/docs/FRONTEND-DESIGN.md)、[Web 规则](../../../qms-2.0/apps/web/AGENTS.md)。本文细化本专项的设计建议；与已确认的领域规则冲突时先修订本文，不以通用控件规范覆盖业务规则。能力事实依据[能力状态总账](../../../qms-2.0/docs/CAPABILITY-STATUS.md)及其对应领域设计和最新交接；其中旧段落不能替代后续关闭记录或现场核验。

方案比较：

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 沿用 Ant Design，补齐控件规则、可运行样例与共享组合，分批迁移 | 能覆盖日常操作细节，保留现有主题、权限与业务契约 | 本方案；先解决共性，再逐页消除差异 |
| 替换整套后台模板或组件体系 | 可快速获得一套演示页面 | 外壳、主题、路由、权限与草稿迁移面过大，不采用 |
| 仅继续逐页修补 | 单次差异较小 | 缺少可执行基线，同类问题继续分散，不作为主方案 |

继续使用 React 19、TypeScript、Vite、Ant Design、lucide-react、现有路由／语言／主题／请求。Ant Design 官方示例作为基础控件来源；ProComponents 和 Ant Design Pro 作为业务组合参考。引入任何包前单独核对已发布版本、peerDependencies、必要性及实际回归，不将上游模板整体导入。

## 2. 分层与覆盖定义

| 层 | 内容 | 产物及边界 |
| --- | --- | --- |
| L1 基础控件 | Button、Switch、Checkbox、Radio、Segmented、Tabs、Select、输入、日期、上传、提示 | 选型／尺寸／完整状态示例；优先配置现有组件，不另造通用控件库 |
| L2 业务组合 | 页面动作区、筛选栏、批量操作条、编辑表单、弹窗页脚、详情区、流程动作、文件区、图表区 | 真实重复后再抽共享组合；允许对象特有内容，禁止各模块自建主题 |
| L3 领域场景 | 第 6 节领域矩阵 | 当前代表页面、规划模式、业务责任和高风险边界 |
| L4 验证维度 | 状态、身份、主题、语言、设备、数据与并发 | 第 7～9 节可操作矩阵；分别记录静态、浏览器、真实服务和人工证据 |

“覆盖”分为：规则已有明确映射、样例可操作、正式页面已迁移、真实业务已验证四层，不能相互替代。没有对应业务的未来模式仅覆盖规则与可复用示例，能力标为“规划模式”或“扩展建议”。

## 3. 基础控件选型矩阵

| 意图 | 默认控件 | 使用规则／反例 |
| --- | --- | --- |
| 执行单次动作 | Button | 动词说明对象和结果；跳往地址用 Link，不能用有副作用的伪链接；提交表单使用正确的 submit 语义 |
| 立即改变二态设置 | Switch | 显示当前真值；异步保存有 loading、禁止并发，失败恢复已确认值并提示。已有领域明确“编辑后保存”的 Switch 不擅改保存时机 |
| 选择后统一提交 | Checkbox／Radio／表单字段 | Checkbox 表示可独立勾选项；Radio 表示互斥值；修改与实际生效分开反馈。不能把待提交值显示成服务器已生效 |
| 同一区域的少量视图／模式切换 | Segmented | 例如列表／卡片；选中项稳定可辨，切换不额外产生保存请求。与已确定的语言、主题持久化机制保持一致 |
| 单项业务值／多项业务值 | Radio.Group／Select／Checkbox.Group | 少量互斥值优先直观展示，候选较多时搜索选择；选择多个值不使用单选切换器 |
| 同一对象内内容分区 | Tabs | 用于有独立标题的内容面板；保留各区草稿和焦点规则，避免用 Segmented 假装无上下文的大页面导航 |
| 不同业务页面／对象工作页 | 现有导航／WorkTabs／Link | URL、深链接、权限与关闭保护沿用现有机制；不能靠本地选中颜色代替真实路由 |
| 多个低频动作 | Dropdown／菜单 | 主要动作外露；菜单提供键盘访问，危险项可识别；关键完成动作不因窄屏被完全隐藏 |
| 选择数量与连续数值 | InputNumber／Slider | 精确测量、规格和质量判定用有单位、精度与校验的数值输入；Slider 不替代精确录入 |
| 日期／期间 | DatePicker／RangePicker | 说明时区、含首尾边界、允许范围；筛选期间与到期日期不混用；空值不擅自填今天 |
| 选择关联对象 | 可搜索 Select／TreeSelect／受控选择弹窗 | 明确组织、对象类型、失效项与权限；无权候选不泄露，加载失败不等同于空候选 |
| 文件选择与上传 | 现有附件组件／Upload | 选择、传输、扫描、可用是不同状态；使用已批准接口及文件限制，不通过前端假清洁状态放行 |
| 提示与状态 | Typography、Tag、Alert、message、notification | 状态不能只靠颜色；持久错误与可恢复操作留在对象内，短消息不承担唯一结果证据 |
| 补充信息／解释禁用原因 | Tooltip／帮助文字 | 必须有可达的说明入口，不依赖悬停才能理解核心操作；禁用控件本身不可聚焦时提供邻近说明 |
| 轻确认／完整确认 | Popconfirm／Modal | 轻确认适合简单且上下文明确的动作；影响、选择或理由复杂时使用 Modal；不为所有安全动作添加机械确认 |
| 侧看详情／连续编辑 | Drawer／页面／Modal | 侧看详情保留列表上下文；复杂长流程使用页面；现有安全与改密弹窗保留已确认宿主和清理边界 |

控件选择不是按外形替换：`Switch`、`Radio`、`Segmented` 和 `Tabs` 的语义必须先判断，再决定视觉。当前已确认的业务规则与数据契约优先。

### 3.1 差异 / 兼容性轻提示（2026-10-24 补充确认）

负责人在客诉人员映射讨论中确认：人工指定与映射不一致等非阻断差异，采用字段 / 条目旁的小感叹号标识，鼠标移入浮出说明，并横展到同类映射、来源差异及兼容性说明。以下为共享设计要求，不代表样例或全站迁移已实现。

- 默认使用既有图标库中的感叹号图标（可带细圆圈）及 Ant Design Tooltip，邻近对应值呈现；不改成大块 Alert、常驻长句、闪烁动画或强制确认弹窗，不新增图标依赖或独立提示平台。
- Tooltip 用简短业务文字说明差异、当前采用值及是否需要处理。例如“当前质量工程师为人工指定，已保留；项目映射建议为……”。只展示当前用户有权读取的对象和人员，不通过提示泄露受限映射。
- 标识除鼠标悬停外须可由键盘聚焦查看，具备可读名称及焦点样式；触屏可点击查看 / 关闭，同样不阻断操作。视觉可小，实际命中区域不能压缩到无法操作；Esc 可关闭浮层，切换条目 / 组织后不残留上一条内容。
- 非阻断的映射缺失、人工值与自动建议差异、兼容 / 来源说明适用此模式；图标语义及颜色复用现有主题，不能仅靠颜色表达差异。已需显示“未检索到映射关系”的空字段仍保留其说明，不用只有一个图标代替全部缺失信息。
- 负责人随后确认批量录入展示具体数据问题后可选取消、继续或跳过错误行；选择继续录入的待补正条目也复用小感叹号 + 浮层，说明具体字段及问题，修正后重验并解除对应提示。已允许的空值不误标为错误，不以此模式隐藏文件无法解析、权限拒绝或保存失败，详细数据边界依领域规格。
- 真正的权限拒绝、保存失败、数据冲突、安全风险及提交阻断继续使用相应行内错误、Alert 或确认，不得因横展把关键错误藏进 Tooltip，也不把轻提示自动升级成审批、人员改派或数据修改动作。
- S07 列表 / 详情样例补充有 / 无差异、长中文、窄屏、深浅主题、键盘 / 触屏、差异消失及权限变化场景；样例确认后按实际同类调用点分批迁移，不宣称本次文档修改已完成全站横展。

## 4. 动作层级和组合规则

### 4.1 动作分类

| 类别 | 示例 | 默认呈现与结果 |
| --- | --- | --- |
| 当前主要完成动作 | 创建、保存、提交当前节点 | 一个独立操作区通常只有一个主要强调动作；独立面板可各有主操作，不能机械要求整页只剩一个 |
| 次要动作 | 取消、返回、刷新、下载模板、暂存 | 中性或文本样式，仍可见可达；暂存只有真实持久化能力才出现，成功说明保存到哪里 |
| 危险／撤回动作 | 删除、撤销授权、作废、解绑 | danger 语义及影响说明；区分可撤销与不可撤销、当前对象与多对象，遵循业务审批及验证要求 |
| 生命周期完成 | 验证通过、复核关闭、完成检测 | 依领域实际影响决定强调与确认，不因为动作叫“关闭”就一律使用 danger；关闭窗口与关闭业务对象必须区分 |
| 审查分支 | 通过、退回、驳回、要求补充 | 按业务语义区分，保持主次；退回并非一律等于删除；必要理由、签名及独立验证不能因样式统一而省略 |
| 对象内导航 | 查看详情、报告、追溯、附件定位 | 使用明确链接／导航，不冒充写入按钮；返回保留许可范围内的筛选与定位 |
| 批量动作 | 选中后导出、分派、启停 | 先显示数量和范围，再执行；跨页／全量选择必须有对应 API 支持与明确范围说明 |

动作文案使用可预测的动词，避免同屏多个无对象的“确定／操作”。删除、提交、发布、关闭、归档、撤销是不同业务动作，不因统一按钮而更改含义。

### 4.2 布局与交互

- 默认按本地既有阅读顺序组织动作；表单／弹窗提交区统一“取消／返回、次要、主要”，危险动作单独分组。保留已确认领域中可解释的例外，并在调用处说明原因。
- 采用统一高度、图标尺寸、图文间距、边框、圆角和焦点。普通业务控件沿现有 36 px 基线，触屏目标沿现有 44 px 要求；小表格动作不能通过无限缩小点击区域实现紧凑。
- 长中文／英文、数字数量、图标／无图标、加载图标均应对齐且不重叠；必要时换行或收纳次要动作，禁止让唯一提交入口消失。
- 不在每页覆盖 `.ant-btn` 等全局类；优先共享 ConfigProvider token、组件公开语义接口及限定作用域 CSS。原生按钮同样需要 hover、active、focus-visible、disabled 和选中反馈。
- 点击正在提交的动作不能重复发出同一写入；请求结束前的保护与现有幂等机制协作，前端禁用不能代替服务端校验。
- “取消编辑／停止尚未发送的批次／取消后台任务”分别命名。关闭弹窗或 AbortController 不意味着服务器已撤销写入；不支持取消的任务不显示假取消按钮。
- 不在成功回调前清空输入／文件／选择；超时或连接中断时写入结果可能未知，先提供查结果／安全重试路径，不能直接宣称失败或自动再次提交。

## 5. 业务组合模式

| 模式 | 必须表达的上下文与动作 | 关键状态 |
| --- | --- | --- |
| 页面标题与动作区 | 对象、当前阶段、主要动作、返回路径 | 无权限、长标题、多个独立任务、窄屏动作收纳 |
| 台账／筛选栏 | 筛选值、搜索／重置、结果数、更新时间 | 首次加载、查询中、空库、筛选无结果、失败、旧结果与新筛选不一致 |
| 批量操作条 | 已选数量、当前页／跨页范围、清除选择、可用动作 | 混合权限、已失效对象、部分成功、结果未知、筛选或组织变化后重验选择 |
| 表单／主从编辑 | 创建／编辑、必填、单位、校验、保存／取消 | 只读、脏数据、重复值、依赖字段、409 冲突、失败保留与秘密清理 |
| 弹窗／抽屉 | 操作对象、正文有界滚动、完整页脚 | 打开／关闭焦点、Esc／遮罩、请求中、未保存、窄屏、重新打开读取 |
| 只读详情／追溯 | 当前值、历史版本、来源、责任人与时间 | 当前身份与历史身份区分、无权限字段、已删除／失效关联 |
| 流程处理 | 当前节点、处理者、证据、允许动作及理由 | 无处理权、版本冲突、验证／关闭前置、并发处理、重复提交 |
| 导入／异步执行 | 模板、预检、行级问题、提交范围、结果清单 | 未发送／处理中／已成功／失败／跳过／停止后待处理，后台任务能力是否存在 |
| 导出／下载／打印 | 数据范围、字段、格式、权限与敏感级别 | 生成中、过期链接、部分失败、无数据、下载未发生不能报已下载 |
| 附件／证据区 | 归属对象、版本、文件信息、扫描、可用动作 | 上传失败、待扫描、拒绝／感染、失权、版本切换、删除确认 |
| 统计／图表 | 指标、单位、期间、来源、口径、更新时间与下钻 | 0／缺失／无效、样本不足、数据滞后、阈值来源、筛选与导出一致 |
| 通知／待办 | 来源对象、待办责任、时限、可跳转动作 | 已处理、失效、失权、未读／已读、任务状态与通知状态不同 |
| 扫码／移动执行 | 当前输入目标、连续录入、已读条码与结果 | 焦点丢失、重复扫描、网络失败、离线草稿、同步冲突、真实设备能力未知 |
| 配置／版本发布 | 草稿与生效版本、差异、校验、受控发布 | 未发布、发布失败、已被引用、不可逆变更、无效定义不允许假成功 |

## 6. 领域场景覆盖矩阵

| ID／领域 | 场景与需覆盖的交互 | 层次／来源 |
| --- | --- | --- |
| D01 身份与个人账号 | 登录、MFA 挑战、改密、邮箱确认、资料、签名、头像、会话撤销；秘密显示与关闭清理 | 现有领域：[账号](../../../qms-2.0/docs/ACCOUNT-ADMINISTRATION.md)、[安全](../../../qms-2.0/docs/SECURITY.md)、`features/auth`／`features/account` |

## 9. 验证及交付前复核

### 9.1 验证矩阵

- 全部基础控件和共享组合覆盖 default／hover／active／focus／disabled／loading／selected 等适用状态；不适用项写原因。
- 共享样例在浅／深 × 蓝／青／紫六主题及中英文中展示全部 S01～S08；跟随系统单独检查即时变化、持久化和存储失败降级。
- 按现有 1440×1000、1024×768、390×844 三档核对所有样例组布局。正式页面按控件组合和数据边界选择代表页，必须保留逐页盘点，不能用样例通过宣布全站迁移完成。
- 视觉截图固定浏览器／字体／视口／语言／主题／数据／动画与日期等输入，稳定后建立代表性基线；差异须由人查看原因，不能盲目更新快照让 CI 变绿。截图相同不证明权限、保存和交互正确。
- 键盘检查 Tab 顺序、Enter／Space、方向键、Esc、菜单、焦点可见与弹层恢复；控件动作不能只对鼠标可用。
- 触屏目标、减少动态效果、200% 缩放、长文本与滚动分别检查。鼠标、模拟触屏和真实手机／扫码枪是不同证据来源。
- 真实业务覆盖允许／拒绝角色、双门户、组织切换、实际读写、409／错误恢复、未保存保护、批量部分成功与文件扫描；只使用一次性验收资源，禁止连接保留库 55440。
- 沿当前主机负载与项目既有验证纪律，单个短定向测试开始，受影响组串行；既有无变化证据合理复用。不为“全面”重复执行无影响全套或并发启动重负载进程。

### 9.2 每批交付检查

在当前交付计划中逐项记录：页面／对象／角色、使用的 D／S／L2 模式、源码版本、主题／语言／尺寸、操作、预期、实际、截图或日志位置、执行者与时间、未覆盖项。源码或环境变更后重新评估受影响证据。

Codex 在提 PR 前主动完成：

1. 规格轴：控件语义、主次动作、状态、权限、数据和未保存边界正确；同类调用方是否都已纳入。
2. 质量轴：主题一致、对齐、密度、图文间距、长内容、焦点、错误／加载、窄屏和性能；实际查看截图，不能只运行类型检查。
3. 最小共享修复：同类问题优先在共同来源修一次，同时核对受影响调用方；真实例外留在局部并说明。
4. 报告：明确本地、CI、隔离浏览器、真实设备和负责人手工验收各自覆盖。不能把负责人“可以／继续”改写为页面审美验收通过。

浏览器受阻时遵循既有人工验收接续，不启动未授权的工具修复；提供版本、页面、角色、步骤、预期和反馈栏，独立可执行工作继续。无法取得视觉证据的页面保留待验收，不能自报全站通过。
