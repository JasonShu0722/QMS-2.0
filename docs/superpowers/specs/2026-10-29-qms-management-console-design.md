## 1. 目标与完成口径

建设完整、可使用、可授权、可观测的管理工作空间，不交付只有侧栏的空壳，也不重新实现一套 QMS。

完整交付包括：管理入口与独立外观、现有管理功能完整安置、既有流程设计迁入、组织直属岗位与兼容授权处置、真实管理概览、安全审计入口、运行服务与 API/数据交换观测、权限及跨窗口安全、真实环境验证和交付证据。

完整控制台不等于已经对接所有外部系统。外部系统的协议、测试端点、数据拥有者、脱敏样本、凭据配置和业务验收均是独立前置。没有接入时明确显示未接入，不以静态图表或演示事件冒充真实业务数据；已纳入交付的监控采集、查询、过滤、异常下钻必须真实工作。

## 3. 同一系统、两个工作空间

- 业务窗口保留当前对象、工作标签和未保存内容。管理窗口独立导航和组织目标，切管理组织不得隐式改变业务窗口上下文。
- 建议路由命名为 /console/*；仍由同源 QMS Web 和现有 API 提供，不新增账号库、权限引擎、独立登录或外部身份服务。
- 入口位于个人账号页；用户拥有至少一项真实管理能力才显示。控制台 context 不能仅复用旧平台管理页的用户/角色权限判断，否则流程专项人员可能被误挡。
- 打开动作由用户点击触发，请求独立浏览器窗口；浏览器可能按设置改成页签。阻止弹出时显示可主动点击的链接，不在原窗口自动替换业务页。
- 重复点击优先复用已有管理窗口，但不得为了复用而放松 opener 隔离、会话校验和失权清理。无法安全复用时允许新开，不牺牲安全。
- 不复制正文草稿或登录令牌到 URL、跨窗口消息或 localStorage。窗口通知只传失效/重验信号，不充当授权证据。
- 登出、账号切换、撤权和安全版本变化应使其他窗口重验；窗口恢复可见或焦点时重新确认会话和能力，敏感操作始终由服务端实时拒绝失效权限。网络失败不能显示为已验证或清除后静默继续写入。
- 不改变现有安全变更撤销会话的规则；撤销后两个窗口重新登录，不为了体验保留原本应失效的会话。

## 4. 信息架构与现有功能归属

| 一级区域 | 真实交付内容 | 边界 |
| --- | --- | --- |
| 管理首页 | 当前身份/管理范围、可处理管理事项、异常摘要、最近获授权审计、常用入口、数据采集时间 | 不复制质量业务大屏；不向无权人员泄露总量或对象名称 |
| 组织与授权 | 组织、部门、岗位、账号及任职、授权来源、供应商账号管理、待配置、兼容授权迁移/清理 | 平台/组织/供应商行政范围分别校验；不建立第二套角色系统 |
| 基础数据与配置 | 现有供应商、客户、物料、组件项目映射、平台规则配置 | 按原业务权限开放；保留必要业务端入口或深链接，不要求业务维护人员获得平台管理员身份 |
| 流程管理 | 现有流程列表、草稿、画布、版本校验发布、复制、业务绑定、职责预览和提醒配置 | 定义与配置迁入；待办、审批、单据进度、签章仍属业务端 |
| 安全与审计 | 现有管理审计、用户/岗位授权来源和可用的账号安全管理入口 | 个人 MFA/签名自主设置仍在个人账号；不显示秘密或授权管理员改写审计 |
| 集成与数据交换 | API 技术观测、获授权的数据交换来源目录、批次/记录状态及异常下钻 | 无连接器即未接入；不自动开启外部接收、补传或业务同步 |
| 运行与服务 | 现有失败队列、通知/扫描/PDF等实际任务状态、Worker执行回执、采集健康和错误 | 区分配置、最近观测和实时状态；不提供任意命令、SQL或任意URL探测 |

旧 AdminPage 中的用户、组织岗位、平台配置、管理审计、失败队列、待配置、问题责任恢复、供应商账号、三类基础数据及组件映射必须逐项映射。问题责任恢复是既有受控治理能力，迁入后不得变成管理员代审批。取消独立历史授权顶层页，以组织岗位内兼容处置和来源详情承接。

菜单来源于能力而非用户名或岗位名称；未知能力先拒绝。有流程管理权不隐含用户读取，有监控读取权不隐含重试、配置、原文导出或跨组织权限。平台管理来源也不自动赋予业务意见签署资格。

模块范围明确区分TARGET（已验证的管理目标）与SESSION_HOME（真实会话所属组织）。现有流程API/发布/绑定固定会话组织，本轮保持原权限语义；流程页明确展示该组织并锁定不适用的目标切换，不允许选B却请求A，也不将actor伪换为目标组织。跨组织流程治理不是入口迁移的隐含权限扩展。

无会话或需MFA/强制改密的深链接，使用仅限已知同源应用路径的returnTo贯穿登录链，保留合法定位query；登录完成后再由正式路由重新鉴权。外站、协议相对地址、非法编码和供应商跳内部控制台均拒绝，不保存token或业务正文。

## 5. 视觉与技术路线

参照 [shadcn-admin](https://github.com/satnaing/shadcn-admin/tree/e16c87f213a5ba5e45964e9b67c792105ec74d26)，核对源码提交 e16c87f213a5ba5e45964e9b67c792105ec74d26；本轮还查看了演示首页和用户列表，演示站版本不据此认定与固定提交相同。MIT 源码如实际复制，保留适用版权与许可；字体/图片等资源另核来源，不整体搬演示素材。

- 外观采用中性色、克制边框、深色主操作、分组侧栏、明确页头及筛选工具栏，浅色也能与业务端区分；深色/跟随系统继续支持。
- 保留 React、React Router、Ant Design、现有请求层、语言和安全机制。先以独立管理主题及样式适配现有功能，不引入 Clerk、TanStack Router、第二请求层或整仓依赖。
- 管理端样式不得泄漏到业务/供应商；不要同时加载两份不受控全局 reset。浮层、图表、流程画布、校验、焦点和危险操作一并适配，不能只有首页像参考。
- 控制台默认采用侧栏与面包屑，不复制业务端 WorkTabs。流程页仍保留会话隔离、未保存和未知提交保护，只替换导航接缝。
- 先制作管理首页、组织/用户、流程设计三类可点击样例，覆盖浅深色、375/1024/1440宽度、中文长文案、键盘和主要状态。先做内部视觉自检及独立审查，再正式迁入；负责人在PR-1集中确认样例与正式效果，不另设逐页审批或第三个常规停点，不当作业务验收。
- 若三类页面无法在稳定主题/组件接口内实现一致效果，先记录具体差距与替换范围，提交技术选型差异供负责人判断；不静默安装第二组件体系，也不以成本为由降低已确认视觉目标。

## 6. 组织直属与历史授权

严格沿用既有设计的 A→B→C：nullable部门的完整ORM/SQL有效性链；受控来源迁移/清理；正式组织岗位页面。

必须保留 QMS_ADMIN 的平台marker、MFA、稳定角色资格和最后一条有效平台管理来源；存续账号不得走永久删除清因子。预览绑定精确来源、版本、受影响人员和扩散影响；锁后重验、同事务替代/解除/归档/撤会话/审计。不重写已发布roleCode、审批和签章。ORGANIZATION_GOVERNOR按初始化来源显式处置，不按显示名批量删除。

本项目代码迁移只改变模型和受控能力，不自动执行生产岗位/角色数据转换。生产转换仍按指定批次预览、人工确认和单行分阶段CLI另核授权。

## 7. API 与数据交换监控

### 7.1 两类事实，不混淆成功

技术面按受控路由模板统计请求量、状态类别、延迟分布及采集时间；不得把带UUID、搜索词、凭据的原始URL或正文直接作为指标标签。默认按分钟聚合保留7天，不保存请求/响应原文；索引、分页、时间范围和基数有界。

业务面区分发出/接收、校验、业务处理和对账；一个HTTP 200不代表全部记录落地。记录来源、方向、对象类型、组织、关联ID、批次/记录ID、幂等键摘要、数量、状态、错误分类及时间；不记录秘密或无限制原文。默认保留30天的非业务审计观测元数据，正式审计/签章保留策略不变。

### 7.2 本轮必须真实工作的链路

- 新建服务端受控观测接口和持久化查询；来自现有API实际请求及已注册真实调用方，不向浏览器开放任意事件伪造接口。
- 对现有通知、扫描、PDF/Worker及失败队列，仅通过事实拥有者公开读接口整合；不能把这些队列统称为外部业务交换。
- 提供受权限约束的概览、时间/组织/来源筛选、分页、错误与追踪下钻、采集失效提示和保留清理机制。
- 以一次性环境的真实HTTP调用、失败响应及真实Worker验证观测链；没有供应商资料时可以验证技术采集，不能记为IMS/MES等业务联调完成。
- 外部交换来源通过内部注册端口接入观测。初始无批准连接器时返回空目录并显示未接入；不为了填图表偷偷建立同步任务、机器账号或万能Webhook。
- 观察结果不赋予重放能力；现有失败队列的受控重试沿原权限/幂等。外部业务补传必须在对应连接器明确幂等、版本冲突、权限和审计后才出现可执行按钮。

### 7.3 可靠性与安全

采集必须有界，不为每个请求启动无限异步写入；采集失败不把已成功的业务动作改写成失败，需显式暴露采集缺口/丢弃/过期，不允许假装零错误。监控端点自身避免递归记录，清理任务有批量与执行上限。只读监控与配置/处置分权，不因新增权限而批量授予存量账号。新增DTO走Swagger生成契约；真实组织/来源授权在查询前完成。

观测采用外层HTTP完成钩子覆盖守卫前401/403及404，不能只用Nest interceptor。可信路由模板/组织归属由成功验证的安全上下文补充；未可信归属的失败计入有界UNKNOWN/UNSCOPED平台桶，不读取未授权query/body推断组织，不向组织读取者泄露。未知路由不以原始URL建高基数标签。

## 8. 管理首页与运行真实性

首页先显示当前范围和需要处理的事项，再放异常与趋势。统计来自拥有者公开查询；原API没有计数时新增受控聚合，不遍历浏览器分页凑总数。各卡片分别显示采集时间、空态/失败/未接入；部分来源失败不隐藏，也不标为全系统健康。

Worker显示最近执行回执和已知任务结果；没有持续采集就不显示实时在线。对象存储、邮件、扫描等区分配置存在、最近检查结果和实际业务回执，不从配置项存在推断可用。不新增Codex heartbeat、定时接单或代理驻留任务。
