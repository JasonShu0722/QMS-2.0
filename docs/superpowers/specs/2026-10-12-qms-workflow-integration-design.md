# QMS 工作流、Skill 与治理文档整合设计

## 1. 已确认目标与范围

2026-10-12 负责人批准按本次讨论的文件清单开始调整：需求提出人通过现有表单提交业务资料；OpenClaw 结合云端项目源码和文档只读分析，填写方案要点、子任务清单、验收标准、变更类型、涉及端；Codex 评审批准范围后开发。负责人同意计划顶部维护当前摘要，并允许按确认规则主动分配版本。

本轮仅维护 Markdown、AGENTS、三个现有 Skill 及文档索引，免 Issue / PR。不修改应用、脚本、契约、数据库、CI、部署和飞书表结构，不执行云端接入或业务回填。最新仓库基线为已推送的 `V0.0.5` / `58f462408acd81e62c99a622c9334cbb597e4753`；本轮分配 `V0.0.6`，分配不代表提交或发布完成。

## 2. 权威职责

| 资产 | 唯一维护的内容 |
| --- | --- |
| 根 / 工程 AGENTS | 活动位置、安全与契约约束、强制入口和关键检查点 |
| 交付流程 | 参与者、授权、版本分配、阶段接续、关闭和回填 |
| 开发治理 | 当前摘要格式、证据矩阵、门禁、独立审查和工程完成条件 |
| 工程工具 | 运行环境、共享 Git 状态、浏览器接续及证据保存 |
| OpenClaw 协作说明 | 只读分析输入、五字段输出、字段责任和机器人边界 |
| 现有 Skill | 任务识别、所需输入、流程调用和阶段交付结果 |
| 设计 / 计划 | 单次批准范围、映射、版本、证据和历史 |
| 文档索引 | 主题权威关系、来源依赖与实际复核 |

根规则不可由下层削弱；重复的关键提醒允许保留，细则引用上述权威来源。

## 3. 完整链路与共享资料

提出人提交 → OpenClaw 只读分析并填写初稿 → 负责人批准 → Codex 核对源码与独立评审 → 主动建 Issue → 实现、两阶段审查和适用验证 → 主动提 PR → 获准合并发布 → 最终版本验收 → 获准关闭和逐行回填。

OpenClaw 保留原始需求，不改变批准状态，不在批准后覆盖方案初稿；新增发现提供调整建议。Codex 保留批准范围快照，安全同范围优化可直接实施并记录，业务范围变化交负责人决定。

只读源码资料注明来源、路径、版本或指纹、读取时间及与部署版本的关系。允许使用批准的只读副本或读取通道，不因此授权 SSH、生产命令或秘密读取；本轮不声明现有接入已经完成。来源与部署关系未知时只生成带限制的分析，不把它当作当前线上事实。

共享定位使用 REQ、实际 record_id、Issue / PR、批准范围、源码 / 部署 SHA、证据来源和下一动作。现有字段保存摘要及链接，不新增工具层、Skill 或通用插件平台。

## 4. 当前摘要与版本

现有计划顶部维护最后核对时间、批准与授权范围、交付映射、当前检查点、分别状态、版本与证据、阻塞和下一动作。摘要用于找到证据，不替代回读和当前源码验证。阶段历史保留并标注日期，已结束任务不因旧未勾选项重复开发。

独立调整默认在当前主 / 次版本下递增修订号；同范围纠错沿用原版本并取最大已用 / 预留 `fixN` 加一。负责人指定优先，主 / 次版本变更另行决定。主代理核对远端、本地、开放 Issue / PR 和计划预留后统一登记；无法核实或冲突时仅暂停提交检查点，不重复询问已获准本地开发。

## 5. 验证与完成条件

- 旧规则基线和新规则十场景推演，由独立上下文执行，记录真实缺口与结果，不称业务测试。
- 三个 Skill 通过既有 `quick_validate.py`；文档 / 来源一致性、治理工具测试、归档隔离和差异检查通过。
- 独立规格与质量审查确认新约定落地、授权未扩大、历史证据未伪造、路由与权威依赖完整。
- 原始报告和日志留在 Git 外；本轮记录具体结果、未验证的云端接入和 Git 同步状态。

实施步骤与实际结果见[整合计划](../plans/2026-10-12-qms-workflow-integration.md)。本设计解释本轮决策，长期规则由上述权威文件维护。
