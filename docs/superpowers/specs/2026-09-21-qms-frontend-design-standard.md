# QMS 2.0 前端统一设计规范

版本：1.4 · 2026-10-31。适用于 QMS 2.0 新增页面、已有页面改版、内部业务应用和供应商门户的公共视觉与交互。REQ-0033补充文案、标题和内部折叠菜单，实施状态见[本轮计划](../plans/2026-10-31-qms-ui-content-navigation-preparation.md)，规范变化不代表实现或验收已经完成。紧凑密度按 REQ-0021 人工反馈进一步减半，账号整合与实际验证见[返修计划](../plans/2026-10-19-qms-account-overview-density.md)，此前交付历史见[原计划](../plans/2026-10-18-qms-compact-account-master-audit.md)。

## 1. 依据、效力与交付状态

本规范沉淀用户认可的 UI V2 方向，是后续前端开发和评审的默认要求。信息架构依据[主设计第 6 章](2026-09-18-qms-2.0-redesign-design.md)，视觉及交互参考[UI 方向样板](2026-09-20-qms-ui-direction-prototype-design.md)。代码位置和验证命令见[前端实施指南](../../../qms-2.0/docs/FRONTEND-DESIGN.md)。

- **必须**表示交付验收条件；**建议**表示默认选择，可基于具体页面说明调整原因。
- 主设计与业务规格决定领域、流程、权限和数据语义；本规范决定公共 UI 行为与视觉基线；参考代码用于解释设计。样板与规范冲突时，不以样板缺陷覆盖规范。
- 2026-09-21 已完成现有正式页面的首轮视觉迁移，共享主题、导航与工作标签已接入；实际验证及交互边界见实施指南。本文件还包括未来质量应用要求，不得整体当作已交付能力清单。
- 新业务页面必须按本规范设计；已有页面随所属改造批次迁移，不能为追求一次性统一而破坏已有业务和安全边界。
- 不以购买商业 UI 套件作为前提。现有样板自行实现；引入商业源码或素材需单独确认来源、适用授权和技术适配，不把设计参考视为素材授权。

## 2. 产品表达与页面层次

QMS 是可扩展的质量应用平台，覆盖问题改进、供应商质量、检验、审核、知识及质量分析。公共外壳和组件统一，各领域保留自身表单和流程。

- 页面首先回答“当前对象是什么、处于什么状态、下一步做什么”。工作台优先展示待办、逾期风险、关键指标和常用入口。
- 页面保留清楚的可访问名称、必要的对象/分区标题、主操作和内容区域；导航已显示页面名时，不再叠加同名正文大标题和无价值概览标题栏。同一操作区域只突出一个主要动作，其他动作使用次级按钮或更多菜单。
- 工作台优先利用首屏展示有效任务与信息，按下述量化间距组织分区；台账保证可扫描的信息密度；分析页强调比较与下钻；处理页把空间留给问题事实、节点内容和证据。
- 使用低饱和背景、轻边框、克制阴影。禁止用大面积装饰渐变、过多卡片或图标代替业务层次。
- 正式产品文案使用业务语言，复用项目语言机制；不向业务用户展示技术栈、接口字段名或内部异常堆栈。

### 2.1 界面文案与标题纪律（REQ-0033）

- 可见文字必须帮助理解数据、判断状态、执行操作或处理异常。删除欢迎词、营销口号、泛化功能介绍、重复标题的副标题、布局/模块设计意图和实现原理；不为填空新增说明、指标或卡片。
- 保留字段歧义、单位、统计时间/范围、真实零与缺失/失败/无权限差异，以及权限、风险、不可逆确认、错误和恢复指引；不按组件名、字数或全局正则机械删副标题。
- 非关键长帮助按上下文进入Tooltip、详情或文档；关键风险直接可见。当前身份、数据范围和来源限制可压缩或进入可发现详情，不删除事实。
- REQ-0033-fix1人工反馈澄清：保留业务含义不等于保留一段常驻说明。页面/弹窗/抽屉的默认状态不解释“不自动发单、不代审批、服务端授权为准、固定会话来源、内部投影”等实现边界；字段约束就近表达，权限/冲突/未知结果仅在当前状态提示，不可逆风险在对象动作和确认点呈现。删除无任务价值的解释，不把原段落整体搬入details当成完成。
- 文案审查必须递归覆盖正式入口可达的子面板、详情、表单、弹窗、抽屉、导入器、空态、选项及占位文字；逐个说明候选记录处理依据。不能只检查route页头或保持旧文案断言，再以测试通过声明“全面完成”。
- 删除文案须同时移除空标题栏、多余容器和占位，收拢间距与对齐；不得压缩字体、触控目标或遮挡内容来追求密度。
- 业务页保留侧栏和工作标签，正文不重复页面名；对象名、编号、编辑上下文和有效分区保留。隐藏可见重复标题时保留语义、页面定位与焦点，不全局CSS隐藏所有h1。
- 管理首页保留一处紧凑页头并与组织选择/主要操作同行，省略重复首页面包屑和路径小字；深层页面保留有返回价值的路径和对象标题。窄屏允许页头自然换行。

## 3. 公共外壳与导航

| 场景 | 必须遵循的行为 | V2 尺寸基线 |
| --- | --- | --- |
| 综合工作台与业务域 | 单列两级折叠菜单，领域图标/名称/箭头可见，页面缩进；父项只展开/收起，原默认业务页保留为子入口 | 展开240 px |
| 路由与展开 | 真实URL决定叶选中，标签/深链/刷新展开当前祖先；多个领域可以同时展开，记忆限当前会话 | 不增第三层业务菜单 |
| 收起菜单 | 保留图标轨与明确展开入口，领域按钮恢复菜单并展开对应领域，不意外跳业务页 | 图标轨64 px |
| 顶栏 | 单行承载工作标签、标签清单及全局操作；右上角唯一“外观”入口，保留可发现的页面名称 | 最小高54 px，窄屏不换行 |
| 专注处理 | 收起领域导航及右侧辅助上下文，保留节点导航、正文和退出专注入口 | 正文使用释放的宽度 |
| 窄屏 | 导航通过按钮展开为覆盖层，可关闭；正文不被永久侧栏挤压 | 760 px 及以下启用窄屏导航 |

图标轨必须提供可访问名称和可发现的文字提示。顶部外观入口不再与侧栏重复。导航由角色和业务权限决定，隐藏入口不能代替后端权限检查。供应商门户沿用主题、组件与反馈规则，但只展示供应商可访问的任务与对象，不照搬内部完整应用导航。

分类展开态、当前页选中态与悬停态必须区分。管理侧栏分类使用字重、对比、组间距与对齐建立层级；图标按业务对象或动作选取，齿轮用于配置，不因缺映射一律回退齿轮。复用lucide-react并统一线条与尺寸，相近业务可以共享图标。

上述单列方案替代2026-09-21的业务图标轨加上下文双栏，供应商门户导航不随之改造；管理控制台仍使用独立分组与能力过滤。尺寸调整在共享布局核对，不逐模块另建外壳。业务六种品牌/显示组合与管理控制台现行中性色、独立偏好各自保持；本次不新增主题或统一偏好键。

## 4. 内部工作标签与状态边界

- 点击台账记录直接打开完整处理页；默认创建内部工作标签。同一记录按业务域和稳定记录标识去重，重复点击激活已有页，不以标题作为身份。
- 工作台不计入业务工作页。工作标签与清单入口整合进共享顶栏：0 个工作页显示门户标识；1 个工作页保留管理/关闭入口；多个工作页显示 **36 px 高、单行、不换行**标签条，不额外占正文上方一行。
- 根据容器可用宽度保留当前及最近使用标签，其余进入可搜索的“全部已打开”面板；不能仅用固定标签数量判断溢出。
- 单工作页也要保留管理/关闭入口。关闭当前页后激活最近的剩余页；关闭最后一页回工作台。关闭未激活页不改变当前业务上下文。
- 必须支持另开浏览器页签，深链接能定位同一对象。另开页面不复制未保存正文；权限失效或对象不存在时给出明确反馈，不默默打开另一条记录。
- 只挂载活动页；非活动页不长期保留完整 DOM、附件内容或大体积数据。可保存少量有界草稿、节点选择和滚动等必要状态；关闭页时清理其临时状态。
- 会话恢复仅保留必要标签元数据。正式实现要按用户/组织隔离，在退出、切换身份或权限变化时清理或重验，不能直接沿用样板的固定存储键。
- 关闭有未保存修改的页面，必须提供“继续编辑”和“放弃修改并关闭”；保存失败不能清除未保存标记。切换标签、路由离开、刷新/关闭浏览器的保护应保持一致，刷新保护能力以浏览器实际行为为准。
- 内部工作标签与对象内“工作区 / 报告预览 / 追溯记录”是两层不同导航；更深的内容使用分区与锚点，避免继续嵌套标签。

正式草稿持久化能力由业务方案决定。样板的内存“暂存”不代表服务端保存，也不代表刷新后可恢复。

## 5. 主题、色彩与样式变量

默认 **浅色 + 晴空蓝**。显示模式提供浅色、深色、跟随系统；品牌主色独立提供蓝、青、紫。两者组合形成浅蓝、浅青、浅紫、深蓝、深青、深紫六种实际配色；“跟随系统”按系统偏好选用浅色或深色配色，不新增第三套色值。切换品牌色不得改变显示模式，切换模式不得重置品牌色。

| 语义变量 | 浅色蓝主题 | 深色蓝主题 | 用途 |
| --- | --- | --- | --- |
| `--accent` | `#277cc4` | `#65b0f0` | 主动作、选中态、链接 |
| `--accent-soft` | `#e6f2fd` | `#203c56` | 选中/提示背景 |
| `--accent-border` | `#b9d8f2` | `#355d7c` | 强调边框 |
| `--background` | `#f3f6fa` | `#111b27` | 页面背景 |
| `--surface` | `#ffffff` | `#1a2838` | 面板、浮层 |
| `--surface-tint` | `#f7f9fc` | `#203044` | 次级区域 |
| `--border` | `#e1e7ef` | `#33465d` | 分隔线与边框 |
| `--text` | `#293b50` | `#e2eaf3` | 正文 |
| `--muted` | `#64758a` | `#a7b8cb` | 次要说明 |
| `--success` | `#208569` | `#74d1ad` | 完成与成功 |
| `--warning` | `#ac7126` | `#f0ba72` | 风险提醒与临近到期 |

青色主色为浅色 `#12847f` / 深色 `#4bc4b8`；紫色为浅色 `#7960c5` / 深色 `#b19af0`。其余衍生背景色以样板 `shell.css` 为初始参考。

正式实现使用 `--qms-` 前缀，单一色值来源为 `apps/web/src/theme/tokens.ts`。浅蓝的普通字号主按钮使用 `--qms-accent-action: #2375bb` 与白字配对，保留 `#277cc4` 为品牌强调色；前者对比度约 4.85:1，避免原强调蓝与白字约 4.41:1 的不足。深色主按钮使用浅主色配深色文字。此调整只深化动作色，不改变已确认的浅蓝方向。

- 色值必须集中为语义变量/主题配置。组件消费变量；模块样式中不反复硬编码品牌蓝、白色背景或黑色正文。
- Ant Design 的 `ConfigProvider`、自定义 CSS 和 SVG/图表必须读取同一份解析后的主题。正式迁移时集中定义品牌色，避免样板中 TS 与 CSS 分别维护色值的重复方式继续扩散。
- 成功、警告、错误/危险、处理中、未开始保持固定业务语义，可随深浅主题调整亮度；不能随主色换成另一种业务含义。错误/危险使用统一主题的 error token，并辅以文字或图标；不得因样板尚未覆盖而遗漏。
- 图表系列颜色独立于品牌色；同一类别在不同页面、筛选和刷新后保持一致。深色时调整可读性，不改变类别映射。
- 主题偏好可保存在本地；存储异常须退回默认而不阻断页面。跟随系统须响应系统模式变化；弹窗、抽屉、下拉、表格、图表与打印/导出分别验证，不能仅改变页面底色。
- 表内色值是已确认的视觉基线，并非所有前景/背景组合的可访问性认证。正式复用时核对对比度，尤其是深色强调按钮的文字；不直接复制样板的全局白字覆盖。

## 6. 字体、间距、密度与响应式

- 使用系统中文友好字体：`"Segoe UI", "Microsoft YaHei", sans-serif`，不依赖远程字体；数字列表使用等宽数字特性以便比较。
- 正文/表单建议 14 px，表格 13–14 px，辅助说明至少 12 px；分区标题 16–18 px，页面标题 24–28 px。样板的 8–11 px 装饰或辅助文字不作为正式字号要求。
- 正文页面边距由共享外壳唯一提供，按下述密度值统一管理；业务页不得重复叠加 24/28 px 外边距。独立登录页和画布等特殊宿主可明确说明例外。
- 普通业务页面内边距 8 px（1200 px 以下为 6 px）、区块间距 6 px、卡片正文内边距 8 px、表格单元格上下内边距 4 px；这是内边距而非固定行高，长文本、错误和操作控件可自然撑高。普通空态内边距不超过 12 px，不用大块装饰留白填充页面。
- 展示类卡片采用按用途的公共密度：快捷入口、概览／看板／趋势／分析、统计数值与通知摘要正文内边距16 px、内部区块间距12 px，入口标题与说明间隔8 px；嵌套领域／分析摘要内边距12 px。尺寸依据压缩前V0.0.20卡片实值。使用共享 display 变量与 qms-display-card 标记，同时覆盖自定义容器和 Ant Design Card；窄屏保留内边距及自然换行。筛选／台账／编辑表单／安全卡片沿用8 px紧凑基线，不按 Card 或 overview 名称自动扩大。展示卡片外的页面／区块／标题间距、表格与控件尺寸不受此例外影响。
- 统一消费共享密度变量及 Ant Design Card/Table 组件 token；不全局压缩 Ant Design 基础 spacing 来间接缩小控件。台账、表单、处理页与弹窗按同一基线，例外必须说明业务或可访问性原因。
- 标准控件高 36 px、圆角 7 px；面板圆角以 8–10 px 为主，1 px 轻边框。触屏高频操作应保留约 44 px 点击区域。
- 正式业务外壳顶栏最小高 54 px，压缩控件上下留白；窄屏仍保留 44 px 操作目标。相邻 Typography 标题、显式 Space／Row 间隔和 Table 分页也须遵守共享区块间距，避免组件默认值恢复大块留白。
- 卡片栅格随容器宽度减少列数。复杂表格可在自身容器横向滚动，整页不得因固定宽度溢出。图表、表单和流程节点应有窄屏布局。
- 动效用于反馈，建议 150–200 ms；尊重减少动态效果的系统偏好，不使用持续装饰动画影响工作。

## 7. 统一业务页面模式

| 模式 | 内容结构 | 关键要求 |
| --- | --- | --- |
| 综合工作台 | 个人优先任务、风险/到期、指标与趋势、常用入口 | 指标可解释，任务可直接进入处理上下文；避免纯模块入口墙 |
| 业务台账 | 标题与主操作、筛选/保存视图、结果数、表格、分页 | 默认展示有权访问的业务总台账；个人待办是快捷视图。编号/标题可进入详情，行内少量操作，长文本省略可查看完整值 |
| 问题工作空间 | 概览、节点进度、宽幅正文、证据/上下文、报告与追溯 | 默认进入问题概览；节点来自受控流程定义，不固定为 D0–D8；动作和审批反馈留在当前对象内 |
| 分析中心 | 统计范围、指标、趋势/分布/帕累托等、明细下钻 | 筛选范围贯穿指标与图表；下钻继承范围并可返回；数据权限贯穿统计与明细 |
| 配置/管理 | 对象列表或分组、编辑区、变更摘要、保存/重置 | 明确只读、可修改和不可授予状态；保存冲突保留草稿，不覆盖他人修改 |

台账字段和保存视图能力遵循主设计 6.4：编号、标题、来源、严重度、状态、责任方、负责人、截止与更新时间；按台账保存列显隐、顺序、宽度、固定列、筛选、排序和视图类型。未交付的保存视图能力不能由前端假按钮冒充。

表单使用明确标签、必填提示、字段校验和必要帮助；不能仅用 placeholder 充当标签。提交中防止重复操作，失败保留输入并提供可恢复路径。危险操作明确说明影响范围，业务保存成功必须以接口结果为准。

每个数据区域必须区分：加载中、无数据、筛选无结果、加载失败、无权限。错误提供重试或可行的下一步；无权限不得显示真实敏感详情；展示 traceId 时只使用安全诊断信息。成功、失败和状态变化不能仅依赖颜色或短暂提示。

### 7.1 基础控件与动作基准（2026-10-21）

负责人已初步认可独立交互样例，第一批正式迁移依[实施计划](../plans/2026-10-21-qms-interaction-foundation.md)逐项验证；以下为统一规则，不代表全站已经迁移或验收。

- Button 执行即时动作，Link 表示真实导航；同一独立操作区通常突出一个主要完成动作，取消／返回保持次要，低频动作可进入菜单。危险操作按实际影响使用 danger，不因动作叫“关闭”就将正常业务完成或关闭弹窗标成危险。
- Switch 表达即时二态设置；Checkbox／Radio 可表达保存后才生效的选择，必须区分草稿和当前值。Tabs 用于内容分区，Segmented 用于少量视图／模式切换；已有语义正确的语言 Radio 不为外形机械替换。
- 共享按钮沿用36 px高度和7 px圆角，横向内边距14 px、字重500，普通／主要／危险按钮去除非必要阴影；色值、危险语义和禁用／loading使用共享主题。图标按钮、链接和特定密度有既有合理边界时按其组件规格保留，不全局硬覆盖尺寸。
- 显示模式与品牌主色为两个独立互斥组，选项标识、checked、键盘方向键和焦点清楚；不能只换 ARIA 名称而缺少行为。主题及语言切换继续沿用当前存储、系统监听和失败降级，不新增偏好来源。
- 弹窗操作区使用限定的共享布局，取消／次要在前、主要完成动作在后，右对齐、8 px间距、必要时换行；触屏目标宽高至少44 px。资料、头像和签名分别保存的页面不增加误导性的“保存全部”。
- busy、dirty、失败／冲突恢复、重新认证、秘密清理和焦点恢复先于样式统一；不得为了复用页脚省略现有保护。正式组件不得导入样例代码，已共享的主题配置从样例局部配置移除，保持一个来源。
- 迁移按控件／调用方清单与主题、语言、尺寸和状态矩阵验证；真实账户、门户和权限操作按对应业务前置验收，不以静态或合成样例代替。样例方向确认、单元测试、真实浏览器几何和负责人业务验收分别记录。

### 7.2 全页面展开的恢复与提交边界（2026-10-21）

本节将[全页展开计划](../plans/2026-10-21-qms-all-pages-interaction.md)实际发现的共性归入统一规则；实现与证据仍逐文件记录，不用规则文本声明运行通过。

- **内容导航和动作分离。** 对象内概览／报告／追溯用有选中态、关联面板和键盘行为的Tabs；只有选中内容需要挂载时按需读取，离开应中止对应读取，不把旧请求结果带到新对象。列表／卡片等呈现模式使用Segmented；Link保留真实地址和另开能力。
- **保存当前修改，提交明确版本。** 编辑区的当前输入与已保存记录不一致时，不能直接提交旧版本而无提示。保存成功以API返回为准，失败保留输入；发布说明等只有发布接口持久化的字段不能在保存其他字段后假装已保存。
- **每个离开路径同等保护。** 取消、关闭图标、遮罩、Esc、刷新、换记录／筛选／组织、导航和工作页关闭都按实际dirty／busy处理。dirty登记必须在成功保存／确认放弃时清理；busy是独立状态，不能伪装成dirty。无修改但请求在途的页面同样保护刷新；拒绝或失败后不能永久锁住页面。
- **已确认的离开必须完成。** 共享guard确认后应关闭／切换目标，不能只清除dirty却仍留原窗；清理内容和新对象读取要有明确次序。不因未保存保护阻断一个不丢输入的只读操作，也不把不同子表单混成一个无法清理的总草稿。
- **重复提交与冻结输入。** 同一写入在途期间使用同步锁阻止重复onFinish／回车，相关输入禁用，避免显示的新输入与提交的旧值不一致。锁在成功、失败和校验返回路径完整释放，失败保留可重试值；不能仅靠loading图标代替防重复。
- **批量与离线部分成功。** 只重试失败／未处理行，已成功行从剩余草稿移除且不会被后续失败重新写回；同一重试不能重置并发锁或重生成原幂等内容。停止循环不回滚已成功行，关闭／重新打开能力按真实持久化范围说明。
- **刷新保留恢复上下文。** 导入台账后台刷新不能卸载仍有未完成行的导入器；只有明确失权时清理。每行成功后同步显示其返回结果与版本，再移除本地草稿。409保留编辑对象与输入，更新版本或放弃后刷新由用户明确选择；新建成功后的自动切换也走旧对象草稿保护。
- **危险确认点名对象。** 删除角色等不可逆动作，确认前不发送写请求；确认列出目标，取消不改变数据。正常验证完成、业务关闭、退出弹层不是同一危险语义，保留领域职责分离与服务端资格。
- **局部滚动和路由边界。** Grid／Flex宿主使用可收缩轨道和必要的子项min-width，宽表只在自身区域滚动；不能用body隐藏溢出掩盖操作不可达。相近路由名按完整路径段匹配，不因前缀相同同时挂载两个业务页面。
- **真实零、缺失和单位。** null／undefined／空文本不是0，缺单位要明确说明，0值保留；不借格式化函数新增统计算法、默认单位、公差或判定。中英文状态与提醒使用同一个语言来源，业务编码／原始记录不擅自翻译。

独立样例的S01删除确认、S02 Tabs／Segmented、S04 dirty／busy／冲突、S05保存版本与处理资格、S06部分重试和S08零／缺失解释这些模式；它们只演示本地状态，不代替真实审批、签名、扫描、离线同步或领域验收。

## 8. 质量图表规范

- 图表类型服务于分析问题：时间趋势用折线，类别比较用条形，缺陷优先级用帕累托；控制图、过程能力等需具备明确业务算法与有效数据条件后再交付。
- 明确指标名称、单位、统计时间窗、过滤范围、更新时间；比率注明分母口径，对比注明基期。缺失数据不能显示成 0，演示值不能混入真实统计。
- 坐标轴、图例、提示内容和系列映射统一；不同量纲不误用同一坐标轴。阈值、目标线、控制限标明含义与来源，不把通用趋势示例称为 SPC。
- 可交互图表必须提供明确的下钻/筛选反馈，并为键盘和非视觉访问提供摘要或等价表格。
- 主题切换不改变数据与统计结论。导出应携带范围与口径，并遵守既有权限及数据导出边界。
- SVG 样板用于视觉参考；生产图表实现及依赖按业务需求单独选型，不因购买后台模板而默认获得质量统计能力。

## 9. 可访问性与复用边界

- 必须支持键盘操作和可见焦点；图标按钮有可访问名称。对话框打开后合理管理焦点，关闭后回到触发处；导航和主内容使用语义结构。
- 验收目标：常规正文对比度至少 4.5:1，大字号文字及必要非文本控件至少 3:1；状态同时使用文字、图标或形状表达。上述数值为本项目验收要求，本轮未宣称已测量通过。
- 默认复用 Ant Design 的表单、表格、弹窗、抽屉及反馈交互；自定义组件承担 QMS 特有的导航、工作标签、节点和证据上下文。
- 禁止正式页面导入 `src/prototypes/`，禁止整份引入样板 `prototype.css` / `shell.css` 的全局重置；先抽取共享主题与公共组件，再迁移业务页。
- 业务模块不得自建第二套主题管理、外壳或通用按钮/表单库；不要为套用 DashboardKit / Gradient Able 引入并行 Bootstrap 样式体系。
- 允许因业务需要扩展模式；扩展应在本规范和实施指南记录适用场景、复用边界与验证，避免逐页复制分叉。
- 已登录账号的安全设置使用当前页面内的紧凑卡片弹窗，MFA 状态、验证器/恢复码与邮箱确认分别分区；关闭返回触发入口，保留原业务路由及后台草稿。MFA 开关统一由管理员在账号管理设置，包括管理员本人；个人安全弹窗不提供开关或解绑。登录挑战保留独立认证页，两种宿主复用同一安全内容与 API。
- 安全弹窗仅在打开时挂载内容，重新打开读取当前状态；写请求期间阻止关闭，未完成绑定或尚在显示恢复码时提示确认。关闭卸载清除表单与一次性秘密，不持久缓存。弹窗正文有界滚动并适配窄屏、键盘与主题。
- 个人账号以一张概览卡整合身份、邮箱编辑和安全摘要；登录会话只保留一份历史分页表，以状态和当前标识区分，只有有效且非当前会话显示撤销动作。表体有界纵向滚动，窄屏横向滚动局限在表格内，表头可见、分页位于滚动体外。刷新清单不覆盖资料草稿。

## 10. 变更与验收

每个前端交付在所属阶段计划中列出使用的页面模式、共享组件、偏离基线的原因和检查范围。改变主信息架构或权限边界须先更新对应设计；常规视觉修正按现有授权推进，不增加重复确认流程。

评审必须检查：导航与标签、主题组合、信息密度、五类数据状态、表单恢复、权限显示、键盘/焦点、窄屏、图表口径。执行方法及正式接入顺序见[前端实施指南](../../../qms-2.0/docs/FRONTEND-DESIGN.md)。记录实际 PASS/FAIL 和未验证项，不以静态截图替代关键交互验收。
