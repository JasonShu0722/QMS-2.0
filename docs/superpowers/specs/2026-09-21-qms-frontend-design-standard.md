# QMS 2.0 前端统一设计规范

版本：1.0 · 2026-09-21。适用于 QMS 2.0 新增页面、已有页面改版、内部业务应用和供应商门户的公共视觉与交互。

## 1. 依据、效力与交付状态

本规范沉淀用户认可的 UI V2 方向，是后续前端开发和评审的默认要求。信息架构依据[主设计第 6 章](2026-09-18-qms-2.0-redesign-design.md)，视觉及交互参考[UI 方向样板](2026-09-20-qms-ui-direction-prototype-design.md)。代码位置和验证命令见[前端实施指南](../../../qms-2.0/docs/FRONTEND-DESIGN.md)。

- **必须**表示交付验收条件；**建议**表示默认选择，可基于具体页面说明调整原因。
- 主设计与业务规格决定领域、流程、权限和数据语义；本规范决定公共 UI 行为与视觉基线；参考代码用于解释设计。样板与规范冲突时，不以样板缺陷覆盖规范。
- 2026-09-21 已完成现有正式页面的首轮视觉迁移，共享主题、导航与工作标签已接入；实际验证及交互边界见实施指南。本文件还包括未来质量应用要求，不得整体当作已交付能力清单。
- 新业务页面必须按本规范设计；已有页面随所属改造批次迁移，不能为追求一次性统一而破坏已有业务和安全边界。
- 不以购买商业 UI 套件作为前提。现有样板自行实现；引入商业源码或素材需单独确认来源、适用授权和技术适配，不把设计参考视为素材授权。

## 2. 产品表达与页面层次

QMS 是可扩展的质量应用平台，覆盖问题改进、供应商质量、检验、审核、知识及质量分析。公共外壳和组件统一，各领域保留自身表单和流程。

- 页面首先回答“当前对象是什么、处于什么状态、下一步做什么”。工作台优先展示待办、逾期风险、关键指标和常用入口。
- 每页使用清晰的标题、必要说明、主操作和内容区域；同一操作区域只突出一个主要动作，其他动作使用次级按钮或更多菜单。
- 工作台适度留白；台账保证可扫描的信息密度；分析页强调比较与下钻；处理页把空间留给问题事实、节点内容和证据。
- 使用低饱和背景、轻边框、克制阴影。禁止用大面积装饰渐变、过多卡片或图标代替业务层次。
- 正式产品文案使用业务语言，复用项目语言机制；不向业务用户展示技术栈、接口字段名或内部异常堆栈。

## 3. 公共外壳与导航

| 场景 | 必须遵循的行为 | V2 尺寸基线 |
| --- | --- | --- |
| 综合工作台 | 完整业务导航，显示图标与名称；返回工作台恢复完整导航 | 导航宽 236 px |
| 进入业务域 | 主导航收为图标轨，旁边展开领域上下文菜单；选中态与当前路由一致 | 图标轨 64 px，菜单 208 px |
| 收起菜单 | 保留图标轨与明确的展开入口 | 图标轨 64 px |
| 顶栏 | 工作位置、全局操作；右上角保留唯一“外观”入口 | 桌面高 72 px |
| 专注处理 | 收起领域导航及右侧辅助上下文，保留节点导航、正文和退出专注入口 | 正文使用释放的宽度 |
| 窄屏 | 导航通过按钮展开为覆盖层，可关闭；正文不被永久侧栏挤压 | 760 px 及以下启用窄屏导航 |

图标轨必须提供可访问名称和可发现的文字提示。顶部外观入口不再与侧栏重复。导航由角色和业务权限决定，隐藏入口不能代替后端权限检查。供应商门户沿用主题、组件与反馈规则，但只展示供应商可访问的任务与对象，不照搬内部完整应用导航。

尺寸为统一初始基线；在 1200 px 及以下可将业务菜单收窄为 184 px。因内容或可访问性需要调整时，应在共享布局层修改并验证受影响页面，不由每个模块另建外壳。

## 4. 内部工作标签与状态边界

- 点击台账记录直接打开完整处理页；默认创建内部工作标签。同一记录按业务域和稳定记录标识去重，重复点击激活已有页，不以标题作为身份。
- 工作台不计入业务工作页。仅 0 或 1 个工作页时隐藏额外标签栏；多个工作页时显示 **36 px 高、单行、不换行**标签条。
- 根据容器可用宽度保留当前及最近使用标签，其余进入可搜索的“全部已打开”面板；不能仅用固定标签数量判断溢出。
- 单工作页也要保留管理/关闭入口。关闭当前页后激活最近的剩余页；关闭最后一页回工作台。关闭未激活页不改变当前业务上下文。
- 必须支持另开浏览器页签，深链接能定位同一对象。另开页面不复制未保存正文；权限失效或对象不存在时给出明确反馈，不默默打开另一条记录。
- 只挂载活动页；非活动页不长期保留完整 DOM、附件内容或大体积数据。可保存少量有界草稿、节点选择和滚动等必要状态；关闭页时清理其临时状态。
- 会话恢复仅保留必要标签元数据。正式实现要按用户/组织隔离，在退出、切换身份或权限变化时清理或重验，不能直接沿用样板的固定存储键。
- 关闭有未保存修改的页面，必须提供“继续编辑”和“放弃修改并关闭”；保存失败不能清除未保存标记。切换标签、路由离开、刷新/关闭浏览器的保护应保持一致，刷新保护能力以浏览器实际行为为准。
- 内部工作标签与对象内“工作区 / 报告预览 / 追溯记录”是两层不同导航；更深的内容使用分区与锚点，避免继续嵌套标签。

正式草稿持久化能力由业务方案决定。样板的内存“暂存”不代表服务端保存，也不代表刷新后可恢复。

## 5. 主题、色彩与样式变量

默认 **浅色 + 晴空蓝**。显示模式提供浅色、深色、跟随系统；品牌主色独立提供蓝、青、紫。切换品牌色不得改变显示模式，切换模式不得重置品牌色。

| 语义变量 | 浅色蓝主题 | 深色蓝主题 | 用途 |
| --- | --- | --- | --- |
| `--accent` | `#277cc4` | `#65b0f0` | 主动作、选中态、链接 |
| `--accent-soft` | `#e6f2fd` | `#203c56` | 选中/提示背景 |
| `--accent-border` | `#b9d8f2` | `#355d7c` | 强调边框 |
| `--background` | `#f3f6fa` | `#111b27` | 页面背景 |
| `--surface` | `#ffffff` | `#1a2838` | 面板、浮层 |
| `--surface-tint` | `#f7f9fc` | `#203044` | 次级区域 |
| `--border` | `#e1e7ef` | `#33465d` | 分隔线与边框 |
| `--text` | `#293b50` | `#e2eaf3` | 正文 |
| `--muted` | `#64758a` | `#a7b8cb` | 次要说明 |
| `--success` | `#208569` | `#74d1ad` | 完成与成功 |
| `--warning` | `#ac7126` | `#f0ba72` | 风险提醒与临近到期 |

青色主色为浅色 `#12847f` / 深色 `#4bc4b8`；紫色为浅色 `#7960c5` / 深色 `#b19af0`。其余衍生背景色以样板 `shell.css` 为初始参考。

正式实现使用 `--qms-` 前缀，单一色值来源为 `apps/web/src/theme/tokens.ts`。浅蓝的普通字号主按钮使用 `--qms-accent-action: #2375bb` 与白字配对，保留 `#277cc4` 为品牌强调色；前者对比度约 4.85:1，避免原强调蓝与白字约 4.41:1 的不足。深色主按钮使用浅主色配深色文字。此调整只深化动作色，不改变已确认的浅蓝方向。

- 色值必须集中为语义变量/主题配置。组件消费变量；模块样式中不反复硬编码品牌蓝、白色背景或黑色正文。
- Ant Design 的 `ConfigProvider`、自定义 CSS 和 SVG/图表必须读取同一份解析后的主题。正式迁移时集中定义品牌色，避免样板中 TS 与 CSS 分别维护色值的重复方式继续扩散。
- 成功、警告、错误/危险、处理中、未开始保持固定业务语义，可随深浅主题调整亮度；不能随主色换成另一种业务含义。错误/危险使用统一主题的 error token，并辅以文字或图标；不得因样板尚未覆盖而遗漏。
- 图表系列颜色独立于品牌色；同一类别在不同页面、筛选和刷新后保持一致。深色时调整可读性，不改变类别映射。
- 主题偏好可保存在本地；存储异常须退回默认而不阻断页面。跟随系统须响应系统模式变化；弹窗、抽屉、下拉、表格、图表与打印/导出分别验证，不能仅改变页面底色。
- 表内色值是已确认的视觉基线，并非所有前景/背景组合的可访问性认证。正式复用时核对对比度，尤其是深色强调按钮的文字；不直接复制样板的全局白字覆盖。

## 6. 字体、间距、密度与响应式

- 使用系统中文友好字体：`"Segoe UI", "Microsoft YaHei", sans-serif`，不依赖远程字体；数字列表使用等宽数字特性以便比较。
- 正文/表单建议 14 px，表格 13–14 px，辅助说明至少 12 px；分区标题 16–18 px，页面标题 24–28 px。样板的 8–11 px 装饰或辅助文字不作为正式字号要求。
- 以 4 px 为间距步长，常用 8/12/16/24/32 px；桌面页面左右留白 28 px，收窄后 20 px，手机 16 px。表单与密集台账可使用明确的紧凑模式，不能任意压缩可点击区域。
- 标准控件高 36 px、圆角 7 px；面板圆角以 8–10 px 为主，1 px 轻边框。触屏高频操作应保留约 44 px 点击区域。
- 卡片栅格随容器宽度减少列数。复杂表格可在自身容器横向滚动，整页不得因固定宽度溢出。图表、表单和流程节点应有窄屏布局。
- 动效用于反馈，建议 150–200 ms；尊重减少动态效果的系统偏好，不使用持续装饰动画影响工作。

## 7. 统一业务页面模式

| 模式 | 内容结构 | 关键要求 |
| --- | --- | --- |
| 综合工作台 | 个人优先任务、风险/到期、指标与趋势、常用入口 | 指标可解释，任务可直接进入处理上下文；避免纯模块入口墙 |
| 业务台账 | 标题与主操作、筛选/保存视图、结果数、表格、分页 | 默认展示有权访问的业务总台账；个人待办是快捷视图。编号/标题可进入详情，行内少量操作，长文本省略可查看完整值 |
| 问题工作空间 | 概览、节点进度、宽幅正文、证据/上下文、报告与追溯 | 默认进入问题概览；节点来自受控流程定义，不固定为 D0–D8；动作和审批反馈留在当前对象内 |
| 分析中心 | 统计范围、指标、趋势/分布/帕累托等、明细下钻 | 筛选范围贯穿指标与图表；下钻继承范围并可返回；数据权限贯穿统计与明细 |
| 配置/管理 | 对象列表或分组、编辑区、变更摘要、保存/重置 | 明确只读、可修改和不可授予状态；保存冲突保留草稿，不覆盖他人修改 |

台账字段和保存视图能力遵循主设计 6.4：编号、标题、来源、严重度、状态、责任方、负责人、截止与更新时间；按台账保存列显隐、顺序、宽度、固定列、筛选、排序和视图类型。未交付的保存视图能力不能由前端假按钮冒充。

表单使用明确标签、必填提示、字段校验和必要帮助；不能仅用 placeholder 充当标签。提交中防止重复操作，失败保留输入并提供可恢复路径。危险操作明确说明影响范围，业务保存成功必须以接口结果为准。

每个数据区域必须区分：加载中、无数据、筛选无结果、加载失败、无权限。错误提供重试或可行的下一步；无权限不得显示真实敏感详情；展示 traceId 时只使用安全诊断信息。成功、失败和状态变化不能仅依赖颜色或短暂提示。

## 8. 质量图表规范

- 图表类型服务于分析问题：时间趋势用折线，类别比较用条形，缺陷优先级用帕累托；控制图、过程能力等需具备明确业务算法与有效数据条件后再交付。
- 明确指标名称、单位、统计时间窗、过滤范围、更新时间；比率注明分母口径，对比注明基期。缺失数据不能显示成 0，演示值不能混入真实统计。
- 坐标轴、图例、提示内容和系列映射统一；不同量纲不误用同一坐标轴。阈值、目标线、控制限标明含义与来源，不把通用趋势示例称为 SPC。
- 可交互图表必须提供明确的下钻/筛选反馈，并为键盘和非视觉访问提供摘要或等价表格。
- 主题切换不改变数据与统计结论。导出应携带范围与口径，并遵守既有权限及数据导出边界。
- SVG 样板用于视觉参考；生产图表实现及依赖按业务需求单独选型，不因购买后台模板而默认获得质量统计能力。

## 9. 可访问性与复用边界

- 必须支持键盘操作和可见焦点；图标按钮有可访问名称。对话框打开后合理管理焦点，关闭后回到触发处；导航和主内容使用语义结构。
- 验收目标：常规正文对比度至少 4.5:1，大字号文字及必要非文本控件至少 3:1；状态同时使用文字、图标或形状表达。上述数值为本项目验收要求，本轮未宣称已测量通过。
- 默认复用 Ant Design 的表单、表格、弹窗、抽屉及反馈交互；自定义组件承担 QMS 特有的导航、工作标签、节点和证据上下文。
- 禁止正式页面导入 `src/prototypes/`，禁止整份引入样板 `prototype.css` / `shell.css` 的全局重置；先抽取共享主题与公共组件，再迁移业务页。
- 业务模块不得自建第二套主题管理、外壳或通用按钮/表单库；不要为套用 DashboardKit / Gradient Able 引入并行 Bootstrap 样式体系。
- 允许因业务需要扩展模式；扩展应在本规范和实施指南记录适用场景、复用边界与验证，避免逐页复制分叉。

## 10. 变更与验收

每个前端交付在所属阶段计划中列出使用的页面模式、共享组件、偏离基线的原因和检查范围。改变主信息架构或权限边界须先更新对应设计；常规视觉修正按现有授权推进，不增加重复确认流程。

评审必须检查：导航与标签、主题组合、信息密度、五类数据状态、表单恢复、权限显示、键盘/焦点、窄屏、图表口径。执行方法及正式接入顺序见[前端实施指南](../../../qms-2.0/docs/FRONTEND-DESIGN.md)。记录实际 PASS/FAIL 和未验证项，不以静态截图替代关键交互验收。
