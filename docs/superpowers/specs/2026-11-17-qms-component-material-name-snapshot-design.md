# 组件项目映射入库：内部物料名称快照

## 状态与授权

2026-11-17，负责人已确认编码对编码关联、快照模式，以及未找到物料时允许名称为空，并要求形成本轮计划。本轮当前交付为本地规格与实施计划；尚未实施、登记新需求、创建 Issue/PR 或部署。实施前按交付流程核对需求编号、Issue、版本及活动分支，不沿用上一轮 REQ-0039 的范围。

## 目标

在现有“API入库衔接”的组件项目映射目标中，允许名称来源选择“内部物料主数据”，通过 API 接收的组件编码匹配同组织物料编码，将物料名称保存为组件名称快照。

```text
API报文 → 编码来源字段 → 组件编码
                            │ 同组织、编码精确匹配
                            ↓
                    物料主数据.materialCode
                            ↓
                    物料主数据.materialName
                            ↓
                    组件项目映射.componentName
```

## 已确认规则

1. 仅组件项目映射目标增加本功能，其他目标不变。
2. 编码继续从已配置的 API 报文路径取得；去除首尾空白后精确匹配，区分大小写、保留前导零，不转数字、不模糊匹配。
3. 只匹配当前目标组织的物料，禁止跨组织兜底。
4. 名称采用快照：实际入库时读取并保存，不在列表查询时动态关联。
5. 物料后续改名、删除或补录，不自动回刷既有组件名称。
6. 未找到物料时，新建组件名称保存为 `null`，组件编码正常入库；已有组件保留原名称。
7. “允许为空”指合法组件编码未找到物料，不是允许组件编码自身缺失、空白或类型错误。
8. 显式重处理可重新读取当时的物料名称，是否修改已有组件仍遵守现有仅新增、更新指定字段、变化人工确认及并发保护。

## 界面

在现有名称格内组织来源方式和字段，不新增页面：

```text
编码来源字段                 名称来源
[ partCode             ]     [ 接口报文字段 / 内部物料主数据 ▼ ]
                             接口模式：[ name路径             ]
                             内部模式：[ 物料名称              ▼ ]
```

- 默认“接口报文字段”，历史规则打开和原样保存保持原语义。
- 内部模式下不要求外部名称路径，也不回退读取报文中的名称。
- 内部字段选项当前仅“物料名称”，不提供尚不存在的规格型号或任意数据库字段。
- 切换来源后提交只包含当前生效配置；切回时不静默保存隐藏旧配置。
- 试处理展示实际组件编码、名称结果及“物料未匹配”；未匹配是可入库结果，不冒充失败。
- 新记录空名称显示“未配置”；不把名称空值混同为现有项目/分类配置状态，项目、人员和分类继续沿用原规则。
- 遵守既有双语、未保存保护、未知请求恢复、窄屏收缩和长内容隔离。

## 入库与快照时点

| 情况 | 新建组件 | 已有组件 |
| --- | --- | --- |
| 编码匹配到物料 | 保存物料名称 | 按现有策略和允许更新字段决定 |
| 未匹配到物料 | 名称为空，正常保存 | 原名称保留，不形成清空差异 |
| 组件编码缺失或不合法 | 原校验拒绝该行 | 原校验拒绝该行 |
| 无物料读取权限或组织不可用 | 拒绝操作 | 拒绝操作，不能伪装为未匹配 |
| 查询异常 | 失败并沿现有重试路径恢复 | 不修改现有数据 |

- 单条试处理、历史分段导入、自动入库、重试与确认共用同一解析逻辑。
- 实际写入阶段使用事务内一致的物料读取结果；记录物料 ID/版本和来源方式作为快照依据。
- 预览是当时的结果。确认或写入时若物料版本、名称或匹配状态变化，不静默采用未展示的新值；沿现有过期/差异确认机制要求重验。
- 在“仅新增”下，重处理不修改已有组件；“更新指定字段”仅在允许更新名称时生效；人工确认仍保留并发基线和来源水位。
- 内部查不到物料表示“无名称供应”，不同于“显式清空名称”。不得用普通空字符串复用两种含义。

## 契约与实现边界

- 保留现有 `mapping` 报文路径语义，不把数据库字段编码伪装成报文路径。
- 新增可选的组件名称查询配置，例如 `componentNameLookup: { source: 'MATERIAL', field: 'materialName' }`；不存在时仍使用 `mapping.name`。
- 查询配置与 `mapping.name` 互斥，非组件目标不得携带该配置。
- 前后端由 Nest Swagger 生成类型同步；不手改生成契约、不重复定义 DTO。
- 物料模块提供受组织与权限约束的精确查询接口，入库模块消费该公开接口，不跨模块读取私有表。
- 组件适配器只为受控内部查询路径支持空名称；外部名称路径保持原必填校验。
- 现有数据库已经允许组件名称为空，规则/任务配置为 JSON；本方案不需要修改业务表结构。物料依据优先进入现有审计/执行记录，不新增无消费者的持久关联框架。
- 读取名称时不能调用要求物料写权限的现有入库适配器，也不能加载全部物料清单到前端逐条匹配。

## 权限与审计

- 保留现有 `ingestion:manage/run`、接收正文权限和 `component-project:manage` 边界。
- 使用内部查询的保存、执行、预览、确认、接管和幂等重放路径，补当前组织 `material-master:read` 校验。
- 管理员使用现有有效 `platform:admin` 投影默认可达；普通岗位不自动增加权限。
- 关闭查询仍允许在具备原规则维护权限时移除该依赖，不因已撤销物料读取权限而永久无法停用规则。
- 记录来源方式、匹配物料 ID/版本和未匹配结果，用于解释名称的入库依据；不复制整条物料或原始报文进审计。

## 验收与非目标

验收覆盖匹配/未匹配、前导零与大小写、组织隔离、三个处理策略、物料改名不回刷、预览后变化、既有名称保护、权限撤销与幂等重放，以及真实 PostgreSQL/Worker/浏览器路径。

不新增物料字段、不做自动补名/级联回刷、不改手工组件表单、不提供任意表关联或 AI 名称生成；不改变历史导入总量、项目/人员/阶段/分类配置规则。
