# QMS 2.0 阶段五覆盖补齐与分析增强设计规格

- 日期：2026-09-24
- 状态：阶段五总规划（分波次实施）
- 参考：QMS 1.0 产品规格、功能需求总表、实际路由/模型/实现文档；QMS 2.0 阶段一至阶段四规格、计划和当前源码
- 目标：补齐 QMS 1.0 对照中尚未形成 2.0 可执行计划的能力，并建立质量数据、管理增强和后续预留域的验收边界

## 1. 设计结论

阶段五采用“全量纳入盘点、按业务决策分波次交付”的总规划。阶段五不把所有遗漏合并成一个大模块，而是冻结覆盖台账，再按依赖拆成可独立验收的波次和子计划。

阶段四已经建立制程、客户、新品和审核的领域基础，但四条链仍存在浏览器、Worker、附件失败恢复和外部系统边界。阶段五先补齐这些主链缺口，再交付用户确认的供应商扩展、质量指标、管理效率和三坐标检测。

正式问题仍统一进入 QMS 2.0 的问题索引、流程、任务、附件、审计和报告链路。阶段五不得复制 QMS 1.0 的状态机、旧编号、负数外键、直接文件路径或兼容层。

## 2. QMS 1.0 覆盖分类

| 分类 | 处理方式 |
| --- | --- |
| 已纳入并已有 2.0 基础 | 账号、组织、权限、审计、附件、流程、问题中心、任务、供应商问题闭环 |
| 阶段四已策划但未完成 | 四域真实浏览器主链、Worker/提醒、附件失败恢复、外部接口验收、详细 8D 控制 |
| 阶段五具体交付 | 质量指标与数据平台、已确认的供应商扩展、客户投诉导入、制程产量与出货报告、审核增强、公告/签名/通知、移动现场能力、三坐标检测 |
| 后续版本 | 客户/供应商索赔、出货/批次追溯、仪器与 MSA、质量成本、完整试验管理、AD/LDAP 与 AI 自动业务决策 |
| 当前 2.0 不接入 | 1.0 历史数据迁移、Preview/Stable 双环境与灰度发布；普通 Feature Flag 并入权限体系 |
| 永久非目标 | 通用 BPMN、任意脚本执行、复制 1.0 代码和旧表结构 |

## 3. 阶段五波次

### 3.0 覆盖冻结与状态治理

- 建立机器可读的 1.0→2.0 覆盖台账，逐条记录来源、状态、责任域、计划波次、权限、验收证据和非目标理由。
- 同步 `CAPABILITY-STATUS.md`、权限目录、阶段四计划勾选状态和阶段五入口，消除源码已实现而文档仍标记 planned/未开始的矛盾。
- 为每个波次建立独立规格、实现计划、真实资源验收和回滚边界。

### 5.1 质量数据与指标基础

- 冻结 IMS/MES/ERP/SAP 的外部来源契约、字段映射、认证方式、幂等键、批次、时间区、失败重试和审计边界。
- 建立质量指标事实表和来源快照，覆盖来料合格率、上线 PPM、制程不合格率、直通率、0KM、3MIS、12MIS、供应商绩效和新品试产指标。
- 交付跨域质量看板、趋势分析、下钻到来源台账/正式问题、红绿灯规则和管理报表导出。
- 质量数据源未核实前只能使用人工录入和适配器端口，不创建模拟同步成功数据。
- AI 仅保留审计隔离的分析接口和人工触发入口；自动决策、自动改状态和自然语言生成 SQL 不在本波次默认交付。

### 5.2 供应商质量扩展

- IQC/来料检验记录、特采标记和 NG→供应商问题触发。
- 特采申请、审批、有效期、批次放行和追溯。
- 供应商准入中的质量资料提交与审核问题跟进，以及 PCN 变更；完整资质/证书与生命周期管理留待后续版本。
- 供应商年度审核、审核 NC、供应商状态更新和整改闭环。
- 质量目标批量/单独配置、审批、版本、生效和供应商签署。
- 月度绩效评分、人工配合度校核、绩效卡和绩效申诉。
- C/D 级会议、改善报告、参会记录和逾期扣分联动。
- PPAP Level 1–5、文件清单、逐项审核、批准和年度再鉴定。
- 检验规范/SIP、版本、出货报告频率和 ASN 资料互锁。
- 关键件条码规则、扫码、防重、批次归档和导出。

所有供应商扩展必须继续使用供应商组织隔离、平台流程节点、附件扫描、审计和 Worker，不能在供应商模块复制独立状态机。

### 5.3 客户、制程与问题闭环补齐

- 客户主数据、投诉台账和 Excel 批量导入；客户审核问题归入审核问题管理。
- D3 客户索赔与 C16 供应商索赔由用户决策列入后续版本，阶段五只保留来源关系与未来扩展边界。
- 制程生产分母、良率/直通率、出货报告归档和来源下钻；完整出货/批次追溯留待后续版本。
- 客诉 8D 的 5W2H、围堵、D4 根因、D6 验证附件、D7 文件变更、D8 水平展开、经验教训、分级审批和归档检查表。
- 本阶段客户/制程写操作进入审计，失败时与问题、附件、Outbox 同事务回滚。

### 5.4 新品与审核增强

- 新品量产移交归档、试产总结 Excel/PDF、IMS 试产数据适配器和来源可追溯报告。
- 初期流动管理作为静态记录和审批门，不直接控制生产系统。
- 审核内置标准库、客户/二方审核台账、Excel 问题清单逐条导入、报告输出和进展晾晒。
- 审核移动执行、弱网/离线暂存和恢复同步；现场附件仍必须经过真实扫描和资源授权。
- 审核提醒、延期、逾期升级、NC→正式问题和验证关闭继续复用平台 Worker 与流程。

### 5.5 系统效率与现场体验

- 公告、重要公告强制阅读和阅读审计。
- 用户电子签名、审批签章引用和签名资源保护。
- 通知规则、升级策略、邮件及企业 IM 通道配置；通道凭据只保存在环境外。
- 全局任务统计、逾期分析、批量转派和失败队列操作视图。
- 响应式移动端、PDA 扫码全屏模式和审核现场可恢复草稿。

普通业务 Feature Flag 不作为本波次默认权限机制；如需灰度，只允许经过独立决策门定义范围、审计和回滚。

### 5.6 三坐标检测

- 三坐标检测申请、审批、排单与使用进度可视化。

仪器量具、校准、MSA/GR&R、质量成本和完整试验管理由用户决策列入后续版本，不在本阶段创建通用表单或万能字段。

### 5.7 决策门与发布边界

- 1.0 历史数据迁移不接入当前 2.0，保持独立开发和数据边界。
- AD/LDAP/OA 和 AI 自动业务决策列入后续版本；本阶段只记录安全及接口边界。
- Preview/Stable 双环境和灰度发布不接入当前 2.0。
- Feature Flag 并入权限体系，不单独建设普通业务开关。

## 4. 跨波次不变量

- 领域事实由领域模块拥有，公共问题索引只保存聚合字段、稳定引用和来源快照。
- 外部数据必须通过适配器端口进入，保留原始键、观察时间、同步批次、失败原因和重试记录。
- 所有写操作使用服务端组织范围、CSRF、幂等键、CAS、审计和明确回滚。
- 正式问题、8D、审批、验证和关闭必须复用平台 Workflow，不允许领域自行修改公共状态。
- 文件必须引用对象资源，经过真实对象存储和扫描服务；客户端状态不能当作扫描证据。
- 每个新增入口必须具备允许、跨组织拒绝、撤权、409 冲突、重复事件、失败重试和历史读取证据。

## 5. 阶段五完成门槛

阶段五总体验收至少包括：

1. 1.0→2.0 覆盖台账无未分类条目。
2. 质量指标可以从来源快照下钻到领域台账和正式问题。
3. 供应商扩展至少完成一个完整纵向主链，并证明供应商隔离。
4. 客诉导入、出货报告、审核导入和 8D 增强均有真实 PostgreSQL 与浏览器证据。
5. 公告、签名、通知规则和现场能力有独立权限、审计和失败恢复测试。
6. 三坐标检测申请、审批、排单与进度有真实 PostgreSQL 和浏览器证据。
7. 外部系统及后续/不接入项有明确边界，不以接口占位宣称完成。
