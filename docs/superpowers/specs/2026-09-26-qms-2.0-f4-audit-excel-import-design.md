# F4 客户与二方审核 Excel 导入设计

## 目标

在审核管理页提供真实 `.xlsx` 文件预览与逐行导入。每一行沿用现有 `POST /audit-management/imports` 契约，由服务端执行组织范围、权限、CSRF、幂等键和外部键唯一性校验。

## 数据与错误

表头固定为 `sourceSystem`、`externalKey`、`finding`，可选 `customerKey`、`auditDate`、`auditType`、`severity`、`responsibleScope`、`responseForm`、`sourceUrl`。解析器拒绝未知/重复/空列名、公式或富文本、无时区日期、非法来源和链接，并保留 Excel 行号。单文件限制 2 MB、100 行、100 列和受限 ZIP 解压体积；错误行只展示，不提交。

## 导入与重试

每个有效行生成稳定的 `Idempotency-Key`，按顺序提交单行 JSON。成功行标记为已导入，服务端 4xx 标记为拒绝，网络/5xx 标记为结果未知并允许使用原键重试。权限撤销立即清除预览并停止后续行；不静默跳过任何行。

## 页面与验证

审核管理页即使没有导入行也加载当前权限，只有组织权限已确认时显示上传入口。UI 提供文件解析、逐行状态、错误信息和重试，不重复定义 API DTO。验证包括 parser 单元测试、真实 ExcelJS 工作簿测试、React 行为测试和既有审核管理回归。
