# 外部API统一对象数组正文

负责人2026-11-11明确要求最外层为`[{},{},{}]`并作为通用规则。覆盖此前仅对象的接收规则，适用所有现有及新增外部接收接口，不改人员管理API请求体、历史收件或业务入库。

- 新请求根必须是JSON数组，每项必须为非null且非数组的JSON对象，字段与对象内嵌值不新增业务限制；空数组`[]`允许。
- 整个原始UTF-8数组正文作为一次收件保存，一次配额/审计/服务端检索编号及201或204回执；不拆项，不恢复Idempotency-Key/去重，不新增schema版本或开关。原字节/1MiB/深度32/限流/身份组织/IP/事务安全保持，历史对象正文照常解密检索。
- 根对象、根null/字符串/数字/布尔、数组内null/数组/标量均400 `INTEGRATION_MESSAGE_INVALID`，受控错误文案明确“JSON正文必须是对象数组”，帮助调用方定位；无效JSON仍同码。Swagger请求体数组items object、页面说明、实际复制、示例payload和运维权威文档同步。
- 不迁移数据库，现有text密文/计数支持数组。新规则会拒绝旧调用方直接发对象，须改为`[{...}]`。生产联调不使用聊天中暴露的凭据。一般管理写API及其幂等不在范围。
- 核真实HTTP单项/多项/空数组与拒绝矩阵、跨组织/凭据/容量/并发/审计/原字节历史解密，生成契约、Web复制和真实浏览器无头发送数组/201204/检索；按源码变化适用验证，不重复无变备份或密钥系统全验。
