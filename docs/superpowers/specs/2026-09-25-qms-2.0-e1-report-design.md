# 阶段五 E1 试产总结原生报告设计

## 范围

从现有试产批次的已批准总结生成 `.xlsx` 与 `.pdf`。报告包含项目、批次、指标快照、正式与遗留问题快照、结论、提交及批准时间、总结版本和来源 SHA-256。原有实时 CSV 报告保留独立语义。

## 来源与门禁

下载端点使用现有内部账号、组织范围及 `new-product-quality:projects:read` 权限。调用者必须提交 `expectedVersion`。总结不存在返回 404；未批准或版本变化返回 409；实时指标或问题相对批准快照变化时返回 `NEW_PRODUCT_TRIAL_SUMMARY_STALE` 409。项目归档后仍可读取未过时的已批准总结。每次请求重新校验权限与来源；文件不缓存，也不进入持久化存储。

## 文件格式

ExcelJS 生成包含“试产总结”“指标”“问题”三个工作表的真实 XLSX。业务文本写为普通字符串单元格，禁止作为公式执行。PDFKit 使用随 API 生产依赖打包的 Noto Sans SC TTF 字体生成支持中文的 PDF。字体采用 OFL-1.1 许可，包路径通过 Node 模块解析，适用于现有 Docker 镜像中的生产依赖。

## 交互和验证

Web 仅在总结已批准时显示 Excel/PDF 下载入口，下载使用同源会话凭据，服务器再次校验门禁。测试验证文件签名及内部结构、中文字体嵌入、真实 PostgreSQL HTTP 下载、跨组织、撤权、版本冲突和过时来源。完整阶段验收由主任务统一执行。
