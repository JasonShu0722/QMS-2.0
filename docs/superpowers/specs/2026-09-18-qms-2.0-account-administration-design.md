# QMS 2.0 账号与系统管理设计

## 背景

本设计起点是已有账号登录、会话、组织范围和功能权限底座，但尚无可用账号管理产品。现已按 A/B/C 实现个人账号、管理员用户及组织角色治理并通过最终验收；证据与本地环境限制见 qms-2.0/docs/FOUNDATION.md。QMS 1.0 中的能力只作为盘点参考，不能直接复制旧系统实现。

## 目标

建立独立于业务域的账号与系统管理能力，为供应商质量及后续业务域提供稳定的用户、组织、角色、权限、安全和审计前置条件。

## 本轮 ABC 范围

A：当前用户资料查看、邮箱编辑、修改密码、有效会话列表和撤销其他会话，内部与供应商分别从 `/app/account` 和 `/supplier/account` 进入。复用 Session、Password、Authorization 和 Audit，所有写操作校验身份和 CSRF，资料及安全变更与脱敏审计同事务。

B：`/app/admin` 按授权组织提供用户查询、创建、邮箱编辑、启停、受控主组织/账号类型变更，以及管理员一次性重置签发；`/reset-password` 支持匿名凭证兑换。初始密码与重置秘密仅在内存中处理。

C：同一管理页提供组织角色 CRUD、同组织角色模板复制、只读权限目录、角色分配和权限矩阵。功能权限与组织范围由服务端执行，普通功能权限不能代替流程节点权限；组织角色 API 不编辑全局角色，也不提供流程节点授权编辑器。

D–H 的组织树、部门/岗位、配置/通知、安全增强、管理审计、部署与数据保护、跨页面治理，以及批次 3 本轮不启动。ABC 验收后可由用户另行分配非生产工作；真实供应商试点仍需这些最小门禁及原平台深度验收完成。

## 接口边界

- `GET /api/v1/me`
- `PATCH /api/v1/me`
- `POST /api/v1/me/password`
- `GET /api/v1/me/sessions`
- `POST /api/v1/me/sessions/:id/revoke`
- `GET /api/v1/admin/organizations`
- `GET/POST /api/v1/admin/users`、`GET/PATCH /api/v1/admin/users/:userId`
- `POST /api/v1/admin/users/:userId/password-reset`、`POST /api/v1/auth/password-reset/complete`
- `GET /api/v1/admin/permissions`
- `GET/POST /api/v1/admin/roles`、`GET/PATCH/DELETE /api/v1/admin/roles/:roleId`、`POST /api/v1/admin/roles/:roleId/copy`
- `GET/PUT /api/v1/admin/users/:userId/roles`

DTO、参数、权限、错误码和审计动作由 API 定义并生成 OpenAPI；Web 只导入 `@qms/contracts` 类型。完整组织 query、幂等头、请求/响应契约见 qms-2.0/docs/OPENAPI.md；权限矩阵由角色与权限目录读取结果生成，不增加独立矩阵接口。

## 非目标

- 不实现 QMS 1.0 兼容层。
- 不实现供应商、客户、制程、新品或审核专业字段。
- 不实现自助邮件找回、MFA 注册/验证/恢复码、组织树编辑或任意系统参数；已有管理员一次性重置不等于完整 E 安全增强。

## ABC 安全修订

- 功能权限按请求选择的目标组织判定；UUID 和组织范围先校验，供应商只能本企业。管理员写事务重新读取当前账号和授权。
- B 用户更新以 query.organizationId 表示源组织、body.organizationId 表示目标组织；迁移需要两端管理权限，禁止自停用、自迁移和自类型变更。修改或重置目标用户需要覆盖其所有组织的现有权限；身份变更清除旧角色并撤销会话。
- 管理员签发 30 分钟一次性重置凭证；浏览器生成至少 32 字符随机 temporaryCode，服务端只保存哈希。签发不修改长期密码；匿名 CSRF 和限流保护的兑换操作原子消费凭证、更新密码、撤销会话及审计。邮件自助找回仍属于 E。
- B/C 写请求必须携带 Idempotency-Key；actor、组织和 key 唯一，动作及 HMAC 请求摘要冲突返回 409。使用 QMS_RATE_LIMIT_SECRET 并隔离用途；安全响应与业务和审计在同一 Serializable 事务中持久化，重试不重复执行。
- username 限 ASCII 字母、数字、点、下划线和连字符；username/email 全局大小写无关且去首尾空格唯一。迁移遇既有冲突明确失败，不删除数据。
- 组织选择目录只返回当前账号有用户或角色管理读取/写入权限的组织及摘要、类型和权限。全局角色不允许通过组织角色分配接口移除。
- A 资料写入和审计同事务，会话列表只列有效会话，改密通过旧密码哈希条件更新防止并发覆盖。
- 主组织迁移有问题负责人、任务办理人或通知接收人引用时返回 `ADMIN_USER_ORGANIZATION_IN_USE`（409），事务回滚并记录拒绝审计。三类复合用户外键使用 `ON UPDATE RESTRICT`，避免级联迁移业务组织；普通资料编辑和停用不受此迁移限制。
- 登录最终身份核对和会话创建持有同一用户行锁，阻止旧密码校验后与停用、迁移或改密竞态建立新会话。
- Web 按所选组织权限控制导航/只读/写入口；角色编辑只提交真正变化的字段，保存待响应期间不能新建第二份用户/角色表单。

## 验证

- 单元和 HTTP 测试覆盖身份、字段白名单、旧密码校验、旧会话失效、跨用户会话拒绝和审计。
- PostgreSQL 集成测试验证组织授权、幂等、迁移引用阻止、一次性重置、密码更新、登录竞态、会话撤销和事务回滚。
- OpenAPI 与生成 contracts 无漂移。
- Web 页面测试覆盖 A/B/C 的成功/拒绝和真实请求参数；真实浏览器使用同库网关验证用户与角色操作、只读边界、供应商入口隔离及单次重置兑换。聚合、在线镜像、运行/清理与本地交付状态以实际证据单独记录，不将单层通过替代整体完成。
