# QMS 2.0 账号与系统管理设计

## 背景

问题与流程平台已经具备账号登录、会话、组织范围和功能权限判定，但缺少个人账号中心和管理员系统管理。QMS 1.0 中的用户、角色、权限、基础信息和管理审计能力需要在 QMS 2.0 中重新建模，不能直接复制旧系统实现。

## 目标

建立独立于业务域的账号与系统管理能力，为供应商质量及后续业务域提供稳定的用户、组织、角色、权限、安全和审计前置条件。

## 首个开发切片

首个切片只实现个人账号中心：当前用户资料读取/编辑、修改密码、有效会话列表和撤销其他会话。它复用现有 Session、Password、Authorization 和 Audit 服务，所有写操作由服务端校验身份和 CSRF，并记录脱敏审计。

管理员用户、角色权限、组织基础资料、MFA、密码找回和管理审计查询拆为后续切片，不在个人账号切片中伪装完成。

## 接口边界

- `GET /api/v1/me`
- `PATCH /api/v1/me`
- `POST /api/v1/me/password`
- `GET /api/v1/me/sessions`
- `POST /api/v1/me/sessions/:id/revoke`

DTO、权限、错误码和审计动作由 API 定义并生成 OpenAPI；Web 只导入 `@qms/contracts` 类型。

## 非目标

- 不实现 QMS 1.0 兼容层。
- 不实现供应商、客户、制程、新品或审核专业字段。
- 不在首个切片中实现管理员密码找回、MFA 注册器、组织树编辑或任意系统参数。

## 验证

- 单元和 HTTP 测试覆盖身份、字段白名单、旧密码校验、旧会话失效、跨用户会话拒绝和审计。
- PostgreSQL 集成测试验证密码更新、会话撤销和事务回滚。
- OpenAPI 与生成 contracts 无漂移。
- Web 页面测试覆盖读取、编辑、修改密码和撤销会话的成功/拒绝状态。
