# QMS 变更影响推荐设计

**目标：** 从当前 Git 改动或指定基线后的提交改动，给出可审查的验证命令和文档复核入口，减少新功能与维护任务的漏测。推荐结果不执行验收，也不降低现有分层门禁。

## 方案选择

调用图分析能追踪更多间接依赖，但无法可靠推出权限、事务和运维影响；自由文本推断覆盖面灵活，却缺少可重复的失败条件。本轮采用版本化路径规则：工程目录、公共平台模块、迁移、流程、部署等路径映射到明确命令与复核文档。未识别路径保守推荐完整本地检查及阶段验收，并标记需要人工判断。

## 输入、输出和边界

- 默认读取活动仓库相对 `HEAD` 的已提交、暂存、未暂存和未跟踪非忽略改动；可用 `--base <ref>` 纳入分支相对基线的提交改动。只读取 Git 路径清单和 P2 源码指纹，不读取差异正文、秘密或归档。
- JSON 规则是唯一映射来源；结果包含匹配规则、改动路径、推荐命令、相关权威文档、未知路径和源码指纹。终端默认输出中文 Markdown，`--format json` 便于其他工具读取。
- 文档来源复核依 `documentation-index.json` 的 `review.sources` 反向查找；目录规则额外关联相应文档。公共权限、迁移、流程及部署变化增加相应真实集成或阶段门禁。未知路径采用保守集合。
- 结果只是建议，不表示命令已执行或 PASS；阶段整合、发布和根 `AGENTS.md` 的真实验收要求继续优先。缺少 Git 基线、规则错误或路径不在已知范围时不能给出“无需验证”的结论。

## 验证

用纯路径测试覆盖文档、API、Web、公共权限、迁移、流程、未知路径、删除与重叠规则；用真实临时 Git 仓库验证工作区及 `--base` 取变更。检查输出无秘密、规则 ID 和命令有效，接入现有治理与默认测试。
