## 2. 原始目标与范围

负责人要求单独建设“API 入库衔接”。按目标功能选择现有接收接口，通过可配置条件识别每条数据，与组织内现有主数据按业务编码比较；新编码校验后入库，已有数据按可选策略处理。支持单条试处理、系统已收历史数据批量导入、后续新消息自动触发，并内置持久化顺序处理，避免后一条在前一条完成前抢先更新。

| 接收接口 | 筛选后目标 | 入库范围 |
| --- | --- | --- |
| 供应商/客户信息 | 供应商档案 | 编码、名称及允许同步的来源字段 |
| 供应商/客户信息 | 客户档案 | 编码、名称及允许同步的来源字段 |
| 物料成品信息 | 物料主数据 | 物料编码、名称及本期批准字段 |
| 物料成品信息 | 现有组件项目映射 | 组件编码、名称先入库，项目/人员/新品量产等由管理员补配 |

“库存对比”在本期指现有主数据档案对比，不含库存数量、仓储、采购订单或出入库。不得另建成品档案取代组件项目映射，不自动生成供应商账号、组织、岗位或授权。

## 3. 配置规则

管理端提供独立“API 入库衔接”配置与结果入口，复用现有组织范围、权限、主题、语言、分页和错误恢复机制。

每条规则包括：名称、目标档案、接收接口、启停、筛选条件、字段对应、业务编码识别、已有记录处理方式、允许更新字段。接收接口下拉直接显示接口名称；仅可关联当前获授权组织的接口。

### 3.1 条件筛选

- 判断字段由管理员配置，可结合已接收样本选择；不把供应商/客户或物料/成品的字段名和分类取值写死。
- 首批比较方式：等于、不等于、属于、不属于、为空、不为空；多条件支持全部满足或任一满足。字段值按配置类型判断，不将字符串与数字隐式混为同值。
- 未命中记录为“筛选跳过”；必需判断字段缺失、类型不符要说明原因，不因缺失字段而错误满足“不等于”等规则。
- 同一个接收接口可以配置四类目标中的多条规则；同一数据同时满足供应商和客户条件时可分别进入两类档案。
- 同一目标档案规则重叠时须在试处理/启用前提示并明确处理，避免重复或相互覆盖；不引入任意执行脚本。

### 3.2 字段与编码

- 按目标映射编码、名称及本期需要的可写字段；来源多余字段保留在原文中，不自动扩展业务表。
- 编码按字符串处理，保留前导零，去首尾空格；不默认转数字或改变大小写。组织内唯一性遵循对应档案现有规则。
- 缺少编码/必要名称或字段类型、长度无效时显示具体行和原因。
- 来源字段缺失、空值默认不清空现有资料；允许清空须有明确字段和操作语义。
- 组件API仅同步允许的来源基础字段，管理员维护的项目、人员、阶段及分类不被接口覆盖。

### 3.3 已有数据三种策略

| 策略 | 新编码 | 已有编码且内容变化 |
| --- | --- | --- |
| 仅新增，已有跳过 | 自动新增 | 跳过，保留当前档案 |
| 新增并更新指定字段 | 自动新增 | 仅自动更新配置允许的字段 |
| 新增，变更人工确认 | 自动新增 | 生成旧值/新值差异，确认后更新 |

相同内容记“无变化”，不新增档案、不反复生成同一差异待确认。人工确认使用当前档案版本重新比较，旧待确认结果不能覆盖后来更新。多个来源写同一目标编码时明确来源字段所有权并保并发校验，不能靠不同接口独立队列保证全部冲突安全。

## 4. 三种操作入口

### 4.1 单条试处理

从已接收对象数组选择具体一条，预览命中规则、字段提取、校验、新旧差异和预计动作，默认不写业务档案。明确点击“确认导入”才进入正式任务，不以预览隐式新增/更新。预览与执行使用同一配置版本；执行时重新检查权限与档案并发变化。

### 4.2 历史批量导入

按接口、接收时间等固定历史范围，预览可处理接收份数和数据条数，确认后提交批次。这里处理系统已保存的接收数据，不增加向来源系统主动拉取历史的发出接口。已经清理正文的数据不能恢复解析，须由来源重新推送。

重复点击或相同范围已存在任务时提示并复用已提交事实；显式重新处理需保留新的处理记录和原因，已成功项不能因任务恢复被重复执行。进度、成功/跳过/失败/待确认数量可查看，失败项可重试。

### 4.3 新数据自动触发

启用规则后新接收数据保存并生成可恢复处理任务；接收提交和任务登记避免出现已成功接收但永久丢失处理任务的窗口。继续使用现有Worker/数据库能力，不预建新中间件。关闭规则不停止机器接收；既有队列暂停、取消及恢复的可观察语义要明确，不能默默丢弃任务。

## 5. 队列、顺序和异常

- 所有正式单条、历史、新触发任务进入持久化队列，服务重启、页面关闭后仍可恢复；同一任务不得被两个执行者同时写入。
- 同一组织、同一接收接口串行；按服务端入队顺序及一份数组的原始下标处理。档案写入和条目成功结果在同一事务提交，避免业务已写但状态未记导致重复写入。
- 首次历史初始化在固定历史边界前建立批次，历史先处理，期间新数据照常接收返回true、排在历史后；不得无限回扫新增数据导致历史批次永远结束不了。
- 自动同步后再补导更旧历史：优先依据来源版本/更新时间防止回退；没有该字段时，历史不自动覆盖已有新值，差异交人工确认。仅接收顺序不能推断来源业务新旧。
- 系统/数据库故障暂停对应接口队列并可退避重试，不能直接越过后反向覆盖。数据校验失败准确记录；管理员可有记录地跳过阻塞项，具体继续策略在实现规格中固定。
- 待人工确认项不长期堵塞整个接口队列，但确认时必须重新比较当前档案；后续相同编码的数据不能被较早的人工结果覆盖。
- 暂停只阻止启动新任务；当前事务按可观察边界完成。取消只取消未执行任务，已入库数据不自动回滚；恢复按原顺序接续。
- 未完成任务及待确认所需数据要保留至结束并计入容量；清理/手工删接收记录不得使任务失去必要输入。容量或积压达到边界应明确告警/拒绝新增处理任务，不无限增长且不伪造成功处理。
- 本期不因一次推送没有某对象而删除/停用档案；来源删除/停用同步在另行明确后再开放。

## 6. 组件项目映射补配与更新

API成品规则先建立或按策略更新现有组件编码、名称，未配项目或必要分类时显示“待配置”，可集中筛选检索；不造虚拟项目、人员或默认新品量产来凑完整数据。待配置组件不能被后续业务当成完整映射自动带出责任人。

复用现有组件多选批量设置/预览/版本检查能力，覆盖待配置与已配置组件的新增关联和更新：关联项目、相关人员、新品/量产阶段及现有必要产品分类。逐字段明确“保持不变”“设置为”，可清空字段另有“清空”动作。默认沿用既有可验证的批量边界，不因接收页支持1000条而推定组件批量上限也为1000。

现有新品/量产阶段、客户质量工程师与项目质量工程师属于项目层配置；修改共享项目可能影响未勾选组件。预览需列出选中数、实际受影响组件/项目数及其他关联组件；管理员确认后执行。仅换组件归属时选择其他项目，不静默复制项目或更改现有领域归属。冲突重新预览，不能直接覆盖他人的修改。

## 9. 验收标准

1. 同一供应商/客户接口按配置分别进入对应档案，同一物料/成品接口分别进入物料与组件映射；改变判断字段/取值无需改代码，未命中与无效数据不误入库。
2. 三种策略分别验证新编码、已有变化、相同内容、空值与前导零；同一组织业务编码不重复，跨组织同码互不干扰。
3. 单条试处理无写入，确认才写；历史固定范围与新自动触发共队列，重复点击、重启、超时未知提交与多执行者不重复业务写入。
4. 同接口任务按顺序、同数组逐项处理；历史与新增交叉、补导旧历史和人工晚确认均不能覆盖较新档案事实。
5. 一条失败能定位到接收记录/行号/字段；正常跳过不报成失败，批次计数与实际一致；暂停、重试、取消、跳过行为符合已公布边界。
6. 未完成/待确认数据保留与容量计账正确；接收正文到期/手工删除不会留下不可恢复任务，未保存历史明确不可导入；删除接收记录不级联删业务档案。
7. 组件编码名称先入库且待配置可查；单条/多选批量补配和更新可完成项目、人员、阶段、分类，保持不变与清空不混淆，预览准确提示共享项目影响，版本冲突不覆盖。
8. 人员候选、选中和预览显示姓名/部门（账号）；按部分姓名查到分页后候选，同名/多任职可区分；失效任职、停用和越权拒绝有效。
9. 配置修改不改写已排队批次的配置版本；多来源同目标冲突有明确处理，不从没传到的数据推断删除或停用；保原200/true与错误协议。
10. 工程验收采用真实一次性PostgreSQL/Worker与浏览器，覆盖四目标及权限/并发/恢复主链，契约生成、审查、PR/CI/部署与人工验收分层记录；本次文档提交不计这些验证已执行。
