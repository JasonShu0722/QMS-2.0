## 2. 架构与已有能力复用

```text
公司系统 / 集成平台
  → 现有公网 HTTPS 网关（接收路径的大小、超时、来源频率限制）
  → api-integration 接收端点（机器身份、接口范围、组织、状态、配额）
  → 同一 PostgreSQL 事务（配置及凭据复核、防重复、元数据、加密正文、回执）
  → 按接口开关返回成功响应（回执正文或 HTTP 204 空正文）

管理控制台 → 现有人员会话 / 管理权限 → 配置与查询 API → 同一拥有者服务
现有 Worker → 有界保留清理
现有技术 / 交换观测 ← 真实接收结果及公开端口
```

- 新增 `api-integration` 领域模块拥有接口、机器凭据、收件记录与容量事实，不向已有 `system-management` 观测表塞入正文。
- 人员权限、管理事务、审计、密钥信封、可信代理、控制台目标组织、Swagger 生成类型和台账组件均复用已有机制。
- `DataExchangeRegistryService` 在启动时封存注册表。注册一个固定接收来源 `QMS_API_INBOUND` 与对象类型 `JSON_MESSAGE`，运行时接口归属由拥有者校验，不按管理员新建接口动态注册来源。
- 交换观测的传输成功只表示接收持久化成功；业务校验、处理、对账保持 `NOT_REPORTED`。观测写入失败不改变已持久化回执。
- 每次 HTTP 请求使用服务端生成的 UUID 作为 `traceId` 和独立观测关联标识，消息编号另行保存，不能将最长 128 位消息编号直接塞入现有最长 80 位观测字段。同消息的失败、重试和成功分别属于独立请求，不覆盖已有终态。复用交换端口时以单请求为 BATCH、接口 UUID 为 batchId、traceId 为 correlationId、attemptNumber 固定 1；单请求只有传输结果，不伪造业务批次/记录数量。
- 收件事务提交后，请求结果采集及交换观测均为非关键记录：隔离其校验、权限、冲突及存储异常，显式显示采集缺口，不允许把已成功的 201/204 改成 4xx/5xx，也不无界后台重试。现有 `tryRecordStageResult` 仅处理 503，不能直接假定它满足此边界。
- API Key 随请求逐次查验数据库，不用浏览器 Cookie，不把机器映射为人员或供应商用户，不授予业务写权限。

## 4. 凭据与人员权限

### 机器凭据

- `Authorization: Bearer <credentialId>.<secret>`；secret 使用密码学安全随机数，至少 256 bit；每个凭据只绑定一个接口及其固定组织。
- 随机秘密的SHA-256校验值用于定长安全比较；按负责人要求，新凭据另用已有keyring加密保存秘密，用于有凭据管理及接口管理权限的人员重复复制对接配置。URL、日志、审计、普通列表/详情及管理幂等回执不保存秘密原文；不新增鉴权平台或密钥环境变量。
- 凭据有名称、创建人、创建时间、失效时间和撤销时间。管理页面默认选择“永久有效”，也可指定1～365天；API以validityDays=null表达永久，省略该字段的已有调用方仍按90天处理。永久凭据expiresAt=null，仍可撤销；每接口原有最多两个有效凭据限制保持。
- 轮换为创建新凭据、调用方切换、撤销旧凭据。新凭据存在不代表调用方已切换。
- 创建的管理幂等回放仍仅返回元数据，不把secret放进AdminMutation响应；新凭据可通过受控对接配置读取重新复制。旧凭据没有可恢复密文，继续按原有效期鉴权，复制时明确提示新建可复制凭据，不伪造秘密、不自动撤销旧凭据。
- 过期、撤销、接口停用、组织停用/删除/待配置时拒绝；接收事务内复核。撤销与接收采用相同锁顺序，以事务提交先后定义生效边界。

### 人员权限

新增专项权限。负责人在首轮上线后明确要求 Admin 默认可用，五项权限纳入有效 `platform:admin` 的既有活跃内部组织权限投影，并由受控 context 显示管理菜单入口；普通账号通过现有岗位授权系统分配。此要求覆盖首版“平台管理员不默认获得”的策略，不批量修改存量岗位、不按用户名特判；供应商、停用/待配置组织及失效平台来源沿原边界拒绝：

| 权限 | 范围 |
| --- | --- |
| `integration:read` | 查看授权组织的接口配置，不返回秘密 |
| `integration:manage` | 创建、编辑、启停；受目标组织与最近认证约束 |
| `integration:credentials:manage` | 创建、轮换、撤销凭据；同时要求对应接口管理权 |
| `integration:receipts:read` | 检索收件元数据与详情 |
| `integration:payload:read` | 单独读取正文；同时要求记录读取权，记录访问审计 |

管理写操作继续使用人员会话、CSRF、最近认证、管理幂等及事务内授权。机器接收 Controller 使用专用强制鉴权 Guard；CSRF 只对明确标记的处理器豁免，缺少或伪造 API Key 仍拒绝。不能按 URL 前缀、存在 Authorization 头或“非浏览器请求”宽泛豁免。现有人员写接口的 CSRF 行为必须回归。

## 5. 接收协议与可靠性

### 请求

```http
POST /api/v1/integrations/inbound/{endpointId}/messages
Authorization: Bearer <credentialId>.<secret>
Idempotency-Key: <调用方生成的唯一消息编号>
Content-Type: application/json

{"任意业务字段":"由调用方提供，一期仅接收留存"}
```

- `Idempotency-Key` 必填，采用现有 8～128 位 ASCII 字母、数字及 `._:-` 规则，按接口与组织限定唯一性。它是技术消息编号，不等于业务单号或业务版本。
- JSON 顶层为对象；一期不要求业务字段或统一 `data` 包装，不将 body 内来源/组织声明作为授权依据。不支持压缩正文、文件或 multipart。
- 专用路径先有界读取原始 UTF-8 字节，鉴权后解析 JSON；拒绝非法 UTF-8、非法 JSON、非对象和超过 32 层嵌套。不改变其他接口默认解析及 100 kB 限制。
- 正文 SHA-256 摘要只用于同编号内容冲突检查；按原始字节比较，空白或字段顺序改变也构成不同内容。调用方重试必须保留编号和相同正文，调用说明明确规则。
- 同一事务保存回执、编号、配置版本及无秘密必要快照、摘要、加密正文与容量记账；唯一约束与事务控制并发重复，异常完整回滚。

| 情况 | HTTP / 结果 |
| --- | --- |
| 开关开启：首次成功持久化 | 201，`receiptId`、`messageId`、`receivedAt`、`status=RECEIVED`、`duplicate=false` |
| 开关开启：同编号同正文重试 | 200，原回执及原接收时间，`duplicate=true`；不新增正文或重复占容量 |
| 开关关闭：首次成功或同编号同正文重试 | 204，无响应正文，不通过自定义响应头返回回执字段；内部接收记录、防重复和计账仍正常执行 |
| 同编号不同正文 | 409，`INTEGRATION_MESSAGE_CONFLICT`；保留原记录 |
| 非法编号 / 正文 | 400；媒体类型不支持为 415，超大为 413 |
| 凭据无效、到期或撤销 | 401，统一机器鉴权错误，不泄露接口存在性 |
| 已鉴权但接口/组织状态不允许、来源 IP 不符 | 403，固定错误分类，无内部详情 |
| 超频 | 429，提供 `Retry-After` |
| 数据库、主密钥不可用或容量耗尽 | 503，无成功回执，不暴露底层异常 |

### 错误协议与关联

应用错误复用现有 `{ code, message, fields, traceId }`，新增 4xx 业务码登记到平台错误目录；否则现有过滤器会退回通用 `HTTP_409` 等代码。5xx 沿用 `INTERNAL_ERROR` 和安全提示，内部以有界原因分类区分存储、密钥、审计或容量故障，不将底层异常返回调用方。没有明确事务结论时标记结果未知，不因返回了 5xx 就断言消息未落盘。

应用响应统一使用服务端生成的 `X-Request-Id` 关联当次请求，包含回执关闭时的 204；它是排查标识，不返回 receiptId/messageId 等回执字段。错误正文 traceId 与该头一致，不采信客户端输入的请求号作为服务器身份。网关提前拒绝、网络中断或上游超时可能没有此头或 JSON 错误正文，调用说明要求先按 HTTP 状态/连接结果处理，不能无条件解析 JSON。

开启回执时首次收件返回 201，关闭时返回 204；两者均须等待接收事务成功提交，不使用暗示另有异步业务任务的 202。关闭回执不意味着不响应、提前确认或吞掉错误：冲突、鉴权、格式、超限和存储失败仍按表中 4xx/5xx 返回受控错误。

开关变更沿用配置版本、管理权限、CAS 与变更审计。每次请求使用当次服务端复核的配置快照决定响应格式；重试也使用当次开关状态，即使原消息接收时开关不同。内部接收数据和原接收配置快照不随开关变更改写；管理详情可查看原记录，调用说明同步当前开关与状态码。

网络中断、超时或 5xx 后，调用方使用原编号和原正文退避重试；409 应排查编号复用，其他 4xx 应修复请求。未知 COMMIT 不编造成功，重试按已提交事实及当次开关返回回执或 204。

防重复保证窗口固定为首次接收后 90 天，正文提前清理不影响窗口内原记录识别；开启回执时可返回原回执，关闭时返回 204，重试不延长窗口。90 天后编号可重新接收，不承诺永久去重。

到期判断以数据库时间为准，不依赖 Worker 恰好完成清理；到期编号重用在同一接收事务内处理旧唯一键及容量释放，防止残留记录造成永久冲突。已撤销凭据、停用接口或组织仍须先拒绝，不能通过旧回执重取绕过当前授权。

## 6. 数据、检索与容量

### 最小数据模型

| 模型 | 拥有事实与约束 |
| --- | --- |
| `IntegrationEndpoint` | 固定组织/来源/编码、状态、`returnReceipt`、配置版本、限制；组织内编码唯一 |
| `IntegrationCredential` | 接口外键、公开标识、秘密校验值、可空有效期、撤销事实及新凭据秘密密文；无持久化明文 |
| `IntegrationReceipt` | 组织/接口/编号、回执 UUID、凭据标识、配置版本及必要快照、摘要、接收/到期时间、正文密文与字节数；唯一 `(organizationId, endpointId, messageId)` |
| `IntegrationRequestAttempt` | 仅已验证机器身份的请求元数据：服务器 traceId、组织/接口/凭据标识、通过格式校验的消息编号、可选回执关联、时间/耗时、配置版本及当次回执开关、HTTP 状态与固定结果/原因分类；不保存正文或认证头 |

限流窗口与组织容量账采用同模块专用有界记录，不建立通用配额平台。接口、组织及凭据的引用纳入受控生命周期。

正文用现有 AES-256-GCM 信封加密，AAD 绑定组织、接口和回执。元数据与密文逻辑分离；清理正文后回执仍存在，显示“正文已按保留期限清理”。列表与观测不解密正文。索引覆盖组织/接口/接收时间以及编号精确检索。

默认查询最近 7 天，最大范围 90 天，默认每页 20、最大 100，按接收时间和回执 ID 稳定倒序。支持接口、来源、消息编号及回执编号过滤；不做任意 JSON 属性全文检索和正文导出。

收件列表展示首次已接收事实及正文可用性。请求结果视图展示已验证身份请求的接收、重复、拒绝、失败或结果未知，支持结果分类及 traceId/合法消息编号精确查询，沿用 `integration:receipts:read` 与组织隔离；无正文或无收件记录的失败不伪造成收件成功。

鉴权前失败、网关提前拒绝及身份不可信请求仅进入全局受控安全汇总，不能按 URL/body/凭据公开标识冒认组织。数据库不可用、进程中断或结果采集失败时可能缺少请求明细，界面明确采集范围/缺口；不能承诺全部失败均无损可查。现有 API 分钟聚合及交换观测没有消息编号/traceId 精确检索，不能单独替代该请求视图。失败记录不保存正文、Authorization 或完整请求头。业务处理区域只显示“本期仅接收留存”。

### 建议运行基线

| 项目 | 默认 / 上限与处理 |
| --- | --- |
| 请求大小 | 默认及一期硬上限 1 MiB，可按接口调低；网关/应用均限制，含无 Content-Length 请求 |
| 接口接收频率 | 默认 60 次/分钟，可设 1～300；数据库窗口原子计数，重启/多进程不绕过；过期窗口限批清理 |
| 正文保留 | 默认 7 天，允许 1～30 天；接收时固定到期，配置变化只影响新消息 |
| 元数据及防重复 | 固定 90 天，与已有交换观测 30 天分别处理 |
| 请求结果明细 | 最近 7 天，每组织最多 10000 条，先清理过期，再限批淘汰最旧明细；容量和淘汰只影响请求排查窗口，不删除收件/审计或改变去重窗口 |
| 正文容量 | 每接口默认 256 MiB，允许 16～1024 MiB；组织总硬限 1024 MiB，事务内共享记账；不足返回 503，不覆盖旧消息 |
| 回执数量 | 每组织保留窗口内最多 100000 条，避免小报文耗尽元数据容量；不足拒绝新接收，重复回执仍可返回 |
| 清理 | 复用 Worker 分钟维护入口，每批最多 100 行、每轮最多 10 批；清正文/删到期元数据分别处理，释放记账，不删除正式管理审计 |

网关另对真实来源 IP 设置接收路径专属频率与连接/读取超时；上限按同一公司出口可能汇聚多个接口确定。不借用登录限流器，不创建无限增长的进程内 key Map。容量、频率和保留是安全初始建议，生产启用前根据真实样本确认，不作为吞吐承诺。

接口详情在已有页面展示有效凭据的到期时间、当前容量/限额及最后一次清理成功或失败事实；容量达到 80% 时提示，达到上限按协议拒收。请求采集缺口与清理失败进入已有运行事实/受控日志，不在一期新增外部通知渠道或告警平台。有效消息才增加收件数量/正文容量；重复不重复占用，但仍计入请求频率；非法身份不创建接口限流窗口。正文容量按实际密文字节计账，元数据、WAL 和备份空间另留余量。

### 备份能力约束

当前 `apps/api/scripts/data-protection.mjs` 的完整备份工具限制数据库 dump 256 MiB、完整包 512 MiB。加密正文不应按高压缩率估计；上表单接口 256 MiB、单组织 1 GiB 是应用硬限建议，尚不能据此宣称现有备份覆盖全部允许容量。

生产启用必须以选定备份路径在实际全库体积、密文和保留上限下完成备份与恢复为证据；用小样本备份通过不能覆盖大容量配置。容量审批同时核对整库、所有组织及对象包开销；在尚无更大能力证明时限制批准容量，不提高旧工具常量或默默截断。若现有路径无法满足真实规模，将大容量备份改造独立策划，不为一期默认引入新系统。恢复后先保持入口停用，核对到期隐藏、去重、组织状态和实际需要撤销的凭据，再经授权重新启用。

## 7. 安全、审计与运维

- 复用批准公网 HTTPS 入口，不额外公开 API 容器端口；调用方直接请求 HTTPS，不依赖 HTTP 重定向保护秘密。
- 复核实际代理层数；只采信可信代理覆盖的来源头，防伪造白名单地址。浏览器 CORS 不因机器接入扩大。
- 正文以纯文本/代码视图显示，禁止执行 HTML。字段未定义时整份按敏感正文保护，只有显式授权人员可查看，不承诺字段级脱敏已完成。
- 审计记录配置、启停、凭据创建/撤销、授权拒绝和正文访问，使用资源标识，排除秘密和正文。机器收件事件的 `actorUserId=null`，以经过验证的组织、接口和凭据追溯，不造人员账号。`AuditLogService` 已支持空人员身份，但 metadata 白名单会过滤新标识；只增有界 UUID 字段 endpointId/credentialId/receiptId 及必要布尔/版本字段校验，不放开任意 metadata。审计不可用时管理写和正文披露失败；首次收件及必要接收审计保持事务一致。
- 新正文模型纳入现有密钥轮换、备份和恢复；`security:reencrypt` 不会自动覆盖新增模型，实施必须扩展并演练。
- 普通组织物理删除沿用引用预检及外键保护，存在接口、凭据或未到期记录时阻断，不级联删历史。历史收件/请求结果按历史引用分类，不因已接收数据而阻止组织普通停用；启用的接口仍按有效配置处理。组织被停用、删除或待配置后逐请求拒绝。
- 既有组织强删采用 tombstone，并非物理删除；不因一期把该治理动作一律禁用。强删事务停用本组织接口、撤销凭据并保留收件及原归属，部门/人员删除不误撤机器凭据。现有生命周期 effect 类型、seal/apply 只枚举 identity/workflow/platform-configuration，需显式接入 api-integration，不能只调用 register。与接收并发时共用组织锁，强删提交后不能继续接收。
- 观测使用受控路由模板，不把接口 UUID、消息编号、原 URL 或正文变成无限指标标签。
- 回滚优先停用接收、撤销凭据，保留已收件；迁移兼容追加，不通过删表回退。镜像回滚须核对旧版本启动和新数据可恢复读取，必要时停接收后向前修复。

## 8. 验收与生产启用

一期必须证明：授权管理员完成配置、凭据管理及回执开关维护；独立进程经真实 HTTPS 发送 JSON；持久化后按开关收到回执或 204 空正文；两种模式下正确组织内均可查完整接收记录；开关切换后的重复响应、失败告知、断网重试、冲突、撤销、停用、跨组织、超限与清理符合本文。

验收用一次性 PostgreSQL、真实 API/Worker、临时 TLS 和浏览器，不触碰预览库 55440。合成无敏感业务含义的 JSON 只验证技术收件，不称为 ERP/MES 业务联调或入库验收。

生产默认停用。启用前具备获准部署版本、真实系统公网出站能力、凭据安全交付、样本敏感信息核对、数量/大小/保留容量及对应完整备份恢复证明、具体接口启用授权。逐调用方确认能发送消息编号和原字节重试，并正确识别 201/200/204、4xx/5xx 及非 JSON 网关错误；协议不适配先调整既有集成平台或修订接口，不擅增认证/兼容平台。没有真实来源时可完成一期工程验收，真实系统联调与生产启用分别保持未完成。

## 12. 接口对接便捷化补充（2026-11-09）

负责人明确要求：地址不用难记UUID、复制按钮给出含真实鉴权信息的完整文字、凭据支持永久并可重复复制。本节覆盖首版只展示一次及仅有限期策略，沿用现有REQ0036/Issue97，不增加审批、短链服务、OAuth或发送业务。

公开地址保持既有路由`/api/v1/integrations/inbound/{endpointId}/messages`，该段可使用接口编码（例如test），也接受原UUID。鉴权先按Bearer凭据确定唯一接口/组织，再验证路径匹配该接口编码或UUID；相同编码分属不同组织时由凭据绑定区分，不改全局唯一规则。短编码大小写精确匹配，UUID大小写保持原支持；收件、去重、AAD、观测身份仍使用数据库规范UUID。

新增受控`GET /api/v1/admin/integrations/endpoints/:id/connection`，query为organizationId及可选credentialId；必须同时有integration:manage和integration:credentials:manage。返回IntegrationConnectionDto：endpoint（IntegrationEndpointDto）、credentialId、credentialName、authorization（完整Bearer值）、expiresAt（string|null）。不指定凭据时取最新可用且有密文的凭据；指定时只返回该接口的有效凭据。没有有效凭据返回原required错误；只有旧无密文凭据返回INTEGRATION_CREDENTIAL_SECRET_UNAVAILABLE。锁组织→接口→凭据，取得最后锁后复权并以当前DB时间复核有效期，读取审计与解密返回同事务，审计失败不披露；响应no-store，不额外增加确认弹窗或认证协议。

页面只保留清晰的“复制对接配置”操作，复制文字包含接口名、真实地址、POST、Content-Type、已填好的Authorization、消息编号生成/重试规则及当前回执模式；不再复制占位凭据。管理调用说明默认使用最新可复制凭据，凭据列表可复制指定凭据。密文明文仅在当前授权操作内短暂用于剪贴板，不进localStorage/sessionStorage或普通列表；异步旧作用域结果不得写剪贴板。剪贴板失败必须显示失败，不能假报成功。

迁移只给integration_credentials新增可空secret_ciphertext并允许expires_at为空；旧有限期/校验值保持。新秘密AAD为`integration-credential:<organizationId>:<endpointId>:<credentialId>`，同现有keyring轮换、备份恢复一起覆盖。旧程序不支持永久空日期，不直接回滚到旧镜像；需要回退时先停接收并保留数据，使用兼容空有效期的修复版本，或经批准按迁移前快照恢复，不能静默改旧凭据期限。

## 13. 接口删除追加（2026-11-10）

负责人在确认没有删除功能后明确“增加，抓紧搞”，批准上一条已展示的最小方案：操作栏一次确认后删除，停止接收、撤销全部关联凭据、移出正常列表，保留历史收件及审计。不增加审批、回收站或恢复平台。该要求覆盖第3节原无删除约定。

使用integration_endpoints.deleted_at逻辑删除并同事务设置DISABLED/增加version/撤凭据及写INTEGRATION_ENDPOINT_DELETED审计。接口编码只在未删除接口中保持组织内唯一，删除后可重新创建相同编码，但新接口必须新UUID和新凭据，旧token永远不转绑；保留外键、历史正文、来源及去重归属，配额仍按实际保留内容计账，Worker照原期限清理。

`DELETE /api/v1/admin/integrations/endpoints/:id`，JSON为DeleteIntegrationEndpointDto（可选organizationId、必填expectedVersion）；成功204。沿integration:manage权限、CSRF、近期认证、管理幂等及组织→接口→凭据锁序，最后资源锁后复权。首次有效删除检查CAS；同key重放及已删除再次删除成功而不重复改版本/成功审计，幂等重放仍复核当前授权。审计失败整事务回滚。旧UUID/编码机器请求提交前复查接口与凭据，删除事务提交后不能接收。

接口列表及总数排除已删除，详情/修改/凭据列表/发放/撤销/配置复制均不可再访问该接口，返回原not found；删除动作只读历史标记以支持安全重试。收件及请求检索不排除被删接口，仍由原组织/来源分权查询。前端只向有管理权者展示删除，清楚告知停止接收/撤凭据/保留历史，确认一次；失败保留原行，同一未知结果使用原幂等键重试，pending阻重复及离开，scope变化拒绝旧结果。
