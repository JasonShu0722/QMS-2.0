## 3. 导航结构

| 一级板块 | 二级入口及顺序 | 行为 |
| --- | --- | --- |
| 问题中心 | 问题管理面板、我的待办 | 替换“问题与改进”；流程设计迁出 |
| 供应商质量 | 供应商问题台账、来料检验、关键件条码校验、其余现有供应商功能 | 原供应商质量子入口更名；条码校验从制程质量迁入；其余功能维持相对顺序 |
| 制程质量 | 不良品台账 | 移除现场扫码子入口；保留原台账业务 |
| 系统服务 | 公告、个人账号、流程设计、平台管理 | 整合原公告、个人账号、系统管理入口；原管理页面及其内部标签继续作为平台管理 |
| 知识与文件 / 体系文件 | 本轮不显示 | 从内部主导航、图标轨、上下文菜单和移动导航移除 |

其他业务领域保留原结构。供应商门户保留自身导航，本轮只接入反馈按钮，不复制内部系统服务菜单。

系统服务侧栏可使用“个人服务”（公告、个人账号）和“平台维护”（流程设计、平台管理）两个非交互分组标题，不增加第三层菜单。页面标题、侧栏选中状态、顶栏和工作标签同步名称；问题管理面板继续展示跨领域的现有问题索引，不修改数据范围。

## 4. 权限与默认入口

- 系统服务按子入口的既有权限分别判断可见性；有可见子入口时显示父板块。
- 公告与个人账号沿用各自访问规则。流程设计和平台管理按各自功能权限、组织范围判断，不能互相替代授权条件。
- 父板块默认进入用户可访问的第一个子页面，不强制跳转 `/app/admin`。
- 管理权限加载失败时，保留可独立访问的个人服务入口，并保留明确失败提示；不能把加载失败解释成拥有管理权限。
- 深链接、接口鉴权和数据隔离沿用现有规则。菜单隐藏不能代替服务端拒绝。

## 5. 对象详情与编辑层级

流程编辑时侧栏持续选中“流程设计”，不再平铺一个同级“流程编辑”条目。页面顶部使用对象层级，例如：

```text
系统服务 / 流程设计 / 来料异常处理 / 草稿编辑
```

使用实际流程名和版本状态，示例文字不进入正式数据。页面标题使用实际对象名称；工作标签使用“对象名称 · 编辑”。其他详情 / 编辑场景按“板块 → 台账 → 当前对象 / 动作”规则排查，不改变业务对象、状态或未保存保护。

登录页右上角提供紧凑的“语言”和“外观”两个入口。语言继续使用共享菜单；外观打开已有显示模式与品牌色设置面板，不额外放置与之重复的主题按钮或泛化设置按钮。
