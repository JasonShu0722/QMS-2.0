# 制程不良品台账筛选聚合与工具栏紧凑化方案

## 当前问题

当前台账页面已经具备服务端分页、全局搜索、台账状态、待完善、待补配、跨页勾选、批量分类、发起问题、内部 8D、供应商草稿复制和删除能力，但这些能力都直接铺在表头以上区域。实际页面形成三到四排控件，按钮之间存在业务重复，分页总数又必须跟服务端筛选结果保持一致。

当前 API `GET /api/v1/process-quality/defects` 已支持分页、全局搜索、台账状态、责任类别、部分来源编码和两个待办状态；台账服务使用 Prisma 查询并返回 `items/total/page/pageSize`。因此不能只在当前页用前端数组筛选，也不能把表头筛选做成只改变视觉状态的假筛选。

## 本地化原则与参考取舍

本方案吸收 Teable 的工具栏密度、APITable 的表头快捷筛选、NocoDB 的字段/运算符/值模型，以及 VisActor/VTable 对固定列和大数据量渲染的性能思路。pxcharts 仅作为交互观察来源。QMS 继续使用现有 React + Ant Design + `LedgerTable`、服务端查询、权限/context、未保存保护和真实业务 API；不复制参考项目源码、CSS、图标、品牌资源或完整视图引擎。

参考项目的开源协议只用于确定能否借鉴实现：AGPL/GPL/Sustainable Use License 项目不进入 QMS 运行依赖；MIT 组件也不因视觉相似直接引入，必须先有已证实的性能消费者和独立许可/包体/可访问性评估。具体标准已沉淀到 [`qms-2.0/docs/FRONTEND-DESIGN.md`](../../../qms-2.0/docs/FRONTEND-DESIGN.md) 的“多维台账本地化标准”。

参考来源记录：

- [Teable](https://github.com/teableio/teable)：工具栏、条件筛选和视图交互观察。
- [APITable](https://github.com/apitable/apitable)：表头快捷筛选、全部/任一条件和视图状态观察。
- [NocoDB](https://github.com/nocodb/nocodb)：字段/运算符/值筛选模型观察。
- [VisActor/VTable](https://github.com/VisActor/VTable)：固定列、虚拟化和大数据量渲染观察。
- [pxcharts](https://github.com/MrXujiang/pxcharts)：高级筛选、排序和分组交互观察；准确仓库及许可证在实际引入前复核。

以上链接是参考来源，不是 QMS 运行时依赖或许可结论；实施前以对应仓库当前许可证、版本和依赖树为准。

## 目标范围

1. 保留全局搜索，聚合状态、分类、待完善、待补配及其他字段筛选。
2. 支持筛选条件的增加、删除、清空、应用和重置；筛选结果继续由服务端分页。
3. 在列标题处提供同一筛选模型的快捷入口，文本、日期、枚举和数值使用匹配的控件与运算符。
4. 将登记、筛选、发起 8D、刷新和分页/列设置压缩到稳定的单行工具区；窄屏自然换行。
5. 勾选记录后才显示批量操作栏，删除所选、清空选择、批量分类及发起 8D 不再占用默认工具行。
6. 移除台账默认工具区的“复制为供应商草稿”；不删除后端能力，若仍有业务入口需要保留，放到来源详情或专用来源选择路径。

## 推荐交互

### 默认工具行

```text
[搜索追溯码、成品编码、工单、不良描述或批次] [登记不良]
[筛选条件] [发起 8D] [刷新]                         [列设置]
```

桌面宽度足够时合并成一行；空间不足时搜索框收缩，按钮保持可点击。筛选条件按钮显示活动条件数量，例如“筛选条件 3”。没有活动筛选时不显示空的筛选面板。

### 筛选面板

```text
筛选
满足以下条件：[全部条件 / 任一条件]

[字段：项目状态] [等于] [新品]
[字段：发生时间] [晚于] [日期时间]
[字段：不良描述] [包含] [关键词]

[添加筛选条件]                 [重置] [应用筛选]
```

字段类型决定控件：

- 文本：包含、不包含、等于、不等于、为空、不为空。
- 日期时间：等于、不等于、早于、晚于、为空、不为空；日期选择器提交明确的时区边界。
- 枚举：等于、不等于、为空、不为空，选项来自受控状态值。
- 数值：等于、不等于、大于、大于等于、小于、小于等于、为空、不为空。

条件数设置有界上限（建议 10 条），逻辑只支持“全部条件/任一条件”。服务端只接受白名单字段和运算符，不接受任意 Prisma 字段、SQL 片段或任意 JSON 路径。

### 表头快捷筛选

默认列和列设置中可筛选的业务列，在标题旁显示筛选图标。点击后打开与筛选面板相同的字段编辑器，并自动定位到该列；应用后回写同一套活动条件。表头筛选不维护第二套状态，不直接使用 Ant Design 的本地 `onFilter`。

默认列和通过列设置显示的单字段列均可使用同字段的快捷筛选。产品类型按台账记录中的产品大类快照执行文本筛选。类型、成品编码、工单号、生产线编码、工序编码等可选列显示后也提供入口。组合列中的具体筛选字段通过筛选面板选择。

筛选按钮占用标题右侧预留空间，标题文字对准列中心。最小列宽应容纳文字与按钮，并保留键盘焦点、触控及列宽调整。

### 勾选后的批量操作

```text
已选择 3 条（跨页保留，最多 100 条）
[清空选择] [批量分类] [发起 8D] [删除所选]
```

该栏仅在有选中记录时出现，沿用接收记录清单的浮动/独立操作栏模式。所有动作继续使用当前版本、权限、幂等键和未知结果恢复；删除仍先预览后提交，不能因为界面收缩而绕过阻断校验。

台账默认只保留一个“发起 8D”入口；发起后在 8D 流程内部完成严重度/等级等分级处理。原“发起问题”入口不再在台账工具栏单独显示，避免同一批来源出现两个发起入口；既有 8D 权限、抽屉、后端流程和调用方继续复用，不新增第二套分级入口。

## API 与数据方案

### 查询契约

保留现有 `page/pageSize/search`，新增受限筛选集，推荐结构如下：

```json
{
  "logic": "ALL",
  "items": [
    { "field": "projectStage", "operator": "EQ", "value": "NEW_PRODUCT" },
    { "field": "occurredAt", "operator": "AFTER", "value": "2026-11-01T00:00:00+08:00" }
  ]
}
```

通过现有 GET 查询传递一个有界、编码后的 `filters` 参数，DTO 先验证 JSON 结构，再由服务层把字段映射到明确的 Prisma/SQL 条件。这样不会为了每一种字段组合不断扩展 query 参数，也不暴露任意字段查询能力。若工程现有契约规范不接受 JSON query 参数，则退回为同等白名单的重复 `filter` 参数；两种实现不改变业务语义。

### 字段映射

- 直接列字段：`occurredAt`、`shift`、`productSubcategory`、`operationSector`、`traceCode`、`lineName`、`operationName`、`description`、`defectQuantity`、`ledgerStatus`、`responsibilityCategory`。
- 已有编码字段：`productCode`、`batchCode`、`workOrderCode`、`lineCode`、`operationCode`、`materialCode`、`projectCode`。
- 快照派生字段：`projectStage` 从持久化 `projectSnapshot.project.stage` 的快照读取，不能在 `view()` 后对当前页内存结果过滤。
- `pendingCompletion`、`pendingConfiguration` 保留为受控布尔条件。

文本筛选使用转义后的大小写不敏感匹配；日期按明确时区转换为 UTC；空值判断使用数据库 `IS NULL`/空字符串口径；枚举和数值在 DTO 与领域白名单中双重校验。必要索引随真实查询计划确认，不能先添加没有消费者的泛化索引。

### 个人筛选记忆与默认条件

- 筛选条件按当前登录账号、目标组织、台账和视图隔离保存；沿用 QMS 现有个人 Ledger 偏好机制，同一账号在同一浏览器再次打开台账时，恢复该账号上一次已应用的筛选和显示状态，不写组织共享配置。
- 首次没有个人记录时，系统默认应用“发生时间为当前自然月”的筛选；月份按打开时的组织/系统时区动态计算，不把旧月份永久写成系统默认。
- 用户可以在默认当月条件上叠加其他日期条件、文本、枚举、数值和待办筛选；应用后的完整组合成为该账号下一次打开时恢复的个人条件。
- 提供“恢复系统默认筛选”动作，清除该账号的个人筛选并回到当前自然月；这不清除列宽、列序和其他台账偏好。
- 个人筛选只影响当前账号，不创建组织共享视图，也不改变其他账号的默认条件。
- 本轮不新增服务端个人偏好表；当前浏览器偏好存储不可用时只保留当前会话状态，不伪装成跨浏览器同步。跨设备同步另立需求。

### 兼容与边界

- 未传 `filters` 时保持当前请求和结果完全兼容。
- 过滤或分页变化时清除当前页勾选，跨页选择需按现有规则重新确认；不能把已选对象静默发送到新筛选结果。
- 过滤结果总数、空态文案和分页都来自同一次服务端查询口径。
- 权限、组织范围、归档排除、删除版本校验、发单和 AI/补配排除规则不变。
- 不新增台账表、不改变删除软归档、不改变既有来源身份和 Worker 行为。

## 前端实现边界

- `ProcessDefectLedgerPage` 只保留一套 `draftFilters/appliedFilters` 状态，表头快捷筛选和筛选面板都调用同一个 `applyFilters`。
- `LedgerTable` 继续承担分页、列设置、选择列和表格布局；不改共享表格的业务语义，不把服务端筛选误接成 Ant Design 本地过滤。
- 工具栏外层取消重复 Card/分隔线和嵌套边框，只保留台账主容器一层边框；筛选浮层独立拥有自己的边框和焦点管理。
- 新增筛选面板的键盘焦点、关闭、未应用草稿、加载中和错误状态；应用筛选时保留真实请求与导航保护。
- 维持中文/英文文案、窄屏、列设置、选择上限 100、未知结果重试和权限失效清敏。

## 验证范围

1. API：每种字段类型、运算符、空值、日期边界、全部/任一逻辑、非法字段/运算符、组织范围、分页总数和旧 query 兼容。
2. Web：默认工具行单行、筛选面板增删应用/重置、表头快捷入口与面板状态一致、勾选后批量栏出现、未勾选时不占行、删除/发单原请求不变、窄屏自然换行。
3. 真实 PostgreSQL：筛选结果与 `total`、快照项目状态和空值判断一致，不能只用内存 mock。
4. 真实浏览器：1440/1024/390/320 宽度，筛选浮层键盘焦点、表头日期/文本控件、选中后批量栏和删除预览。
5. 回归：制程台账删除、发起问题、内部 8D、AI 描述、补配、列偏好和旧调用方。

## 结论

方案可行，且应以“服务端筛选模型 + 单一前端状态 + 表头快捷入口复用筛选面板 + 账号个人筛选记忆”为最小完整实现。主要工作量在查询契约和服务端派生快照字段过滤，不在按钮布局；因此不建议先只改 CSS。台账默认唯一发起入口为“发起 8D”，分级在发起流程内部完成。

本轮需求由单一页面压缩调整升级为 QMS 台账通用标准的首次落地：先在制程不良台账验证筛选模型、工具栏密度、表头入口和选择后批量栏，再评估接收记录、物料主数据和组件项目映射的复用边界。标准化不意味着本轮自动改造其他清单，也不把参考项目的全部能力列入交付范围。
