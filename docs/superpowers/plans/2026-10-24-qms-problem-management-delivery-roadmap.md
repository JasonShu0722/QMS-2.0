## 2. 主路径与交付颗粒

推荐 **六个主交付 PR 节点，各自合并后立即完成对应部署核验**，不将全部成果堆到最后一次巨大上线。本文不预建六个空 PR，也不承诺强行把任何规模压成一个巨大 diff；正式开工影响分析若确需拆分，仍挂同一节点，逐 PR 合并均视作潜在生产部署，不能绕过提醒和授权。

```text
N0 获正式启动通知、核对基线 / 授权 / 维护门禁
  → N1 组织与岗位治理正式交付
      → 部署验收后准备真实试点结构 / 任职
  → N2 组件项目映射 + 共用流程配置与运行基础
      → 部署后补管理职责 / 分管及候选模板，暂不开新业务
  → N3 过程人工台账 + 内部 8D 首条完整链
      → 配置预览 / 发布绑定 / 内部过程试点
  → N4 客诉 / FAE / SQE 分析 + 新品同源完整链
      → 客诉及新品分别验收、分别开通
  → N5 供应商独立 8D 与门户完整链
      → 对外账号 / 披露验证后开供应商试点
  → N6 IMS / AI 真实接入 + 最终联合回归与闭环
      → 小范围同步 / 对账 / 扩围，按需求逐条验收关闭
```

N2 将映射和动态流程接缝作为下一完整链的配置基线，分别独立验收，不以“共享文件”掩盖耦合。N4 将新品与客户的项目阶段 / 工程师接续共同验收，过程事实仅引用，不复制计数。N6 是完整集成的放行节点，不把 N3 的人工试点声明成 REQ-0027 全部上线完成。

## 4. 开源提醒与每次发布的停点

“提醒开源”在本路径中解释为：到云端 CI / 发布边界时，主动提醒负责人确认 GitHub 仓库可见性及其影响。**不等于代理已经获准公开仓库，也不等于必须通过公开仓库才能运行 Actions。** 公开可见性与开源许可证、历史披露是不同决定，不自动新增许可证。

| 检查点 | 主动提醒时机 | 交给负责人的信息与进入条件 |
| --- | --- | --- |
| O1 首次云端检查 | PR-1 本地验证 / 双审通过，首次推送 / 建 PR 触发云端 CI 之前 | 先核对实际远端可见性、Actions 可执行条件和本轮披露变化；提醒“即将提交 PR 并运行云端检查，请确认是否按你的安排开放仓库，或保持私有使用现有获准执行条件”。选择开源前先完成当前范围安全审查，用户决定前不自动公开；用户尚未提供云端可执行前置时停在本地可提交点，不连续失败重跑 |
| O2～O6 后续节点 | 每个节点准备 PR，以及获准合并前 | 回查可见性是否变化及该节点新增披露面；已公开且策略未变就报告核验结果，不反复要求切换。若已转回私有或 CI 不满足则再次提醒本节点需采取的选择 |
| M1～M6 合并 / 生产边界 | 对应 PR 必需检查通过、合并 main 之前 | 说明 PR / 实际版本 / 迁移 / 备份 / 线上影响；提醒 main 成功会触发部署。核对本次合并与生产发布授权，开源选择不能替代发布授权 |
| D1～D6 部署完成 | 每次合并后逐次，不等最后批次 | 核对 main Foundation、部署 SHA / 镜像 / 迁移 / API / Worker / Web 健康与目标行为；前置未完成不推进后续依赖合并 |
| B3～B6 业务启用 | 人工 / 门户 / 同步正式使用前 | 人员预览、流程发布与业务版本绑定、数据 / 门户 / 同步范围独立核对；不因代码部署完就自动开通 |

每次开源前检查当前改动与必要的全历史 / 分支、Issue / PR、Actions 日志 / 制品、环境样例和业务二进制等披露面；不能仅扫描工作树就声明安全，旧审查的数量或结论也不直接复用。发现疑似泄露停止公开动作，单独处理，不为省云端费用牺牲数据安全。

原策划阶段没有创建定时提醒或后台轮询。2026-10-26负责人夜间临时授权后曾建立当前聊天heartbeat `qms`，非定时接单；负责人醒来要求恢复原规则后，已通过应用工具删除并核实配置不存在，回到正常交付检查点。既有本地验证保留，不重复启动共享验证、不并发操作Git/数据库。
