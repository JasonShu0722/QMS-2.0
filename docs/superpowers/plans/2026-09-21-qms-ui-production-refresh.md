# 现有前端统一改版实施计划

目标：按前端设计规范 v1.0 更新所有现有正式页面。用户明确限制登录页只改登录框样式，保留背景、顶部品牌与整体构图。

架构：在正式 Web 建立共享 ThemeProvider 和 CSS 变量，适配 Ant Design；现有外壳、工作标签、业务页面消费同一套主题，保留真实业务请求和权限。原型只作为参考，不导入原型代码。

## 范围及任务

- [x] 共享主题：新增 `apps/web/src/theme/`，在 `App.tsx` 接入；浅/深/系统 × 蓝/青/紫，存储容错、独立外观抽屉。
- [x] 外壳和标签：更新 `layouts/`、`work-tabs/` 及专用 CSS，完整导航/领域图标轨/上下文菜单、统一顶栏、可收起导航、按宽度收纳与检索工作页；保留权限及现有路由。
- [x] 业务页：检查工作台、台账、处理空间、任务、工作流、管理/权限/治理、账户、供应商现有入口及认证辅助页，统一表面、标题、间距和窄屏。
- [x] 登录：仅更改 `.login-panel-shell` 及其内部样式，不改变背景素材、hero、topbar 或 stage 布局。
- [x] 验证与复核：完成前端验证并执行基础验收尝试，记录失败与环境缺失；此勾选不表示完整基础验收通过。使用一次性 PostgreSQL 55449，未使用保留的 55440 数据库。
- [x] 更新前端实施指南与实际验证记录。

## 分工

采用 subagent-driven-development：公共外壳/标签、业务页面样式分别有独立实现者；主任务负责主题/全局基础/登录框、集成及测试，完成后按规格与质量两阶段审查。共享文件避免多人修改，不提交现有无关变更。

## 验证边界

本轮不新增未来业务功能、统计算法或 API，不伪造工作台数据。现有页面和权限行为必须保留。视觉验收不能代替真实登录及业务验收；不可用环境和存量失败单独记录。计划范围已由用户的整体现有界面改版请求授权，按计划直接执行。
