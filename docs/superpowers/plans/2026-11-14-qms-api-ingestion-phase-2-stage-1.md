## 开工评审与最小实现决策

1. 管理员指有效platform:admin且所在/目标内部组织正常启用，新增内部权限走已有动态投影和菜单；保留既有供应商/观察只读/节点职责边界。根与工程AGENTS、权限目录/菜单回归形成后续强制规则，不按用户名或另造超级会话。
2. 复用现有PostgreSQL和Worker；规则/配置版本快照、批次、逐行结果用独立持久化表。输入始终从受控已收正文解密，调用方不能声明组织。预览默认无业务写入；正式任务与接收在同一事务登记。保护未完成正文，终态保留可查且有界。
3. 四目标由其拥有者公开服务在传入事务内读取/写入，API接入模块不跨读私表；共有code/name和可选供应商联系字段，组件只写编码名称，不碰项目/阶段/人员。
4. 同组织接口串行锁序组织→接口→队列；每批次固定规则JSON/version、数组下标及接收原始次序。系统失败阻塞后续同接口，显式重试或取消；校验失败逐行记录可跳过；人工差异转待确认不堵全部队列，确认重新校验版本/较新事实。
5. 历史按固定时间窗口选取已存正文，不主动拉外部；初始化期间新数据接收继续排队。相同任务持久化唯一身份避免恢复重复，明确重新处理保留原因。历史/人工晚确认无来源版本时不自动覆盖较新写入，保护人工字段，空值不自动清空。
6. 权限在保存规则/正式提交和执行时复核其授权配置者及目标写权限，后台不伪造人员身份；审计同时保留机器接收与管理员配置/确认来源。过期凭据不影响已接收事实，但接口/组织停用及删除不继续入库。
7. 完整相关人员选择器清单从源码搜寻：组件ProjectPicker/EngineerPicker、制程发起8D、客户/新品内部8D、重派/责任恢复等；在既有资格和分页接口上统一姓名/部门（账号）标签与姓名查询，不改变责任归属。复用现有组件批量100条预览/共享项目影响，不扩组件上限。
