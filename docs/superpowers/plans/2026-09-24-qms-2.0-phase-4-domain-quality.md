# QMS 2.0 阶段四业务域实现计划

> **面向 AI 代理的工作者：** 必需技能链：`superpowers-zh:using-superpowers` → `superpowers-zh:brainstorming` → `superpowers-zh:writing-plans` → `superpowers-zh:using-git-worktrees` → `superpowers-zh:subagent-driven-development` / `superpowers-zh:dispatching-parallel-agents` → 子代理使用 `superpowers-zh:test-driven-development` → `superpowers-zh:requesting-code-review` / `superpowers-zh:receiving-code-review` → `superpowers-zh:verification-before-completion` → `superpowers-zh:finishing-a-development-branch`。步骤使用 `- [ ]` 跟踪进度。

**目标：** 在 QMS 2.0 已验收平台和阶段三供应商质量主链之上，按 QMS 1.0 的业务语义交付制程、客户、新品和审核四个业务域的“来源台账→正式问题→流程闭环”。

**架构：** 每个业务域拥有自己的来源台账与专业事实，通过公开领域服务调用问题索引、流程 runtime、任务通知、附件、审计和报告。制程、客户和试产外部数据使用适配器端口；MES/IMS/ERP/SAP 在字段、认证和样本核实前只保留契约，不实现真实连接。

**技术栈：** NestJS / Prisma / PostgreSQL / React / Ant Design / Swagger 生成契约 / Playwright / 真实 Worker。

**参考规格：** `docs/superpowers/specs/2026-09-24-qms-2.0-phase-4-domain-quality-design.md`；QMS 1.0 只读参考位于 `E:/WorkSpace/QMS/archive/qms-1.0/`。

## QMS 1.0 语义复核交接

- 客户质量沿用“客户主数据 → 客诉来源台账 → 退件/实物处置或实物解析 → 问题简报/8D”的分流。客户名称、严重度政策版本、解析状态和证据摘要进入来源快照；客诉台账可以完成实物处置，不因登记客诉自动生成 8D。
- 售后客诉的 VIN、失效里程和购车日期按类型条件校验；终端客户名称可选。严重度不能复制 QMS 1.0 的关键词定级，使用版本化政策和人工决策；7/10 工作日从正式发单开始，依赖工作日历、时区和日历版本证据。
- 客户质量外部 ERP/SAP/IMS 只保留适配器端口、字段映射、同步批次、幂等和失败审计，未核实字段、认证和样本前不启动真实连接。
- 审核管理分为年度计划/延期审批、模板/不可变版本、固定版本执行、检查表评分、NG→NC 原子生成、整改验证和客户/二方审核逐条导入。模板发布后不可变，执行固定模板版本，NC 关闭必须经过验证；提醒和逾期升级由 Worker 按持久化截止时间运行。
- QMS 1.0 的负数外键、可变 JSON 模板、直接文件路径、自然日 SLA 和模拟 IMS 追溯均不得复制；QMS2 使用显式来源关系、文件对象引用、工作日历和真实适配器未启用状态。

## 子代理驱动执行编排

阶段四采用“主代理协调 + 每项任务一个全新实现子代理 + 两阶段审查”的方式执行。主代理负责冻结共享契约、分派任务、整合生成契约、处理跨模块冲突和运行联合验收；子代理只修改自己拥有的目录，不直接改公共导航、`AppModule`、权限目录、模块边界、生成契约或阶段文档。

每个子代理必须按以下顺序完成：

1. 主代理向全新子代理提供完整任务文本、领域背景、接口依赖、文件所有权和验证命令；子代理先把任务拆成可逐项验证的 TDD 微步骤，不以自行浏览计划代替上下文交接。
2. 每个微步骤先运行测试并确认因目标功能缺失而失败，再做最小实现、运行同一测试确认通过，并运行邻近回归；记录红灯、绿灯命令与结果，最后自审。
3. 实现完成后由独立子代理进行规格合规审查；不通过时由原实现子代理按 `receiving-code-review` 核对证据、修复并重新审查。
4. 规格审查通过后由独立子代理进行代码质量审查；Critical/Important 问题修复并重新审查，Minor 问题记录；技术误判须用代码或测试证据说明。
5. 两阶段审查都通过后，主代理检查实际 diff、退出码和测试输出，再整合该任务并重新运行受影响测试；`DONE_WITH_CONCERNS` 先核实疑虑，`NEEDS_CONTEXT` 补全上下文，`BLOCKED` 必须拆小任务或改变方法后重派。

审查交接记录基线和当前 Git SHA，并附未提交 diff；不因本计划自行提交。全部任务完成后再分派一次跨域整体审查，逐项核对规格。完成前独立执行 `verification-before-completion`，将环境、命令、退出码、PASS/FAIL、限制和证据写入 `qms-2.0/docs/PHASE-4.md`；仅在验证通过后按 `finishing-a-development-branch` 检查工作区状态，未经用户选择不合并、推送或丢弃成果。

| 1A：新品基础 | 1 个 `new-product-foundation` 代理可与波次 1 并行 | 只实现项目、经验教训、阶段评审、试产批次和人工指标；不得在制程来源查询契约冻结前实现跨域遴选。 |

| 3：联合验收 | 1 个 `phase-4-acceptance` 代理 | 四条业务链全部合入后执行真实 PG、Worker、附件、浏览器、权限撤回和失败恢复；主代理维护阶段记录。 |
