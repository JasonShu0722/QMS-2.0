## 批准行为

- 制程列表、详情和批量删除确认显示目标或数量与必要影响，取消或确认即可。服务端继续预检和提交复查，保留组织范围、权限、正式引用、版本、软删除、审计和幂等。可选旧原因继续兼容。
- 制程列表支持 500、1000 条每页和当前页全选，单次删除最多 1000 条，整批提交。发起 8D 继续最多 100 条。筛选范围变化清理过期选择，删除结束刷新计数与页码。
- 发生时间显示日期，悬停显示同一时区的完整时间，筛选和排序使用完整值。缩窄发生时间、板块和不良数量三个默认列宽，保留自定义宽度、筛选和常驻横滚。
- 删除确认横展排除账号、职位。逐个领域盘点草稿、已发单和已审批的流程，确认节点依业务状态、权限、撤回、审批和引用要求。涉及连带影响时显示必要影响。逐项记录可执行删除节点以及由流程要求使用归档、撤回或作废的状态。

## 实施与验收

1. 制程 API。调整列表及删除上限，审计兼容旧原因，控制千条读写查询量。先用现有测试补边界失败用例，再运行定向真实 PostgreSQL 验证。
2. 制程 Web。先补精简确认、千条分页选择和日期列用例，修改制程专属入口，复用共享台账分页、列设置和日期格式。验证大页、末页、阻断和重试。
3. 删除横展。盘点 API 和可达 UI，记录三个状态实际流转，在已有业务删除能力的执行节点统一简短确认。对不同领域保持其事务及资格规则，按实际缺口补回归。
4. 生成 Swagger 契约，执行契约检查、治理、受影响测试和构建。真实 PostgreSQL 与浏览器核对千条读取、选择、原子软删和审计，核对权限、版本、引用冲突、末页回退和缩列常驻横滚。规格、质量审查有反馈时修复并重验。
5. 提交推送，建立同 Issue 的 PR。等待所有必需检查覆盖当前提交和基线后 squash 合并。查主线检查、部署日志、运行 SHA、服务健康和同版本最终业务回归。记录交付闭环，按验收及实际授权处理 Issue 关闭和协作台账。公共危险确认设计沉淀至前端设计规范。

## 流程节点覆盖

| 流程 | 确认与状态边界 |
| --- | --- |
| 主数据与台账设置 | 供应商、客户、物料、组件项目映射保留所选数量与删除结果，组件项目映射补充共用项目保留提示。客户关联、工序板块和个人问题视图提示具体对象及直接影响。 |
| 组织与部门 | 普通删除依现有依赖校验。强制删除依实时影响预览、资格和原请求重试。账号、职位不纳入本轮。 |
| 附件与 API 接入 | 可删除附件提示文件名、下载和历史影响，受流程保护证据维持只读。接收接口、入库规则、接收记录分别提示对象或数量，凭据撤销影响仅在接口删除时提示。 |
| 已发单、已审核流程的退出节点 | 已关闭的旧版客诉、适用状态出货报告和已发布公告使用归档确认。特采草稿、已提交或已批准记录依既有撤回资格。新品量产移交依原风险说明、审批及前置条件后归档。 |
| 留档流程 | 正式客诉台账、供应商与内部 8D、审核、标准、ASN、PPAP、准入、PCN、检验、绩效目标和流程定义检查后，继续使用对应的关闭、审批、纠正、修订或发布节点。撤销轮次或延期申请作用于申请本身。历史角色由授权影响预览和显式确认管理。 |
