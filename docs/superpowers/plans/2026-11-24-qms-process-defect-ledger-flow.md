## 1. 业务流转

| 展示顺序 | 板块 | 业务内容 |
| --- | --- | --- |
| 1 | 表单登记 | API 传输落库或人工登记，进入同一制程不合格台账。 |
| 2 | 分析进度维护 | 在原单维护分析进度。 |
| 3 | 责任判定 | 在原单记录责任类别。涉及物料不良时，按物料明细登记不良物料信息并指定责任 SQE。 |
| 4 | 处置维护 | 每条台账的处置方案为单选（返修、报废、让步放行），处置进度以文字录入。填写完成时间时，时间选择器默认带出当时的日期和时间，可手动改选后保存。 |
| 5 | 台账关闭判定 | 由有权操作关闭环节的人员按业务实际判断是否关闭。 |

表中顺序用于页面展示。登记落库后，各板块由有权限的人员按实际进展独立维护，可先记录处置，再补充分析或判责。

后续如需将处置进度改为状态切换，再单独开发。

责任 SQE 在自己负责的物料明细上完善复核情况。`RETURN_ANALYSIS` 沿用台账现有文案「返厂解析」，表达该物料的返厂分析情况。物料处理信息在对应明细上查看。

处置维护、台账关单与物料复核各自独立。有关闭权限的人员可在处置未完成或物料未复核时按实际情况关单。处置完成后仍由有权限的人员判断是否关单。台账关闭后，各板块仍可按权限维护，责任 SQE 仍可完善自己负责的物料复核。后续维护保留原台账关闭状态。

### 不良物料信息登记

- 在责任判定板块的物料明细中填写物料编码、供应商名称和物料批次。输入物料编码后，按当前组织的物料主数据精确匹配并自动显示物料名称。输入供应商名称后检索供应商档案，由用户选定对应记录。供应商代码随名称显示为「供应商名称（供应商代码）」，归在同一字段。
- 在当前物料明细增加「扫描批次标签」，复用制程台账现有扫码组件。标签以 `&` 分隔，字段顺序为 `ReelID&数量&供应商编码&批次&物料编码&生产日期`。取第 2 和第 3 个 `&` 之间的供应商编码、第 3 和第 4 个之间的批次、第 4 和第 5 个之间的物料编码。按供应商档案的业务编码精确匹配供应商，按物料编码带出物料名称，并回填当前明细的物料批次。
- 扫描图中示例时提取供应商编码 `2000428`、物料批次 `221114`、物料编码 `D0.800.R1042-03`。扫码回填后由用户确认并保存。结构错误或需提取的字段缺失时提示重新扫描并保留表单原值。主数据未匹配时提示核对相应编码，可更正后重新检索。

### 批量维护

勾选多条已登记的台账后，可按板块批量维护分析进度、责任判定、处置和关闭判定。涉及物料不良时，不良物料信息、责任 SQE 指派和复核情况也支持批量维护，操作落实到对应物料明细。批量维护范围从登记落库后开始，表单登记及登记字段不纳入。每次操作只更新所选板块中明确提交的字段。

## 3. 流程配置与权限

- 在管理控制台的「制程不合格台账」配置中按板块维护「可操作岗位」。每个板块均可多选，命中当前组织对应板块任一已选有效岗位即可更新该板块。服务端对每项写入校验组织、岗位和数据范围，业务端据同一规则提供操作入口。
- 物料信息登记和责任 SQE 指派属于责任判定板块。物料复核按该条明细上实际指派的责任 SQE 授权，沿用现有有效身份、数据范围和物料复核权限校验。
- 批量维护与单条维护使用同一权限规则。服务端逐条校验台账数据范围和所操作板块的权限，批量复核还须逐条核对对应物料明细的责任 SQE。
- 管理员在适用组织范围内配置岗位。配置读取、保存、授权与撤权一起验收。岗位配置使用现有岗位和受控管理入口，记录实际修改人和变更内容。
- 组织首次保存岗位配置前沿用现行台账权限，避免切换时中断办理。首次保存后，各板块以该配置和账号的有效任职判定，空岗位板块不可维护。原有功能权限、组织范围和 SQE 指派同时有效。

## 4. 实施顺序

1. **台账数据与办理**。在现有制程台账上补充单选处置方案、文字进度、可手动选择的完成时间及历史记录。首次填写完成时间时以选择当时的时间为默认值，编辑已有完成时间时回显原值。复用既有批量判责及各板块的业务规则，为登记以外的各板块提供单条和批量维护能力。在责任判定的物料明细接入物料主数据、供应商档案和批次标签扫码录入。
2. **板块岗位配置**。实现岗位多选与保存，各板块写入与对应配置接通。排查单条和批量维护等已有写入入口，确保同一板块使用同一授权判断。API 入库继续使用接口授权及映射规则，涉及已有记录更新时保护人工维护的分析、责任、处置和物料信息。
3. **流程管理页面切换**。核对旧编辑器相关代码和使用发布版本或绑定的业务调用方，接续仍需使用的维护操作。替换首页并接入制程台账岗位配置，撤下旧路由和编辑器专用代码，记录 Git 封存位置，同步菜单、链接、受控访问与工作台说明。
4. **联合回归**。覆盖人工录入和 API 来源、板块独立维护、登记以外各板块的批量维护、物料与供应商检索、批次标签扫码、处置方案单选、处置与关单独立、关闭与复核的两种顺序、岗位授权变更、旧路径下线及在途实例。核对首次配置对现行组织岗位的影响，以及仍依赖既有版本和绑定的发单能力。处置字段使用追加迁移，API 契约由 Swagger 生成。
5. **交付与验收**。获准实施后接续 #169。完成规格和质量审查、受影响的 API 与 Web 测试、一次性 PostgreSQL 集成、正式页面验证、契约检查、构建和治理检查后提交关联 PR。发布后的版本核验、最终回归、Issue 关闭及适用的台账回填按各自授权执行。正式口径随验收记入制程台账与流程管理的现有文档。

供应商板块联动在后续需求中策划。相关正式 8D 继续通过其现有业务入口办理。

## 5. 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 两种登记来源 | API 落库与人工登记单据均能在原台账维护分析、判责、处置方案、进度和完成时间。 |
| 板块岗位多选 | 两个已选岗位均可更新该板块。只持有另一板块岗位的人员更新该部分时被拒绝。撤销配置后，原权限不再生效。 |
| 板块独立维护 | 分析和判责尚未填写时，获授权人员可保存处置数据，获授权的分析及判责人员随后可补充各自板块。 |
| 台账批量维护 | 勾选多条记录后，可分别批量维护分析进度、责任判定、处置及关闭判定。登记字段、未选记录和未提交字段保持原值。关闭操作由具备关闭权限的人员发起，逐条校验权限。 |
| 处置方案单选与批量维护 | 可勾选多条台账并统一设为报废，保存后每条选中记录只保存一个处置方案。编辑处置进度和完成时间同样支持单条和批量操作。批量写入限于所选且有权操作的记录。 |
| 处置进度与完成时间 | 可直接填写并保存处置进度文字。选择填写一个空白的完成时间时，默认带出当时的日期和时间，可直接确认，也可改选后保存。再次打开已保存记录时显示原完成时间。 |
| 不良物料与责任 SQE | 有判责权限可按物料明细批量维护不良物料信息和责任 SQE。责任 SQE 可批量完善自己负责的多条明细，批量或单条操作他人负责的明细均被拒绝。「返厂解析」显示在实际物料明细上。 |
| 物料与供应商检索 | 输入物料编码带出正确的物料名称。按名称找到并选定供应商档案，同名候选可通过括号中的供应商代码区分。检索遵守当前组织的主数据访问范围。 |
| 批次标签扫码 | 扫描示例标签，验证三个字段的位置、主数据带出的名称及当前物料明细保存结果。结构错误提示重新扫描并保留原值，主数据未匹配时提示核对编码。 |
| 关闭与后续维护 | 处置未完成时有权人员仍可关单，处置完成后台账保持原关闭状态。先关闭后复核、先复核后关闭均可办理。关闭后维护分析、处置或复核时，原关闭状态保持有效。 |
| 管理权限与已有数据 | 有效平台管理员在适用组织内可配置，未授权人员被拒绝。既有台账和原来源引用可查询，选取受影响的 8D 路径回归。 |
| 页面替换与清除 | 从管理菜单进入新流程管理首页。首期仅展示「制程不合格台账」一项配置，打开后可配置并保存各板块岗位。 |
| 旧编辑器下线及封存 | 直接访问旧页面和版本详情路径时显示未找到。站内导航及登录回跳清除相应旧路径，活动构建移除旧编辑器专用代码，记录的 Git 提交及源码路径可用于查阅。 |
| 存量流程接续 | 仍需维护的绑定可通过保留入口操作。已启动实例按原版本继续办理，仍使用存量版本和绑定的 8D、PCN 及审核发单分别核验。 |

## 6. 后续业务流程梳理

以制程不合格台账为首个样例。后续每个业务流程先按以下口径梳理，再在开发时将业务办理和「流程管理」中的对应配置项一并交付。

1. 梳理单据来源、业务板块、展示顺序，以及各板块维护的字段和操作。
2. 为各板块明确可操作岗位的配置范围，岗位可多选。涉及指派到人的操作，明确由谁指派、被指派人可维护哪些内容。
3. 明确哪些板块支持单条和批量维护，以及批量操作针对台账记录还是具体明细。
4. 分别梳理关闭、复核及其他业务动作的触发条件，明确关闭后可继续维护的内容。

客诉台账按这套口径单独梳理，具体板块、字段和权限按客诉业务确定。

## 7. 本地审查与验证记录

- 规格审查核对了分板块岗位、登记表单提交范围、物料名称精确匹配、扫码失败保留原值和详情展示顺序。首次审查发现的问题已修订，候选复核接续执行。
- 质量审查发现岗位撤权与在途写入的事务竞态，以及物料主数据读取权限、附件回显、物料删除和存量发单版本查询的兼容问题。岗位写入提交和幂等重放在组织的配置锁内重新读取有效权限，已补充真实 PostgreSQL 并发回归。
- PostgreSQL 18、RustFS 和 ClamAV 隔离集成共 43 项通过，覆盖人工登记、IMS 入库、五板块权限和制程 8D 链路。后续变更使用独立 PostgreSQL 重跑台账与配置用例，28 项通过，含撤权并发、主数据授权和物料明细移除后的复核历史。
- Chromium 已验证新版流程配置岗位多选、保存与重载、未授权人员拒绝和旧链接下线，也验证了关闭后继续处置与分析、登记抽屉控件布局。批次标签解析使用示例与负例验证，实物相机待验。
- PR 首轮检查发现两项 PCN 新增用例超时，调整后保留候选筛选和手填 ID 发单覆盖。独立复核发现登记保存后的附件回显问题，已补回归并修复。Web 定向验证通过，涵盖登记编辑 19 项、AI 描述 9 项及 PCN 14 项。
- PR 审查发现人工采纳 AI 建议也会修改登记字段。人工采纳及幂等重试纳入登记岗位权限，失去登记权限的操作者重新整理时只生成建议。回归覆盖采纳、撤权、重新整理和保留可读详情。
