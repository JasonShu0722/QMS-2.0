# QMS 2.0 阶段五覆盖补齐与分析增强实施计划

> **面向 AI 代理的工作者：** 必需子技能：使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 按 QMS 1.0 对照和用户决策，建立 QMS 2.0 阶段五覆盖台账，并分波次交付质量数据、供应商扩展、客户/制程、审核增强、系统效率与三坐标检测。

**架构：** 阶段五总计划只协调边界、依赖和验收；每个波次进入实现前必须拥有独立规格和子计划。领域模块拥有专业事实，通过公开服务接入问题索引、Workflow、任务、附件、审计和报表平台。外部系统通过适配器端口进入，未核实字段、认证和样本前不启动真实连接。

**技术栈：** NestJS / Prisma / PostgreSQL / React / Swagger generated contracts / Playwright / 真实 Worker / 真实对象存储与扫描服务。

---

## 范围和顺序

1. 5.0 覆盖台账与状态治理。
2. 5.1 质量数据与指标基础。
3. 5.2 供应商质量扩展。
4. 5.3 客户、制程与 8D 补齐。
5. 5.4 新品、审核、移动和报告增强。
6. 5.5 公告、签名、通知规则和任务管理增强。
7. 5.6 三坐标检测申请、审批、排单与进度。
8. 5.7 后续/不接入项决策记录。

- 不复制 QMS 1.0 FastAPI/SQLAlchemy/Vue 代码或旧表结构。
- 不以 Mock、假同步、客户端扫描状态或跳过外部接口替代真实证据。
- 不在公共问题索引中加入供应商、索赔、仪器或成本领域的专业大字段。
- 不在没有用户决策和迁移演练前导入 1.0 业务数据。
- 不把 AI 建议、Feature Flag、配置检查或 Compose 校验描述为生产能力。
