# 制程不良品台账筛选聚合与工具栏紧凑化实施计划

## 当前状态

2026-11-19：负责人已确认本计划全部业务口径并授权持续至整体实现、PR 检查验收、合并部署。目标分支 `codex/process-defect-ledger-ai-filter`，基于已发布主干 `7bb6860`；本轮同时接续 API 多字段变量绑定和台账服务端筛选/个人记忆。

## 已核对的现状

- 前端入口：`apps/web/src/features/process-quality/ProcessDefectLedgerPage.tsx`。
- 当前筛选状态：`search`、`ledgerStatus`、`pendingCompletion`、`pendingConfiguration` 四组独立状态。
- 当前默认工具栏还包含内部 8D、供应商草稿复制、发起问题、选择统计、清空选择、批量分类和删除；最终口径只保留一个“发起 8D”，分级在发起流程内部完成。
- API 查询：`ProcessDefectQueryDto` 与 `process-defect-ledger.service.ts` 已支持分页、全局搜索、部分编码、状态、责任类别和待办状态；项目状态来自持久化快照，不能仅在前端过滤当前页。
- 共享台账已有选择后操作栏可复用，接收记录清单已有筛选条件折叠与选中操作栏模式可参考。

## 推荐拆解

1. 冻结字段白名单、运算符、全部/任一逻辑和唯一“发起 8D”入口口径。
2. 为 API 增加受限筛选 DTO、规范化解析和服务端查询，覆盖快照项目状态及分页总数。
3. 在台账页建立唯一 `draftFilters/appliedFilters` 状态和筛选面板。
4. 将表头筛选入口接到同一筛选模型，不启用本地数组过滤；按账号/组织/台账/视图保存已应用筛选。
5. 将选择后的批量动作移到独立操作栏，移除默认工具区的供应商草稿复制。
6. 合并工具栏边框和间距，补桌面/窄屏几何与键盘焦点验证。
7. 运行 API/Web 定向测试、真实 PostgreSQL、契约生成/检查、lint/build、治理和真实浏览器回归，再进入独立 SPEC/QUALITY 与交付流程。

## 本地化标准落点

- 交互借鉴 Teable/APITable，保留 QMS `LedgerTable`，不引入多维表格整套运行时。
- 筛选结构借鉴 NocoDB，收敛为 QMS 白名单字段、类型化运算符、全部/任一逻辑和有界条件数。
- VTable 的虚拟化只作为后续性能评估，不进入本轮；当前服务端分页和每页上限不构成替换理由。
- 参考项目的许可证、依赖和品牌资源不进入产品；外部代码若未来确有必要，单独做许可、包体、供应链、可访问性和真实浏览器审查。
- 该标准后续可复用于 API 接收记录、物料主数据和组件项目映射，但每个调用方仍需保留自己的权限、查询字段、分页上限和危险操作语义。

## 已确认的业务口径

- 台账只保留一个发起 8D 入口，发起时在 8D 流程内部做分级处理。
- 多字段组合中的 API 来源字段绑定变量，变量供提示词调用；提示词应用不重复配置 API 来源路径。
- 筛选条件按账号个人保存；首次无个人记录时默认当前自然月，用户可以叠加其他日期和筛选条件；支持恢复系统默认筛选。
- 首批表头筛选字段按设计文档建议范围执行。

## 不在本轮默认范围

- 不新增组织共享筛选视图、共享筛选模板、后端任意字段查询、全文检索引擎或报表导出；本轮只保存账号个人已应用筛选。
- 不删除内部 8D、发起问题、供应商复制的后端服务；台账默认入口只保留发起 8D，分级在 8D 流程内完成。
- 不修改删除语义、权限、来源身份、AI/补配 Worker 或数据库业务字段。

## 当前无阻塞确认项

本轮已确认的业务口径足以进入实现；分级选项沿用现有 8D/严重度流程，不另起一套等级字典。若实现过程中发现现有 8D 流程缺少承载字段，再针对该具体契约差异单独沟通。
