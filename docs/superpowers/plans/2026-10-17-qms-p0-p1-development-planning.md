## 已确认的业务决定

### REQ-0013：记住登录与 MFA

1. 普通账号记住登录目标为 30 天；管理员勾选记住登录后为 7 天，不因关闭 MFA 被当作普通账号而延长到 30 天。
2. 每个管理员在自己的个人账号安全设置中管理 MFA，不建设全站一键关闭，也不授予代他人调整的能力。
3. 默认保持管理员 MFA 保护，本人可以开启或关闭；开关必须影响统一服务端判定，不能仅修改页面状态。
4. 关闭要求近期完整认证、二次确认与审计；已开启时使用密码及当前验证码或恢复码。切换后使旧会话及未完成挑战失效，重新登录。
5. “是否要求验证”与“是否绑定验证器”分离，关闭开关不自动解绑；重新开启时验证已有验证器，未绑定则先完成绑定。
6. 保留密码校验、限流、功能与组织权限及高风险操作的近期认证；7 天会话不等于 7 天免除所有敏感操作验证。

未勾选时沿用 8 小时、固定到期不滑动续期属于当前建议，尚未单独冻结；管理员权限认定、角色显式 MFA 要求与本人开关的有效策略在正式设计中统一推导，不让关闭开关失效，也不扩大为其他账号的策略变更。

### REQ-0014：批量建号与密码维护

1. 批量建号逐行提交，允许部分成功；逐行返回原行号、账号、结果和错误原因。账号、审计和必要事件在同一行事务内提交，失败行不留半成品。
2. 重试不得重复创建已成功账号；同幂等键同内容重放复用结果，不同内容拒绝，修正后的数据使用新请求。
3. 无权限、格式不合法、整批超限等前置错误整批拒绝，不开始创建。每行仍需在事务中复验权限与组织范围。
4. 随机初始密码作为临时密码，新账号首次登录必须改密，完成前不能访问业务接口。
5. 提供不含密码的账号清单下载，以及账号与有效临时密码对应清单下载；支持单项复制账号、单项复制临时密码，并有结果反馈。
6. 不限定只能点击一次；本次页面可重复复制/下载，后续页面仍可查询、复制和下载有效临时密码。
7. 管理员使用已有账号创建/重置权限及组织范围，不为复制或下载另设专门权限或审批；列表读取权限不能自动视为密码读取权限。
8. 系统签发的临时密码加密保存，明文不进入 URL、日志、审计、浏览器持久缓存或 Git。用户完成改密或临时密码到期后清除可恢复内容，不导出已失效密码。
9. 用户自行设置的长期密码继续只存不可逆哈希，不提供查询原文；用户忘记密码时管理员可直接生成或设置新的临时密码。
10. 管理员直接重置时旧密码立即失效、撤销目标用户现有会话、记录审计，下次登录强制改密。现有凭证兑换流程不因此自动删除。

临时密码具体有效期、到期后的登录行为及加密记录与幂等重放的版本绑定需要在正式设计中收敛；不得先自行选一个业务期限。并发本人改密、管理员重置、旧批次下载和幂等重放必须避免重新返回或恢复已失效的临时密码。

### REQ-0015：供应商导入与组织重新策划

1. 负责人明确：批量导入供应商清单时不同时创建尚不存在的供应商企业组织；撤回前一轮自动补建组织的候选建议。
2. 供应商企业组织部分需要重新策划；供应商通常只需个别“接口账号”，不能据此建设完整供应商部门、岗位或人员组织树。
3. 负责人确认“接口”指供应商人员，但对外名称仍为“供应商用户账号”，不另造“接口人账号”产品用语。它是人员门户账号，不是 API 机器凭据；释义同步至既有业务术语入口。
4. 不开放供应商注册；同一家供应商可以有多个用户账号，均由我方管理员创建。不能据此开放供应商自行邀请同事、创建账号或授予账号管理权限；正常个人改密等已有自助能力不受此限制。

候选方向是供应商档案与登录身份分离：清单管理商业资料，只有实际需要外部协作的供应商才按需开通少量账号；是否保留后台企业隔离实体以及如何映射由正式设计决定，不把隐藏组织创建当作满足“不自动创建”的替代。

首期界面与技术候选方案：在供应商档案中提供管理员按需建立、关联、停用供应商用户账号的入口，复用本轮临时密码与首登改密能力，按账号保留独立操作留痕；具体页面入口和底层企业映射仍由正式设计收敛。管理员创建、允许一家多账号及不开放注册已确认，不重复要求批准。

当前代码的 `SupplierBusinessProfile.supplierOrganizationId` 必填，创建服务要求关联已存在的 `SUPPLIER` 组织；门户问题、附件和通知依赖企业归属及复合约束。因此“仅取消导入时自动创建”不等于已实现档案独立维护。不能简单删除组织校验、把所有供应商账号放进同一共享组织或扩大通用权限；须检查既有问题、PCN、附件、通知、账号归属和历史数据迁移，保留企业之间的拒绝边界。

### REQ-0015：物料一期范围（已确认）

1. 负责人确认沿用现有物料编码，相关叫法差异不构成新建编号体系或新业务对象的理由。
2. 负责人随后明确：“一期先只做物料编码和物料名称两个，后续如有延伸再延伸开发。”首期业务录入、列表和导入模板围绕这两个字段，不再要求提供表头才继续策划。
3. 单位、规格型号、分类、额外业务状态等未获批准的扩展字段不纳入首期，也不先做空入口、动态字段配置或扩展框架；后续实际提出扩展时另行策划。
4. 来源区别保留：Codex 最早提出的名称、规格型号和单位仅为通用候选，已经撤回；本轮物料名称纳入范围的依据是负责人本次明确确认，不是此前机器人初稿或清单证据。
5. 内部标识、组织隔离、版本并发、幂等和审计等必要技术机制与业务字段分开设计，不将其变成新增业务录入列。编码唯一范围和导入重复处理按领域规则收敛，不借技术设计追加业务属性。

### REQ-0015：重复编码导入（已确认）

1. 供应商、客户和物料批量导入命中已有业务编码时，均跳过该行并在结果中提示重复，不自动覆盖已有资料。
2. 需要修改既有资料时，通过对应维护页面执行受控更新；导入首期不兼作批量更新工具。
3. “跳过并提示”只针对已存在编码的重复行；格式错误、权限不足、组织范围越界等仍按逐行错误返回，不能以重复提示掩盖其他失败原因。
4. 导入结果需区分成功新增、重复跳过和校验失败，保留原始行号；具体是否允许同一批其他合法行继续提交，沿各领域的安全事务与批量上限设计，不直接套用账号批量建号口径。

### REQ-0015：外部平台接收仅预留（已确认）

1. 负责人对“一期只预留 API 对接契约，暂不开放实际接收接口或启用数据同步”明确回复“是的，只做预留”。
2. 首期不挂载可用的外部数据接收端点，不启用自动同步、外部网络调用或同步 Worker 任务；不创建或分发外部机器凭据，也不把供应商人员账号当作机器身份使用。
3. 预留边界以对接说明和未启用契约表达，说明未来的数据对象、接入边界及认证/幂等/冲突规则的设计位置；没有协议资料的细节保持未启用，不编造已验证的 ERP/MES 等接口契约。
4. 不将实际请求量、同步成功率或投递队列监控计入一期已交付范围；不为预留伪造监控数据或额外建设无实际数据的监控系统。原始需求中的可视化设想保留为后续真实接入时的扩展方向，不声称已实现。
