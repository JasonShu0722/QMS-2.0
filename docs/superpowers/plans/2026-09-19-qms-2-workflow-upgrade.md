# QMS 2.0 简报升级 8D 实现计划

## 目标与边界

依据阶段二设计，升级保留问题 UUID、报告编号、来源及证据引用；创建新的固定版本流程实例，保留旧实例、动作、通知及领域修订。专业字段和映射归领域适配器，公共平台不读写供应商内部表。不访问其他用户任务。实现位置为 `D:/WorkSpace/QMS-2.0/qms-2.0`。

依赖 P2c 独占领取和统一锁顺序、P3 附件授权、P4 工作空间。没有注册生产领域适配器时默认拒绝；中性领域仅在测试支持模块与临时 PostgreSQL schema 中存在，不加入生产 AppModule，不用环境开关开放测试入口。

## 历史归属与迁移

- [x] WorkflowInstance 新增稳定、不可变的 problemIndexId 历史归属。当前 ProblemIndex.workflowInstanceId 只表示当前实例。组织+问题+实例复合约束禁止同组织不同问题串联。
- [x] 从明确当前一对一关系回填历史归属；孤立或歧义数据必须显式报告，不从编号或任意事件 payload 猜测。若保留 legacy null，则运行、升级及读取均默认拒绝。
- [x] 新增 WorkflowUpgrade：前后实例唯一、问题/组织/操作者/时间/原因、幂等键及请求摘要/响应、前后问题版本、映射版本、领域修订引用、受限映射摘要。前后实例不可相等且属于同一问题。
- [x] 不扩展 WorkflowMutation 的合法动作协议；升级有专用回执，新实例使用现有合法 START mutation 与 WORKFLOW_STARTED。

已知迁移边界：只对能由当前一对一关系唯一证明的问题实例回填 `problem_index_id`；未解决的 legacy 实例保留 NULL 并输出 `WORKFLOW_HISTORY_UNRESOLVED`，后续 runtime、升级和历史读取默认拒绝。`problem_indexes` 当前实例复合外键以 `NOT VALID` 添加，避免把未知旧数据误判为可信历史；约束继续保护新写入，但旧数据治理需另行完成，不能从报告编号、Outbox 或审计 payload 推断归属。

## 领域协议

新增 WorkflowUpgradeService、类型及精确领域注册表。输入仅有会话身份、问题 ID、预期问题/旧实例/领域版本、当前节点、原因、幂等键和 traceId。目标已发布流程由领域绑定解析，浏览器不能任意指定版本。

适配器在同一事务内证明资源授权及当前简报类型、解析合法 8D 目标、执行版本化显式映射与领域 CAS、返回不可变前后修订和证据关系。不接受通用任意对象替代 8D 表单。人工填写或有意清空的目标值（包括 false、0、空字符串、null）均保留；只有明确未设置字段可复制。映射摘要仅含字段标识与 COPIED/PRESERVED/UNMAPPED 等结果，不记录专业正文。

## 单事务流程

1. 校验输入，取得幂等锁；命中回执仍复核当前资源权限，摘要不同返回 409。
2. 按 problem → old instance → current tasks 锁定，所有等待后重验会话、安全版本、节点资格、独占领取、预期版本。
3. 限定当前 RUNNING 简报、未关闭/归档、允许升级节点；他人有效领取、已升级、旧实例被替换均拒绝。
4. 验证目标已发布固定版本及合法起点，执行领域映射与版本 CAS。
5. 创建独立 instanceKey 的新实例；提取普通 start 与升级共享的内部创建/START 回执逻辑。
6. 旧实例设 CANCELLED 并递增版本，旧未完成任务设 CANCELLED 并递增版本；保留原领取与全部历史事实。
7. 使用问题旧版本和旧实例指针 CAS 切换当前实例，新状态由新起点决定。
8. 写升级事实、审计、START 回执与 Outbox；任一步失败全部回滚。绝不先清空旧指针再调用普通 start。

升级事务不逐条锁定旧 Outbox，避免与 Worker 的 event → instance 锁序形成死锁。领域回调不得先锁领域再反向请求问题锁。

## 迟到事件与读取

- [x] Worker 先验证 payload、receipt、固定版本、节点及稳定历史问题归属。真实已替换/取消实例的 START/ACTION 事件成功确认，不创建旧任务/通知；伪造或归属不一致事件仍失败。
- [x] 定时事件同样验证历史归属后对非当前/取消/非本轮实例静默确认。旧 FAILED 事件在管理列表保留，授权重试无业务副作用。
- [x] Outbox 管理归属 JOIN 稳定 problemIndexId，不再只依赖当前指针；保留 receipt 校验。
- [x] 历史通知保留送达/已读事实，进入旧实例时只读并标示升级。当前动作继续要求当前指针，历史资格不能执行旧节点。
- [x] 工作空间返回服务端 canUpgrade、预览映射/保留项、预期领域版本、升级历史和实例链；报告读取对应领域修订及当时固定流程版本。
- [x] 追溯先授权问题，再按可信关系及 resourceType 查询问题、实例、任务、升级和证据，不能直接使用客户端资源 ID 集合。

## 验证

- [x] 真实 PG：正常升级保留 UUID/编号/来源/证据，旧任务取消，新固定版本唯一；人工值/有意清空均保留。
- [x] 回滚：领域回调、审计、START 回执、Outbox 任一步失败全部回滚。
- [x] 幂等：同键重试一次、不同摘要 409、不同键并发仅一个胜者；与领取/释放/提交/关闭竞争不双执行。
- [x] 实时权限：等待后撤权、撤会话、组织 A/B 隔离、归档/已 8D 拒绝，回放也授权。
- [x] 事件：旧 START 尚未投影即升级、旧 ACTION 乱序/失败重试、提醒并发均无旧任务复活；篡改仍失败。
- [x] 历史：旧失败事件、通知、审计和报告保留；发布新定义不改变旧实例固定版本。
- [x] 真实浏览器：登录中性测试领域，先完成处理→审批→验证并确认升级前报告 `RESOLVED`，再预览→填写原因→升级→编号不变→8D 节点→旧简报只读且历史报告仍为 `RESOLVED`→旧待办消失→附件状态保持；双会话视图冲突及跨企业直接HTTP拒绝通过。历史通知关联实例跳转由组件/API定向测试覆盖。
- [x] P3 真实附件上传、ClamAV扫描、证据下载与删除后拒绝路径已纳入闭环；缺少真实依赖会失败。
