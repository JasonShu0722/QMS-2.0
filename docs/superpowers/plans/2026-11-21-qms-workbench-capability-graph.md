## 4. 首发后优化：界面收拢与双路径状态维护

### 界面调整

- 桌面把搜索、三个筛选及复位放在同一行，不保留控件上方的可见标题；搜索框显示简短占位提示，控件仍有独立可访问名称，窄屏可折行。状态图例沿用原三态。
- 移除左侧常驻目录，画布占用释放出的空间。搜索结果在输入框下方浮出，选中后关闭并定位；保留键盘选择、空结果和关闭操作。无 WebGL 时仍可从同一个浮层按搜索或筛选定位节点和边，不恢复左栏。清空搜索或复位时不留残余结果遮层。
- 右侧固定功能标题与关闭按钮，仅滚动正文。常态只展示一句业务用途、主要能做什么、入口链接和直接上下游；不显示裸路径、状态日期、独立策划段落和反复出现的指南元数据。具体步骤和异常处理放进按需展开的使用指南，不删原帮助内容；保留业务前置条件及原入口权限检查。连线详情聚焦方向、触发条件、传递内容和结果。
- 浅色主题不改工作台外壳。默认推荐仅画布采用深蓝星空底，配低干扰微星点及高对比节点、边、标签；深色主题可共用画布色系。相较浅蓝渐变加深色连线，局部深底能延续星图层次，不让搜索浮层和详情随画布变暗。装饰不接收指针事件、不新增持续动画，不改变现有三维布局、聚焦或复位。

### 状态配置与交付边界

- 现版 `GET /api/v1/workbench/graph` 从版本化目录读状态。调整后，版本化目录继续提供节点初始状态和图谱内容；代码发布中的显式状态变更与管理员保存按稳定能力 ID 更新同一个生效状态。没有显式调整的节点不受发版影响，不按全量目录重新写入。
- 冲突规则：普通发版、改说明或改指南不覆盖管理员设置；只有 PR 中逐项声明且随部署实际应用的状态调整才替换对应节点状态，管理员之后仍可再改。以同一节点最后一次**成功应用的明确调整**为准，不比较提交日期与保存时间。重复执行发版时，已成功应用的 Prisma 迁移不重放；普通代码回滚不隐式改状态，若回滚导致原认可失效，必须在回滚检查点显式修正对应节点。
- 有效 `platform:admin` 在「功能简介」旁显示当前状态和配置入口，普通用户只看状态、看不到编辑控件。服务端同样校验内部身份及管理员权限，仅允许现存节点与三态枚举。保存成功后同步当前详情、节点颜色及筛选；失败保留原状态。审计记录操作者、新旧状态和时间；标为「已上线」前需确认发布及认可证据，可追溯至原计划、验收或 Issue，不把编辑状态当成实际部署。此设计不改岗位、不授予业务入口权限、不改连线状态。
- 发布调整记录能力 ID、目标阶段、交付出处及实际生效结果；内部用户重新加载图谱即可读到同一状态。不从 GitHub、飞书或部署成功信号自动推断状态，不新增后台采集或跨会话推送。

#### 代码发版调整操作

新增能力仍在目录登记初始状态；调整现有能力时，在原交付 PR 列出能力 ID、目标状态和交付证据，新建一次性 Prisma 数据迁移（不得编辑既有迁移）。在事务中对 `workbench_graph_statuses` 逐项写入 `node_id`、`status`、`evidence`、`updated_at`，初次插入 `version = 1`，冲突更新只替换指定节点并令 `version = workbench_graph_statuses.version + 1`。同一事务的重复 ID 视为错误，交付审查按当前目录核对每个 ID；不得通过改目录全局日期覆盖已有设置。标记 `live` 的迁移必须附可追溯的发布与认可记录。迁移由既有发布门禁执行并记录在 `_prisma_migrations`，失败或中断按现有迁移恢复流程处理，不手工重放已完成的 SQL。
