# QMS 2.0 账号与系统管理实施计划

## 范围

在问题与流程平台之后补齐平台级账号与系统管理。首个切片落地个人账号中心，同时冻结管理员后台、组织基础资料和安全增强的边界与后续顺序。

## 任务

1. [已完成] 建立账号中心错误码、DTO、审计动作和字段白名单失败测试。
2. [已完成] 实现个人资料读取/编辑 API，拒绝敏感字段写入和跨用户访问。
3. [已完成] 实现修改密码 API，验证旧密码、强度、审计和其他会话撤销。
4. [已完成] 实现会话列表与撤销其他会话 API，仅返回用于撤销的会话句柄，不暴露令牌原文或哈希。
5. [已完成] 生成并检查 OpenAPI 与前端 contracts。
6. [已完成] 实现个人账号与安全设置页面及响应式交互。
7. 建立管理员用户/组织/角色/权限工作包的失败门禁和后续迁移计划。
8. 运行 API/Web/集成测试、构建、契约检查和真实浏览器账号中心验收。
9. 建立横向运维治理门禁：TLS/密钥、对象存储保护、备份恢复和恢复演练。
10. 建立横向产品治理门禁：数据导出与报表权限、保留策略、国际化和可访问性。

## 后续切片

- B：管理员用户生命周期和组织角色分配。
- C：角色模板、权限目录和权限矩阵。
- D：组织树、部门/岗位、字典和系统参数。
- E：密码找回、管理员 MFA、高风险操作保护。
- F：管理审计查询、通知规则和受控运行配置。
- G：部署运维与数据保护，包括 TLS、密钥轮换、对象存储保护、备份恢复和演练证据。
- H：跨页面产品治理，包括导出/报表授权、数据保留、国际化和可访问性验收。

## 依赖与并行策略

G/H 不要求在 F 完成后串行启动。G 拆为“开发环境与秘密/TLS基线、对象存储保护”以及“备份恢复演练与发布门禁”两段，前段可与 B/C 并行，后段必须在供应商质量试点验收前完成。H 先定义导出授权、保留策略、国际化资源和可访问性基线，再与 D–F 及业务页面并行落地，避免后期返工。

完成 A、B、C 并通过真实权限、组织数据范围和流程节点权限验收后，可以启动批次 3 的领域建模、接口草案、测试夹具和非生产实现。批次 3 的真实供应商试点、外部协作和发布验收还必须等待 D 的通知/配置最小闭环、E 的管理员 MFA/密码重置与高风险审计、G 的 TLS/密钥/对象存储/备份恢复门禁，以及 H 的导出授权与数据保留门禁；国际化和可访问性按产品发布范围设为同一验收门槛。

## 交付门槛

每个切片必须按“失败测试 → 最小实现 → 针对性验证 → 提交”执行，并通过规格审查、质量审查、OpenAPI 同步和真实权限拒绝验证后才能进入下一个切片。G/H 与 B/C/D/E/F 同属供应商质量试点前置治理，不能仅以部署说明或页面文案标记完成。
