# QMS 2.0 账号与系统管理实施计划

## 范围

本轮交付限定为 A 个人账号中心、B 管理员用户治理、C 组织角色与权限管理的 API、生成契约和 Web 页面，并补齐真实 PostgreSQL、运行网关浏览器和聚合验收证据。D–H 与批次 3 不在本轮启动；原批次 2 的流程运行时、业务 Worker 和完整业务浏览器门禁不因 ABC 验收而自动完成。

本次文档收口已核对控制器、DTO、页面及测试，更新 README、ACCOUNT-ADMINISTRATION、OPENAPI、PHASE-2、FOUNDATION 和设计边界。ABC 最终验收 PASS，聚合、镜像、production 构建和双阶段复审证据齐全；产品源码已本地合并，5173 预览从已验收 NTFS 工作树运行。E 盘依赖安装失败、临时文件删除被自动审批阻止，均作为环境限制保留，不写成全清理 PASS。

## 依赖与并行策略

G/H 不要求在 F 完成后串行启动。G 拆为“开发环境与秘密/TLS基线、对象存储保护”以及“备份恢复演练与发布门禁”两段，前段可与 B/C 并行，后段必须在供应商质量试点验收前完成。H 先定义导出授权、保留策略、国际化资源和可访问性基线，再与 D–F 及业务页面并行落地，避免后期返工。

完成 A、B、C 并通过其真实功能权限和组织数据范围验收后，可由用户另行分配 D–H 或批次 3 的领域建模、接口草案、测试夹具和非生产实现，本轮不自动启动。流程节点权限仍由流程运行时独立验收。真实供应商试点、外部协作和发布还必须等待 D 的通知/配置最小闭环、E 的管理员 MFA/完整找回与重置策略/高风险操作保护、G 的 TLS/密钥/对象存储/备份恢复门禁，以及 H 的导出授权、数据保留、国际化和可访问性门禁；原平台流程运行、业务 Worker 和浏览器主链路深度验收也必须补齐。B 已有一次性管理员重置，不等于 E 完成。

## ABC 安全修复执行计划

### ABC Web 执行范围（2026-09-18）

补齐 A 成功反馈及交互回归、B/C 按组织权限控制的系统管理页、匿名一次性密码重置兑换页。沿用 Ant Design 与现有样式，所有契约类型来自生成 contracts；管理写请求带 CSRF 和可重试幂等键，秘密仅存在内存。先验证组件/API 请求红灯，再最小实现、Web 测试构建与真实网关 PostgreSQL Playwright 验证；完整聚合验收与独立审查由主代理接续。

ABC Web 复审补修范围：角色编辑按生成的 UpdateAdminRoleDto 只提交变更字段，权限按集合比较，无变化不发写请求，避免纯改名重建权限、使成员重置凭证失效或覆盖并发权限修改。组件请求体回归已验证红灯并完成最小修复；真实网关场景覆盖成员签发凭证后 UI 仅改角色名仍可兑换，最后补充保存等待期间禁止创建的四条红绿回归。各阶段测试数量和最终聚合证据统一记录于 FOUNDATION。

1. [已完成] 建立目标组织授权、B 幂等/迁移/一次性重置、C 全局角色和拒绝审计、A 并发改密回归测试并验证失败。
2. [已完成] 实现公共 Serializable 管理事务、事务内授权及 HMAC 幂等记录；接入 B/C 写接口。

5. [验收 PASS] 生成 OpenAPI 契约，完成内部 `/app/admin`、两门户个人账号页和 `/reset-password`；按目标组织权限控制入口、只读视图和写操作。针对性验证、最终聚合、在线镜像及运行证据均已汇总。
6. [复审修复] 主组织迁移补问题、任务和通知引用阻止、数据库 RESTRICT 迁移及 409 拒绝审计；通过真实 PostgreSQL 验证业务组织和账号安全状态保持不变。
7. [已完成] 登录最终身份校验与会话创建在同一用户行锁事务中完成；真实 PostgreSQL 和可控 Promise 屏障复现旧密码、停用、主组织及类型变化竞态后，验证 401、无新会话及先登录后重置撤销。独立连接验证行锁持续到会话提交；临时移除锁得到有效红灯。成功限流记录仅在会话事务提交后执行，不变更 API 契约。

本次范围包括 ABC 安全缺陷修复和 Web 闭环。角色仅改名时只提交 name，权限按集合比较且无变化不写；用户/角色保存等待期间禁止重新创建，避免迟到响应覆盖新表单。使用临时 PostgreSQL 和同库网关，不打印或提交凭据。失败测试、实际命令和最终结果写入 FOUNDATION。
