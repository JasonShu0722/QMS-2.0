# 一、项目简介

## 1.1 产品名称及用途：
质量管理系统，建立覆盖质量各板块管控的信息化管理系统，同步衔接现有的信息系统，实现各版块质量数据智能化统计以及跟进。

## 1.2 主要特性和功能：
- 质量问题登录、跟进
- 质量数据（来料、过程、客户、分供方绩效）统计，实时计算推移，趋势预警以及超标报警，自动联动内部IMS系统拉取物料到料以及成品产出数据
- 经验教训归拢罗列，从质量问题延伸沉淀，新品项目进行点检
- 新品试产、初期流动生产数据汇总，指标批次推移跟进，超标问题闭环跟进
- 客户审核、内部过程审核、分层审核（管理层级别）、供应商准入审核、供应商年度审核等各类审核结果以及问题清单闭环跟进
- 索赔管理（含客户索赔、供应商索赔），自动联动内部OA、SAP系统
- 供应商变更提交、跟进
- 通过数据仪表盘、任务看板可视化管理全面的质量数据
- 接入AI实现趋势诊断、问题回复诊断

## 1.3 目标用户或使用场景
- 系统管理组：超级管理员负责系统级治理、权限矩阵、功能开关、版本发布与底层配置；业务管理员负责账号维护、模板维护、流程异常干预、公告与通知管理
- 质量管理部：覆盖质量部长、体系工程师、制程质量、客户质量、项目质量、供应商质量等岗位，承担质量主链路的数据录入、问题跟进、审核与关闭
- 采购部：围绕供应商绩效、供应商索赔、供应商变更等流程做商务协同
- 研发中心与制造管理部：作为责任部门处理质量问题与审核问题应答，并参与新品试产和经验教训点检
- 供应商：仅处理分配给本公司的质量问题、审核问题、绩效确认、供应商索赔与供应商变更
- 各部门负责人及公司高管：查阅可视化面板、质量预警和关键审批结果，了解整体质量状况

## 1.4 业务领域及背景
汽车电子制造行业，新能源汽车控制系统设计与加工制造

## 1.5 当前底座实施基线（2026-04）
- 第一里程碑已完成到底座闭环的基础交付：账号创建与审批、内部/供应商登录、环境准入、平台管理员引导、权限矩阵、账号治理、个人中心基础、基础工作台、双环境治理与功能开关。当前前台公共注册入口临时关闭，账号新增优先走后台用户管理/后台创建路径。
- 当前统一会话已稳定返回 `user_info`、`environment`、`allowed_environments`、`is_platform_admin`、头像/签名路径、供应商名称等字段；其中 `environment` 由后端运行入口决定，不再由登录表单提交，`is_platform_admin` 当前应解释为超级管理员（SuperAdmin）bootstrap 标识。
- 当前工作台已落地“基础可用版”：个人信息卡、系统设置弹窗、可自定义快捷入口、页头待办统计窗、个人待办事项弹窗、底座域真实待办任务、公告/通知占位区。
- 当前第一里程碑暂不把通知中心、公告管理大面板、操作日志总览、系统配置大面板作为验收阻塞项；这些能力保留接口或页面占位，后续按需求推进。

# 二、功能模块规划

## 2.1 系统基础与门户管理

### 2.1.1 核心架构：
    基于“功能-操作”的拆解细分式权限控制体系，由管理员进行权限分配而非简单的固定角色。
    - 权限配置：
        功能模块维度：细分至一级/二级/三级菜单（如：供应商管理 > 绩效考核 > 月度评分）。
        操作权限维度：针对每个功能点，独立配置以下权限的开关
            - 录入/新建：是否能发起单据。
            - 查阅：是否可见（含对应板块的可视化看板，特殊逻辑：供应商账号仅能查看关联到其自身供应商名称的数据）。
            - 修改/编辑：是否能修改未归档数据。
            - 删除：是否能软删除数据（逻辑删除，数据库保留记录但前端不可见）。
            - 导出：是否有权下载 Excel/PDF（防泄密管控）。

### 2.1.2 动态配置UI：
    提供一个网格化（Grid/Matrix）的配置界面，管理员通过勾选“复选框”实时调整权限集合，后端无需重启即可生效。
    - 当前第一里程碑已落地统一的权限矩阵契约：后端返回 `modules + rows`，前端按该契约渲染与保存。
    - 当前权限治理主模型已切换为“角色标签 -> 权限集合 -> 账户分配”，即管理员优先维护角色标签权限，再把角色标签分配给具体账户。
    - 当前平台管理员入口采用独立 bootstrap 机制，先保证系统管理后台可进入，再承接后续业务权限矩阵配置。

### 2.1.3 用户基本信息配置：
    - 前台公共注册入口当前暂不开放；内部员工账号临时由管理员在用户管理或后台创建路径中维护，需记录用户名、姓名、电话、邮箱、部门（序列下拉选择）、职位。
    - 后端内部员工注册申请能力保留兼容，若重新开放公共注册，需校验企业邮箱策略；对外失败提示不得暴露具体校验规则，以避免为外部滥用提供线索。
    - 供应商账号不开放公共注册入口，统一由管理员在用户管理中创建。
    - 管理员创建供应商账号时，必须绑定系统内已存在的供应商基础信息主数据，不允许脱离主数据单独创建供应商账户。

### 2.1.4 操作日志：
    所有关键操作（提交、删除、修改）必须记录后台日志（谁、什么时间、做了什么），管理员可以查阅操作日志，并可以进行筛选查阅。

### 2.1.5 统一登录与鉴权策略
*（补充逻辑：在现有用户体系之上，增加“内外网统一入口”下的分流认证机制。）*
- 登录入口统一：
    - 在单个运行入口下，内部员工与外部供应商共用同一登录页，无需为不同用户类型记忆不同入口。
    - 当前系统同时存在 `stable / preview` 两套运行域名，用户访问的域名和后端实例决定当前运行环境，登录页不再提供正式 / 预览选择。
- 身份识别与分流：
    - 内部员工：
        - 界面提供独立的“员工登录”选项。
        - 集成策略：除常规账号密码登录以外，可对接公司 AD/LDAP 或 OA 系统实现单点登录。
    - 供应商：
        - 界面提供独立的“供应商登录”选项。
        - 界面保留标准的“账号/密码 + 验证码”输入框。
        - 安全加固：强制启用图形验证码（防撞库），并支持配置“连续输错 5 次锁定账号 30 分钟”的安全策略。
- 环境准入：
    - `allowed_environments` 作为运行环境准入的唯一来源。未获授权的运行入口不得登录，即使账号密码正确也应拒绝。
- 登录成功返回：
    - 除 Token 之外，需返回稳定的会话对象，至少包含用户信息、当前环境、可访问环境、平台管理员标识和头像/签名/供应商名称等标准字段。
- 强制密码策略：
    - 系统强制校验密码复杂度（大写、小写、数字、特殊字符中至少三种，长度>8位），并设定 90 天强制定期修改要求。

### 2.1.6 动态工作台
*（补充逻辑：登录后的“第一屏”。基于角色定义，为不同用户展示千人千面的看板。）*
- 内部人员视图：
    - 当前第一里程碑先落地基础工作台：个人信息卡、环境标识、系统设置入口、快捷入口、页头待办统计窗与个人待办事项弹窗。
    - 指标全景监控：依据不同角色定义，自动聚合 2.4 模块的指标趋势图；在第一里程碑中，这类增强块受 feature flag 控制，未启用时允许隐藏或展示空态。
    - 待办聚合：采用可扩展的任务聚合器，当前覆盖注册审批、权限初始化以及 SCAR 当前处理人待办；SCAR 发布后进入供应商问题回复待办，供应商提交后进入内部审核人待办，后续继续扩展到 PPAP、变更申请等业务任务。
- 供应商视图：
    - 当前第一里程碑优先保证资料、环境标识、快捷入口、待办任务与空态表达正确。
    - 红绿灯状态：顶部醒目展示其当前的绩效等级（A/B/C/D）及本月被扣分情况，起到警示作用；若当前没有真实绩效数据源，则该区域保持预留或空态。
    - 任务驱动：仅展示“待回复 8D”、“待签署协议”、“待上传报告”等需要其行动的卡片，屏蔽无关信息。
    - 快捷入口支持用户在其可见功能范围内自行配置。

### 2.1.7 移动端适配规范
*（补充逻辑：针对现场作业场景，明确移动端的交互标准，无需开发原生 APP，采用 H5/PWA 模式。）*
- 响应式布局：
    - 系统需适配手机/平板分辨率。在移动端访问时，自动折叠左侧菜单栏，将“操作按钮”和“输入框”放大，适应手指触控。
- 场景化适配：
    - 扫码枪模式（对接 2.5.10）：
        - 在 PDA 或手机浏览器打开“扫码防错”页面时，自动隐藏顶部导航和底部版权信息，全屏显示扫描框和红绿灯结果，防止误触。
    - 离线暂存模式（对接 2.9）：
        - 针对审核员在车间无信号场景，支持将审核打分表“暂存本地”，网络恢复后自动同步提交。


## 2.2 个人中心（默认首页）

### 2.2.1 页面布局与逻辑
- 设计原则：作为系统登陆后的默认落地页，采用“卡片式”布局，强调“任务驱动”。
- 数据加载：页面加载时，自动触发 API 从各个业务模块（客诉、IQC、审核等）拉取与当前登录用户 ID 关联的待办事项。

### 2.2.2 个人信息模块
- 基础展示：显示用户头像、姓名、部门/供应商名称、职位、当前环境与平台管理员标识。
- 账号安全与设置：
    - 当前在工作台中统一聚合为“系统设置”弹窗，通过页签集中处理账户信息、头像设置、修改密码、电子签名。
    - 账户信息：仅平台管理员可自助修改自己的账户信息；其他用户（含领导）由管理员在用户管理界面统一调整。
    - 头像管理：支持头像上传与裁剪更新。
    - 修改密码：支持用户自主修改登录密码。
    - 电子签名管理：用户可上传个人的手写签名图片，网站自动实现图片背景透明化。在后续审批 8D 报告或审核单时，系统将调用此图片自动生成电子签章。

### 2.2.3 待办事项
- 聚合逻辑：这是一个“任务聚合器”。当前采用“适配器注册 + 不可用源自动跳过”的方式，不再要求一次性硬编码遍历所有业务表。
- 任务分类与展示：
    - 显示要素：任务类型（如“8D报告审核”）、单据编号、紧急程度（高/中/低）、剩余处理时间（倒计时）。
    - 工作台统计：页头固定展示待办总数、超期事项数、临期事项数，并支持点击进入个人待办事项清单弹窗。
    - 快捷跳转：点击某条待办，直接跳转到对应模块的具体单据详情页进行处理。
- 状态颜色标识：
    - 🔴 已超期：倒计时 < 0。
    - 🟡 即将超期：倒计时 ≤ 72小时。
    - 🟢 正常：倒计时 > 72小时。

### 2.2.4 站内信通知
- 消息类型：
    - 流程异常通知：如“您提交的索赔单已被驳回”。
    - 系统提醒：如“本月客诉数据已生成，点击查阅”。
    - 预警通知：如“供应商 A 的不良率连续3天上升，请关注”。
- 交互功能：
    - 支持“一键标记为已读”。
    - 未读消息在右上角铃铛图标显示红点数字。
- 当前第一里程碑说明：
    - 保留通知区块与接口兼容位，但不作为主验收项；未启用时允许展示明确空态。

### 2.2.5 公告栏
- 内容分类：系统公告（维护通知）、质量警告、体系文件更新通知。
- 强制阅读机制：
    - 对于被标记为“重要”的质量预警（如：客户发生重大投诉，全员需知晓），用户登录后弹窗提醒点击查阅，系统后台记录“阅读时间”和“阅读人 ID”。
    - 未读的重要公告应置顶并高亮显示。
- 当前第一里程碑说明：
    - 公告区保留在工作台布局中，但默认走 feature flag 控制或空态展示，不作为主链路阻塞项。

## 2.3 系统管理与全局配置
*（本模块仅限管理员可见）*

### 2.3.0 管理角色分层
- 超级管理员（SuperAdmin）：
    - 负责系统最高级技术控制权，包括全局数据突破式查阅、权限矩阵与角色配置、审计日志全局查阅、底层参数配置、版本发布治理和极端异常数据干预。
    - 当前代码中的 `is_platform_admin` 即对应这一 bootstrap 身份。
- 系统管理员 / 业务管理员（Admin）：
    - 负责业务层面的日常运维支撑，包括账号启停用与密码重置、主数据与模板维护、流程异常干预、公告发布和通知规则维护。
    - 后续应通过角色模板或权限矩阵承接，不直接等同于超级管理员。

### 2.3.1 全局任务统计与监控
- 用途：用于监控团队整体的工作负载和流程瓶颈，而非具体操作单个任务。
- 统计视图：
    - 待办分布图：按“部门”或“人员”统计当前的待办任务数量（例如：SQE组目前积压了 50 个 8D 报告）。
    - 逾期分析：列出当前所有已逾期（红灯）的单据清单，支持按“逾期时长”排序，方便管理者进行督办。
- 批量转派：当某位工程师离职或请长假时，管理员可在此界面将其名下的所有“待办任务”批量转移给另一位用户。
- AI诊断：调用AI工具诊断评价目前现状

### 2.3.2 消息通知机制配置
- 触发规则引擎：
    - 管理员可自定义业务触发器（Trigger）。
    - *配置逻辑举例*：[选择对象：客诉单] + [选择条件：状态=已驳回] -> [执行动作：发送邮件给提交人]。
- 升级策略：
    - 定义“超时自动升级”规则。
    - *配置逻辑举例*：若单据在 [当前节点] 停留超过 [48小时]，自动触发 [邮件抄送] 给 [当前处理人的上级]。
- 通道配置：
    - 配置 SMTP 邮件服务器参数。
    - 配置企业微信/钉钉/飞书的 Webhook 地址（用于接收系统级预警）。

### 2.3.3 人员信息及权限配置
- 平台管理员引导：
    - 当前采用独立的平台管理员 bootstrap 机制，先保证系统管理后台可进入，再配置细粒度业务权限，避免权限矩阵自身无法自举。
- 管理员分工：
    - 超级管理员优先负责权限矩阵、角色模板、数据字典、集成配置与版本治理等底座级能力。
    - 业务管理员优先负责账号治理、模板维护、流程异常干预、公告和通知配置等日常运维能力。
- 用户管理：
    - 用户审批：查看并处理状态为“待审核”的内部员工注册申请，支持批准、驳回与审批意见记录。
    - 用户清单管理：查看全部非待审核账户，支持姓名/用户名、部门、岗位、角色标签、用户类型、账号状态等条件搜索筛选。
    - 账号维护：支持重置用户密码、冻结/解冻账号、删除普通账户（需保护超级管理员 bootstrap 账户和关键业务关联账户）。
    - 账户资料治理：普通用户的账户信息调整由管理员在此统一处理，而不是分散给各用户自行维护。
    - 角色分配：管理员可为账户绑定一个或多个角色标签，让相同岗位的权限配置统一归口。
    - 创建用户：支持管理员单条创建和批量创建内部员工或供应商账号；其中供应商账号仅允许绑定启用中的供应商基础信息。
    - 供应商基础信息：在系统管理下提供独立的供应商基础信息维护入口，至少维护供应商代码、供应商名称、状态，并支持搜索、单条创建、批量导入、编辑与启停用。
- 权限矩阵配置：
    - 实现 2.1.1 章节定义的“网格化配置界面”。
    - 当前主入口改为“角色标签权限矩阵”，管理员在此维护角色标签对应的一二三级模块与录入/查阅/修改/删除/导出权限，保存后实时生效。
    - 用户级直连授权能力仅作为兼容性补充通道保留，不再作为日常权限治理主路径。

## 2.4 质量数据面板

### 2.4.1 数据集成与计算逻辑
- IMS系统对接：
    - 接口定义：开发定时任务，每日凌晨 02:00 从内部 IMS 系统同步“物料入库批次数”、“物料入库不合格批次数”、“物料入库总数量”、“成品出库总量”等分母数据。
    - 自动计算公式：
        - 来料批次合格率 = ((物料入库批次数-物料入库不合格批次数) / 物料入库批次数) * 100%
            注：
            - 按供应商进行区分统计并计算总数
            - 按日、月统计推移并合计年度数据
        - 物料上线不良PPM = (物料上线不良数 / 物料入库总数量) * 1,000,000
            注：
            - 按供应商进行区分统计并计算总数
            - 可实现按物料类型分类统计
            - 按日、月统计推移并合计年度数据
        - 制程不合格率 = (完成制程不合格品数 / 成品产出入库数) * 100%【有更新】
            注：
            - 按责任类别、工序、线体进行区分统计并计算总数
            - 按日、月统计推移并合计年度数据
        - 制程直通率 = (一次测试通过数 / 一次测试总数量) * 100%【有更新】
            注：
            - 按责任类别、工序、线体进行区分统计并计算总数
            - 按日、月统计推移并合计年度数据
        - 0KM不良PPM = (0KM客诉数 / 成品出库总量) * 1000,000
            注：
            - 按产品类型进行区分统计并计算总数
            - 按日、月滚动推移并合计年度数据
        - 售后不良PPM(3mis) = (3mis客诉数 / 3个月滚动出货量) * 1000,000
            注：
            - 按产品类型进行区分统计并计算总数
            - 月度滚动推移
        - 售后不良PPM(12mis) = (12mis客诉数 / 12个月滚动出货量) * 1000,000
            注：
            - 按产品类型进行区分统计并计算总数
            - 月度滚动推移

### 2.4.5 跨模块问题管理共通能力
*（适用于 2.5 供应商质量、2.6 制程质量、2.7 客户质量、2.8 新品质量、2.9 审核管理的问题闭环主链路）*
- **统一问题中心**：

- **问题回复形式分级**：

    - 复杂或重大问题：采用 **8D 报告** 回复并完成闭环。
    - 发起问题时可选择默认回复形式；问题跟进责任人和具备管理职责的角色在流转过程中可即时调整回复形式，系统需保留切换原因和操作轨迹。
- **统一分类与编号规则**：
    - 问题主单号格式：`ZXQ-<分类子类>-<YYMM>-<三位流水号>`，例如 `ZXQ-CQ1-2604-003`。
    - 8D 报告号格式：`ZX8D-<分类子类>-<YYMM>-<三位流水号>`，例如 `ZX8D-AQ3-2604-001`。
    - 分类与子类编码：
        - `CQ0`：0km
        - `CQ1`：售后
        - `PQ0`：PCBA段
        - `PQ1`：组装测试段
        - `IQ0`：结构料
        - `IQ1`：电子料
        - `DQ0`：厂内试产/调试问题
        - `DQ1`：客诉问题

        - `AQ1`：过程审核 NC
        - `AQ2`：产品审核 NC
        - `AQ3`：客户审核问题
- **统一可见范围口径**：
    - 公司内部人员默认可查看全量业务问题，具体操作权限仍由角色、阶段和当前责任归属共同决定。
    - 外部供应商账号仅可查看并处理分派给本供应商的问题，不可查看其他供应商或内部备注信息。
- **统一待办与通知**：
    - 工作台和待办中心展示的问题卡片需统一显示任务类型、问题主单号或 8D 报告号、紧急程度、剩余处理时间。
    - 分派、驳回、重开、升级、关闭、回复形式切换等关键动作均需触发统一待办刷新与消息通知。

## 2.5 供应商质量管理

### 2.5.1 IQC 数据集成与监控
- **接口同步策略**：
    - **单向同步**：QMS 通过 通过 API 或数据库中间表定时从 IMS 读取入库检验记录（包含：物料编码、批次号、检验结果 OK/NG、不良描述、不良数量）。
    - **数据用途**：此数据不用于重复显示，而是直接作为 **2.4.1 质量数据中心** 的计算源数据，并最终流向 **2.5.4 绩效评分**。
- **智能触发器**：
    - **NG 自动立案**：监测到 IMS 出现“检验结果 = 不合格”时，自动生成 SCAR 单。
    - **特采标记**：同步 IMS 的特采记录，用于后续追踪该批次物料在产线上的表现。

### 2.5.2 供应商协同与问题闭环
- **交互流程**：
    - **发起端**：IQC 或 产线 发现供应商责任的不良 -> 生成 SCAR 单，可附加缺陷图片佐证（支持点击、拖动、粘贴图片）-> 通知供应商账号。
    - **供应商端**：供应商登录系统（仅见自己的数据），按严重度分级回复；低等级问题采用“问题简报”，仅需填写原因分析、改善对策、完成时间，并提供对策实施佐证/报告附件上传区域；中、高、重大问题采用 8D 报告（包含问题描述与临时处理、原因分析、纠正预防、验证结果），并在对策实施证据区上传图片或文件佐证；若供应商另有完整报告文件，可作为报告附件提交。
    - **审核端**：按严重度分级关闭；低严重度问题由供应商质量工程师审批后关闭，中、高严重度问题需供应商质量工程师与供应商质量室经理双层审批后关闭，重大问题需供应商质量工程师、供应商质量室经理、质量管理部部长三层审批后关闭。任一节点可驳回，驳回时必须填写具体修改意见并通知当前责任人。
- **AI 辅助审核**：
    - 在 SQE 人工审核前，接入 AI 接口预审 8D 报告。
    - *预审逻辑*：
        - 关键词检测：检查是否包含“加强培训”、“加强管理”等空洞词汇，若有，AI 自动提示供应商“措施不具体，请补充作业指导书变更证据”。
        - 历史查重：检查“根本原因”是否与该供应商过去 3 个月的历史 8D 高度重复。

### 2.5.3 供应商生命周期与审核
- **准入审核**：新供应商注册时，需在线上传 ISO9001/IATF16949 证书、营业执照等资质文件，系统自动识别有效期并设置“过期预警”。采购工程师/SQE可以对供应商上传资料进行审核以及系统自动识别信息修订，对于供应商提交文件不合格时可以驳回并创建提交任务。
- **供应商变更管理**：供应商在线提交 PCN 申请，采购工程师/SQE 发起内部评估流程，验证通过后系统回传后，供应商执行切换，并上传断点信息。
- **审核管理**：
    - **计划管理**：设定年度审核计划并制定供应商、审核责任SQE以及计划审核月份。
    - **审核周期**：每个月 1 号自动触发审核流程，审核员根据计划审核供应商。
    - **审核指标**：审核员根据 VDA6.3 过程审核 / 体系审核，评估供应商的质量、服务、交付等方面。
    - **审核结果**：审核通过后，系统自动更新供应商状态为“正常”，并记录审核日期。审核未通过，系统自动更新供应商状态为“异常”，并记录审核日期。
    - **问题点追踪**：审核员录入的不符合项 (NC)，自动转化为“任务清单”指派给供应商，直至整改完成关闭。

### 2.5.4 供应商质量目标发布
*（核心逻辑：确立考核基准，支持批量与个别差异化配置，需供应商在线确认签署）*
- **目标制定**：
    - **批量设定**：
        - 支持 SQE 按“物料类别”或“供应商等级”批量设置通用目标。
        - *场景*：设定所有“C级供应商”的来料合格率目标为 99.8%。
    - **单独设定**：
        - 支持针对特定供应商（Supplier ID）进行差异化目标配置。
        - *场景*：针对“核心战略供应商”或“重点整改对象”，单独设定更严格或阶段性的 PPM 目标。
    - **优先级逻辑**：
        - 系统自动遵循 **“单独设定 > 批量设定 > 全局默认值”** 的优先级原则。
        - *计算逻辑*：在计算绩效时，系统优先查询该供应商是否存在有效的“单独目标书”；若无，再回退查询其所属类别的“批量目标书”。
- **辅助决策数据**：
    - 在设定界面，系统自动左右分栏展示：
        - 左侧：拟设定的 2026 年目标值。
        - 右侧：该供应商 2025 年实际达成值（平均值及波动范围），辅助 SQE 评估目标的合理性与挑战性。
- **审批与发布**：
    - **审批流**：SQE 提交 -> 质量经理审核（若目标值低于历史实际值，系统自动高亮提示“目标倒退风险”）-> 发布。
- **供应商签署**：
    - **待办任务**：目标书发布后，供应商门户收到“待签署质量目标”任务。
    - **在线确认**：供应商查阅目标值，点击“确认/签署”。
        - *互锁机制*：若在规定时间（如 1 月 31 日）前未签署，系统限制其查看绩效申诉权限。
    - **版本生效**：系统记录生效日期。绩效计算时，严格依据**数据产生当月**所生效的目标版本进行考核。

### 2.5.5 供应商绩效评价
*（核心逻辑：采用 60 分制扣分后按100分满分折算百分制模型。每月 1 日自动计算，对比 **2.5.5 中签署的目标值**）*
- **基础配置**：
    - **初始分**：每月默认 **60 分**。*注：最低分为 0。*
    - **目标基准**：**直接调用 2.5.5 模块中该供应商当前生效的目标值**。
- **扣分规则**：
    1.  **来料质量扣分**：
        - *数据源*：2.4.1 计算的“来料检验质量合格率”。
        - *算法*：计算（2.5.5 设定目标值 - 实际值）的差距。
            - 达到目标：扣 0 分。
            - 差距 < 10% 目标值：扣 5 分。
            - 10% ≤ 差距 < 20% 目标值：扣 15 分。
            - 差距 ≥ 20% 目标值：扣 30 分。
    2.  **制程质量扣分**：
        - *数据源*：2.4.1 计算的“物料上线不良 PPM”。
        - *算法*：计算（实际 PPM - 2.5.5 设定目标 PPM）的超标比例。
            - 达到目标：扣 0 分。
            - 0 < 超标 ≤ 50%：扣 5 分。
            - 50% < 超标 ≤ 100%：扣 15 分。
            - 超标 > 100%：扣 30 分。
    3.  **配合度扣分**：
        - *数据源*：SQE 人工评价 + 系统自动规则。
        - *标准*：高（扣 0 分）、中（扣 5 分）、低（扣 10 分）。
    4.  **0公里/售后质量扣分**：
        - *数据源*：2.7 模块中的客诉记录（带严重度标签）。
        - *算法*：
            - 个例物料问题：每次扣 10 分。
            - 批量重大质量异常：每次扣 20 分。
            - 安全问题（如抛锚）：每次扣 30 分。
- **人工评价校核**：
    - SQE在每个月的最后一天，必须在门户填写“配合度评价”（高/中/低）。
    - 系统会根据 SQE 输入的配合度等级，自动计算“配合度扣分”。
    - 针对系统生成的扣分项以及数据，SQE 可在门户查看并进行复核，针对扣减内容可以进行核减并附上详细说明。
- **等级评定**：
*60 分制扣分后按100分满分折算百分制模型*
    - **A级**：得分 > 95。
    - **B级**：80 ≤ 得分 ≤ 95。
    - **C级**：70 ≤ 得分 < 80。
    - **D级**：得分 < 70。
    - *输出*：SQE人工校核后，系统自动生成月度绩效卡。

### 2.5.6 供应商会议与改进监控
*（基于绩效等级的强制干预机制）*
- **会议触发机制**：
    - **自动立项**：当月度绩效生成为 **C级** 或 **D级** 时，自动生成“供应商月度品质改善会议”任务。
    - **参会人员要求**：
        - C级：通知要求供应商**副总级**参加。
        - D级：通知要求供应商**总经理**参加。
- **会议执行与纪律**：
    - **资料上传**：供应商需在门户上传《物料品质问题改善报告》，逾期触发预警。
    - **考勤与纪要**：SQE 录入“实际参会最高级别人员”和“会议纪要”。
    - **违规处罚**：
        - 若标记为“供应商未参会”或“未提交报告”，系统自动在**下个月度**的 2.5.6 绩效评价中，锁定“配合度扣分”项，强制执行额外扣分。

### 2.5.7 PPAP 管理
- **提交管理**：
    - **触发场景**：新物料导入、变更 (ECN)、模具转移或停产一年后恢复生产。
    - **提交等级**：支持配置 Level 1 - Level 5 提交要求（默认为 Level 3）。
    - **文件清单**：系统内置标准 18 项文件检查表（如：PSW、全尺寸测量报告、控制计划、PFMEA、材质证明等）。由SQE指定各项文件的要求上传日期，供应商需在线逐项上传附件。
- **审核与批准**：
    - **在线签核**：SQE 对文件包进行审核，支持“单项驳回”或“整体批准”。
- **年度再鉴定**：
    - 系统自动监控 PPAP 批准日期，满 1 年自动生成“年度产品审核”任务，提醒供应商提交最新报告。

### 2.5.8 物料检验规范及定期报告管理
*（核心逻辑：建立数字化检验标准库，并基于物料风险等级设定差异化的出货报告管控频率，实现发货动作与质量资料的强关联。）*

- 检验规范生命周期管理：
    - 任务发起：SQE 可针对特定物料（或物料族）发起“规范提交”或“版本升级”任务。
    - 供应商交互：
        - 供应商收到待办任务，在线填写关键检验项目（SIP Key Characteristics）并上传双方签字版 SIP 文件（PDF）。
        - 支持版本管理（V1.0, V1.1...），新版本生效后，旧版本自动归档。
    - 审批与发布：SQE 审核通过后，该规范状态变为“生效”，并自动同步通知至 IQC 供进料检验参照用。

- 报告频率策略：
    - 策略配置：SQE 可在物料主数据中指定“出货报告收集频率”。
    - 频率选项：
        - 按批次：*默认选项*。每一笔发货单都需要对应一份报告。
        - 按时间：如“每周/每月/每季度”提交一次。

- 报告收集与互锁（暂时做预留功能，待后续发货数据流打通后启用）：
    - ASN 强关联（按批次）：
        - 当供应商在门户创建发货单 (ASN) 时，系统自动检查该物料的策略。
        - 若为“按批次”，供应商必须上传附件（COC/OQC报告）才能提交 ASN，否则系统拦截发货。
    - 定期任务推送（按时间）：
        - 系统根据设定周期（如每月 1 日），自动向供应商生成“定期报告提交”待办任务。
        - 逾期处理：若任务逾期未关闭，自动触发 2.5.6 绩效评价 中的扣分逻辑。

### 2.5.9 关键件防错与追溯扫描
*（核心逻辑：为未纳入 MES 管控的关键件提供轻量级防错工具，在 IQC 或投产前扫码验证，防止错料混入。）*

- 校验规则配置：
    - 正则匹配：支持 SQE 为特定料号配置正则表达式（如 `^A\d{4}[XYZ]$`），系统自动验证条码格式。
    - 特征校验：支持配置固定前缀、后缀、长度限制（Min/Max Length）。
    - 防重逻辑：开启“唯一性校验”后，系统自动比对历史记录，拦截重复扫描的序列号 (SN)。

- 扫码执行终端：
    - 交互体验：
        - 即时反馈：扫描 OK 显示绿色 “PASS” 字样；扫描 NG 显示红色报警并提示错误原因。
        - 计数管理：设定“目标数量”，实时显示当前已扫数量/剩余数量，满额自动停止。

- 数据追溯与导出：
    - 系统自动记录：物料号、供应商代码、条码内容、判定结果、扫描时间、操作员、设备IP。
    - 批次提交归档：供应商完成发货批次扫码录入后可进行提交归档，提交时填写物料号及批次，归档后推送对应的SQE及IQC，以用于IQC检验校核。
    - 一键导出：支持导出Excel文档。

## 2.6 过程质量管理
*（核心逻辑：聚焦于制程不合格数据的采集、责任分类统计以及异常发单闭环。首件/巡检作为线下控制手段，数据暂不接入本模块指标体系。）*

### 2.6.1 生产数据集成
*（为核心指标计算提供准确的“分母”数据）*
- **接口同步策略**：
    - **接口逻辑**：QMS 定时（如每日/每班次）从 IMS 拉取生产入库统计数据、一次测试通过数、一次测试总数量。
    - **核心字段**：成品入库数，用于计算“制程不合格率”；一次测试通过数、一次测试总数量，用于计算“制程直通率”。
    - **维度要求**：数据需携带“日期”、“工单号”、“工序”、“产线”等标签，以支持多维度的钻取分析。

### 2.6.2 不合格品数据录入与分类
*（核心目的：支持指标“按责任类别进行区分统计”）*
- **数据来源**：
    - **IMS 同步**：同步各工序自动判定的不良记录。
    - **人工补录**：产线/维修工位手动录入未被设备捕捉的外观/组装不良。
- **关键字段定义**：
    - **不良现象**：关联预设的失效类型。
    - **责任类别**：
        - 下拉选项：物料不良、作业不良、设备不良、工艺不良、设计不良。
        - *逻辑关联*：若选择“物料不良”，系统自动关联 2.4.1 的“物料上线不良 PPM”指标。

### 2.6.3 制程质量问题发单管理
- **触发机制**：
    - **自动触发**：预留自动触发配置接口，依据系统实际运行，在未来合适时候进行构建。
    - **手动发起**：PQE 在查看 2.4.3 报表或是不合格品数据清单，可选中关注的数据点、问题点，一键发起整改。
- **闭环流程**：
    - **指派**：根据责任归属，由PQE指派给责任板块担当。
    - **执行**：责任板块担当填写原因分析，制定围堵及长期对策，并上传改善证据。
    - **验证**：对策导入后设定验证期（如：后续 1 周内 2.4 模块显示的指标无超标或是不合格品无再发），由PQE判断验证通过后系统允许关闭。

## 2.7 客户质量管理
*（核心逻辑：实现全渠道客诉的闭环管理，并依据出货数据自动计算 0KM 及 MIS 售后指标，联动财务索赔及供应商扣分。）*

### 2.7.1 出货数据集成
*（为核心指标计算提供准确的“分母”数据）*
- **接口同步策略**：
    - **接口逻辑**：QMS 每天从 ERP/SAP 或 IMS 拉取发货记录。
    - **核心字段**：
        - **当期成品出库量**：用于计算 0KM PPM。
        - **历史滚动出货量**：系统需存储并维护过去 24 个月的分月出货数据表，用于计算 3MIS / 12MIS 等滞后性指标。
    - **维度要求**：数据需携带“客户代码”、“产品类型”、“出货日期”标签。

### 2.7.2 客诉录入与分级受理
*（依据质量问题等级划分标准进行录入与分流）*
- **录入分类**：
    - **0KM 客诉**：客户产线端发现的问题。
    - **售后客诉**：终端市场反馈（需录入：失效里程、购车日期、VIN码）。
- **录入主字段**：
    - 客诉录入时需区分 **是否涉及退件**、**是否需要实物解析**。
    - 客诉录入时需强制录入 **客户名称**；**终端客户名称** 允许选填。
    - 客户名称应优先从系统管理下维护的客户主数据中选择，终端客户在第一阶段允许文本录入，后续再视使用稳定度决定是否纳入主数据治理。
- **缺陷等级界定**：
    *系统需内置分级逻辑，录入时必选，直接决定后续的升级汇报机制及供应商扣分权重：*
    - **具体分级方案TBD**
- **受理分流**：
    - **无需实物解析**：可不直接进入 8D，而是先进入“实物处理 / 后续方案备案”支线，使用客诉台账补充录入实物处理方案、责任人、执行结果和归档信息。
    - **需要实物解析**：客诉单需选择下一步责任人并流转至失效分析工程师、客户质量工程师、工艺工程师等角色处理，形成后续问题发单和 D4 根因分析输入。
- **自动追溯**：通过录入的追溯信息，联动IMS系统追溯查询系统，自动调取过程记录是否存在异常，如涉及物料失效可通过输入物料编码实现自动追溯查询。
- **客户主数据治理**：
    - 系统管理需补充客户基础数据管理能力，至少维护客户编码、客户名称、状态和基础联络信息。
    - 客诉录入、出货数据集成和后续索赔统计应复用同一客户主数据口径，避免客户名称散落填写造成统计失真。

### 2.7.3 客诉解析、实物处理与问题发单
*（将客诉台账、实物处理和正式问题闭环解耦，避免所有客诉都强制直接进入 8D）*
- **客诉台账定位**：
    - 客诉清单首先是客户质量的来源台账对象，用于记录 0KM / 售后问题、退件信息、实物解析需求、客户信息和后续处置轨迹。
    - 客诉台账不默认等于 8D 主单；是否升级为正式问题单或 8D，应由客户质量岗位根据实际复杂度决定。
- **实物处理支线**：
    - 若涉及退件，系统需记录退件接收、实物账务处理、改制返修或报废等后续动作的责任信息和状态节点。
    - 若无需实物解析，可直接在客诉台账上登记实物处理方案、完成情况和归档证据。
- **实物解析支线**：
    - 若需要实物解析，系统需在客诉台账基础上扩展记录至少一次原因分析、责任部门、责任人、失效零部件料号、分析结论和证据附件。
    - 该解析记录作为后续问题发单或 8D D4 分析的重要输入，但不应与正式 8D 主单强绑定为同一对象。
- **问题发单机制**：
    - 客户质量室经理、客户质量工程师可在客诉清单中选中一条或多条客诉记录，发起正式质量问题单或 8D 流程。
    - 正式问题单需支持在跟进过程中实时增删客诉范围，保持问题主单与客诉来源范围动态关联。
    - 简单或单点问题可直接走“问题简报”；复杂或重大问题启动 8D 报告流程。

### 2.7.4 8D 闭环与时效管理 (8D Workflow & SLA)
*（遵循时效要求，并实行分级审核）*
- **SLA 动态时效监控**：
    - **8D 报告提交**：7 个工作日内。
    - **报告归档**：10 个工作日内。
    *注：SLA 以“正式问题单 / 8D 已发起”为起点；若客诉仅走实物处理备案，则按客诉台账自身节点管理，不强制套用 8D 时效。若系统扩展至内部或供应商模块，需支持配置不同的 SLA（如内部制造不良为 3 天回对策）。*
- **8D 执行标准步骤**：
    - **D0-D3 (CQE / 客户质量发起端完成)**：
        - 填写问题描述 (5W2H)。
        - 制定围堵措施（需覆盖：在途品、库存品、客户端库存）。
        - 关联来源客诉范围，必要时维护主问题与客诉明细的多对多关联。
    - **D4-D7 (责任板块担当完成)**：
        - D4 可复用前序实物解析记录作为原因分析输入。
        - **根本原因**：提供5Why、鱼骨图、FTA、流程分析等工具模板，供责任板块进行分析。
        - **对策验证**：D6 环节必须上传“验证报告”或“测试数据”作为附件，否则无法进入下一步。
        - **标准化**：D7 环节需勾选“是否涉及文件修改”（如 PFMEA/CP/SOP），若选是，需上传修改附件。
    - **D8 水平展开&经验教训**：
        - **水平展开**：需在系统中搜索并关联“类似产品/类似工艺”，将对策推送到相关项目组。
        - **经验教训沉淀**：提交结案时通过勾选是否沉淀经验教训，系统自动弹出《经验教训总结表》弹窗，提交后由责任部门部长审批。
- **审批与归档**：
    - **分级审批流**：
        - C级问题：科室经理审批。
        - A/B级问题：质量部长 + 责任部门部长联合审批。
    - **归档互锁**：
        - 归档时自动触发《8D报告归档检查表》核对流程。

### 2.7.5 索赔管理
- **客户索赔处理**：
    - **录入**：登记客户发来的扣款金额及明细。
    - **手动关联**：可通过筛选将客户索赔与问题清单进行多选关联。
- **供应商索赔转嫁**：
    - **触发条件**：若 8D 报告的根本原因判定为“供应商来料问题”。
    - **一键转嫁**：在客诉单界面点击“生成供应商索赔”，系统自动提取相关信息（物料号、供应商、客诉金额）生成 **2.5 模块** 的供应商索赔单，实现成本转移。

## 2.8 新品质量管理

- **质量阀门管理**：
    - **阶段定义**：配置各项目关键节点。
    - **交付物清单**：
        - 系统内置项目质量需点检交付物。
        - 支持设置“其他关键交付物”，若缺失，系统自动锁定项目进度无法转段。

### 2.8.3 试产目标与实绩管理
*（核心功能：生成试产总结数据的“一张表”）*
- **目标设定**：
    - **关联工单**：在试产开始后，录入本次试产对应的 **IMS 工单号**。
    - **设定指标**：为该批次设定具体的质量目标（如：直通率 > 95%，CPK > 1.33，尺寸合格率 100%）。
- **实绩录入与集成**：
    - **自动抓取**：
        - 系统根据关联的“IMS 工单号”，自动调取该工单的 **投入数、产出数、一次合格数、不良数**，自动计算试产合格率、直通率。
    - **手动补录**：
        - 针对 IMS 无法采集的数据（如：CPK 测算值、破坏性实验结果、外观评审得分），提供在线表格供 QE 手动录入实绩。
- **达成分析报告**：
    - **红绿灯对比**：自动对比“目标值”与“实绩值”。
        - 达标：显示绿色。
        - 未达标：显示红色。
    - **输出**：一键输出《试产质量总结报告 (Excel/PDF)》。

### 2.8.4 试产问题跟进

- **问题清单**：
    - **录入**：记录试产过程中发现的设计、模具、工艺问题。
    - **闭环**：
        - 简单问题：默认采用“问题简报”回复，指派责任人 -> 上传对策 -> 关闭。
        - 复杂问题：可一键升级为 **8D 报告** 流程进行深度分析。
    - **遗留问题管理**：若 SOP 节点仍有未关闭问题，需经过“带病量产”特批流程（签署风险告知书）。

- **预留接口**：

    - 预留“退出机制”的自动判断逻辑。

## 2.9 审核管理
*（核心逻辑：实现多体系审核计划的统筹管理，推行数字化检查表以替代纸质记录，并强制追踪不符合项（NC）的整改闭环。）*

### 2.9.1 审核计划与排程
- **多维度计划管理**：
    - **年度计划视图**：支持导入或创建年度审核计划，涵盖以下四类：
        1.  **体系审核** (IATF16949)。
        2.  **过程审核** (VDA 6.3)。
        3.  **产品审核** (VDA 6.5 / 周期性全尺寸)。
        4.  **二方审核** (客户审核 / 潜在客户拜访)。
- **智能提醒**：
    - 系统根据计划日期，提前 N 天（如 7天）邮件通知审核组长及迎审负责人准备资料。
    - **自动延期管理**：若计划未按期执行，需在系统提交“延期申请”并注明理由，经质量部长批准后方可修改计划时间。

### 2.9.2 审核实施与数字化检查表
- **模板库管理**：
    - **内置标准**：系统预置 VDA 6.3 (P2-P7)、VDA 6.5、IATF16949 检查条款库。
    - **自定义模板**：支持创建“专项审核模板”（如：防静电专项审核、异物管理专项审核）。
- **在线打分**：
    - **移动端支持**：可实现审核员携带手机/平板/笔记本，现场逐条录入检查结果（OK/NG）。
    - **证据留存**：对发现的问题点，支持**现场拍照上传**，直接挂载到对应条款下。
    - **自动评分**：
        - 根据 VDA 6.3 规则（如：单项 0 分降级规则），系统自动计算最终得分（如 87%）及等级（A/B/C）。
        - 自动生成《审核报告 (PDF)》，包含得分雷达图和问题清单。

### 2.9.3 问题整改与闭环
- **问题立项**：
    - **自动转化**：审核结束提交后，所有判定为 NG 的条款自动生成“不符合项 (NC) 待办任务”。
    - **任务指派**：由审核组长将 NC 指派给责任板块。
- **整改流程**：
    - **原因与措施**：责任人填写根本原因及纠正措施。
    - **举证关闭**：上传整改后的照片或文件（如：更新后的作业指导书）。
    - **验证**：审核员在线查看证据或进行现场复核，验证有效后关闭 NC。
- **逾期升级**：
    - 设定整改期限（如：一般项 30 天，严重项 7 天）。逾期未关闭的 NC，实现自动跟催并升级抄送。

### 2.9.4 二方审核特别管理
*（针对客户来厂审核的高关注度场景）*
- **迎审档案**：
    - 建立“客户审核台账”，记录：客户名称、审核类型、审核日期、最终得分/结果。
- **问题跟进**：
    - **外部格式兼容**：支持以附件形式上传客户指定的“问题整改清单 (Excel)”。
    - **内部闭环**：依据客户指摘问题清单在系统内部仍需创建对应的问题任务条目，确保不遗漏任何一个客户提出的整改项。

## 2.10 仪器与量具管理（预留功能接口）
*（核心逻辑：建立量具电子台账，强制实施周期性校准与 MSA 分析，确保检验数据的法理有效性。）*

### 2.10.1 全生命周期台账
- **电子身份卡**：每台设备赋予唯一二维码。扫码可查看：校准状态、有效期、责任人、MSA 报告。
- **状态互锁**：
    - **过期自动锁定**：当量具超过“下次校准日期”且未上传新证书时，状态变为“冻结”。
    - **检验拦截**：在 2.5.1 IQC 或 2.5.10 扫码环节，若关联的量具 ID 处于“冻结”状态，系统禁止录入检验数据。

### 2.10.2 校准与 MSA 任务
- **智能预警**：
    - 校准到期前 30 天/7 天自动发邮件给仪器/设备管理员。
    - **MSA 计划**：系统根据 PPAP 要求，自动生成年度 GR&R (重复性与再现性) 分析任务，经内部确认后发布。
- **报告归档**：支持上传第三方校准证书（PDF），系统自动 OCR 识别“校准结果”和“建议下次校准日期”。

## 2.11 质量成本管理 (预留功能接口)
*（核心逻辑：将质量数据转化为财务数据，量化“不良”带来的直接经济损失。）*

### 2.11.1 损失数据归集
- **内部损失成本**：
    - 自动抓取产线报废单金额（数量 × BOM成本）。
    - 统计重工工时成本（重工时间 × 人力单价）。
- **外部损失成本**：
    - 自动累加 2.7 模块中的“客诉索赔金额”。
    - 统计差旅费、运费等售后处理费用。

### 2.11.2 决策看板
- **COQ 趋势图**：按月展示质量总成本的变化曲线。
- **TOP 损失归因**：
    - 自动分析“哪家供应商赔钱最多”？
    - 自动分析“哪个产品型号报废最贵”？
    - *价值*：指导采购进行议价索赔，指导研发进行设计优化。

## 2.12 版本与发布管理
*（核心逻辑：构建“预览版 (Preview)”与“正式版 (Stable)”双轨运行机制，共用同一套数据库底座，确保新功能在“隔离区”验证通过后，再向全员无感切换。）*

### 2.12.1 双环境架构策略
- 环境定义：
    - 预览环境 (Preview)：
        - *访问入口*：独立子域名，入口有按钮可实现实时切换正式环境。
        - *适用人群*：IT 管理员、Key User（关键用户）、指定试用新功能的 SQE。
        - *代码版本*：包含最新功能（如 beta 版的功能）。
    - 正式环境 (Production)：
        - *访问入口*：主域名，入口有按钮可实现实时切换预览环境。
        - *适用人群*：所有供应商、产线操作员、普通用户。
        - *代码版本*：经过验证的稳定版本。
- 数据共享：
    - 原则：两个环境连接同一个 PostgreSQL 数据库，确保数据实时互通（例如：在预览版录入的测试单据，正式版也能查到，保证业务不割裂）。
    - 用户头像、电子签名、业务附件等上传文件视为共享业务资产，需与数据库中的文件路径保持同一可访问性，避免一个环境可见、另一个环境缺失。

### 2.12.2 数据库兼容性规范（针对预览版）
*（为防止预览版修改数据库导致正式版崩溃，系统需强制遵循以下开发约束）*
- 增量更新原则：
    - 新增表/字段：允许。但新增字段必须设置为 `Nullable`（可为空）或带有 `Default Value`（默认值），确保正式版旧代码读取时不报错。
    - 严禁操作：禁止重命名列、删除列、修改列类型（除非完全兼容），直到正式版代码也同步更新后方可清理旧结构。
- 应用层兼容：
    - 后端代码 (FastAPI) 需具备“版本感知”能力，针对尚未发布的字段做好判空处理。

### 2.12.3 灰度测试开关
- 功能控制台：
    - 在 2.3 系统配置 中增加“功能特性开关 (Feature Flags)”面板。
- 控制粒度：
    - 全局开关：一键开启/关闭某模块（如：“暂停 2.5.10 扫码功能”）。
    - 白名单机制：支持按“用户ID”或“供应商代码”开启新功能。
        - *场景*：仅允许“供应商A”在正式环境中试用“新版 ASN 上传”，其他供应商仍看旧版界面。
